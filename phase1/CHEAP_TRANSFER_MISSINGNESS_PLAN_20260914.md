# Missing-label sensitivity, no imputation

Freeze before model predictions on incomplete pools. Same four already closed roots: EScope whole_program only; action, width, memory all arms. Same fixed HGB and short-code comparator, source checks and training-overlap exclusions. This follow-up is explicitly post-hoc sensitivity after the complete-pool signal; it does not redefine that earlier result or any prospective E2E gate.

Include every non-bootstrap width-two pool with both generated programs available, regardless of completion or whether both were executed. A known label requires a returned original-candidate call, matching journal id/raw code/native executed hash, and an observed validity field (or a known nonzero process exit). Otherwise it remains unknown, including unexecuted candidates and missing journals. Never fill unknown with failure. Width-four and incompletely generated pools are structurally inapplicable and counted separately. De-duplicate unordered byte-identical program pairs within each run, first recorded pool retained; report duplicate counts.

Each policy distributes its choice uniformly among top-score ties. Let d_i = p_HGB(i)-p_short(i). On a known candidate label y_i, contribution is d_i*y_i. On an unknown binary validity label, contribution lies in [min(0,d_i), max(0,d_i)]. Summing gives the sharp paired difference interval for that observed pool; do not subtract unrelated policy intervals. Aggregate these bounds with equal weight per pool within run, then equal weight per eligible run. Preserve original run technical eligibility; list other runs separately. These are partial-identification bounds, not confidence intervals or final search-return bounds.

Verify bounds by enumerating all binary assignments to missing labels, and confirm fully known original complete-pool rows reproduce the earlier point differences. Compare all uncertainty-inclusive bounds alongside the complete-case result, without selecting whichever is positive.
