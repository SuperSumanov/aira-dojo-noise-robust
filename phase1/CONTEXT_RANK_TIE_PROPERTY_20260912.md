# 平均排名的共识候选保留性质：纯人工检验

2026-09-12。没有读取seed13候选/成绩，也没有重算旧8程序。0 GPU、0 API；不更改当前或已冻结的重复实验。

双序Borda按平均排名选top2、平分按原slot时，不保证保留两次都在top2的候选。
反例：两个排名分别为 `[0,2,1,3]`、`[1,2,0,3]`；候选2两次均第二，但前三者平均排名相同，原slot平分会选0和1。
这只证明集合性质，不表明候选2真实质量最好，也不表明真实数据中存在该情况。

穷举有标签的全部排列对（不是独立实验seed，也不是现实发生概率）：

|候选数|排列对|平均排名丢失共识候选|平均排名后按最坏排名打破平分的丢失|更换该平分规则改变top2集合|
|---|---:|---:|---:|---:|
|3|36|2|0|2|
|4|576|8|0|92|

替换平分规则不改变被选集合的平均排名之和；以上枚举中最大平均排名成本均为0。
若直接优先最坏排名而非仅破平分，4候选情况下会改变164/576集合，最大平均排名成本0.25；这不是等价改动。

对于两序top2，候选同时在两序前二时：如果它排名和小于4，则平均排名已保护它；唯一危险的边界为(2,2)与(1,3)/(3,1)同和。
在这一边界按最坏排名优先，(2,2)优于另两种，可保留共识。这个结论不推广成任意k、任意序数的定理。

可行后续假设：在新一轮独立实验中，仅改变平分规则，检验是否能以零额外裁判调用增加选择稳定性，再测e2e。
目前既无真实成绩收益，也无新颖性声明；不把标准排序平分处理包装成方法突破。
脚本 `context_rank_consensus_analysis_20260912.py`，两项反例/全枚举测试通过。当前seed13及其seed14重复仍严格使用原slot平分。

## 已核对的相关工作边界

2026-09-12查阅原始出版页：[Found in the Middle（NAACL 2024）](https://aclanthology.org/2024.naacl-long.129/)
已研究打乱输入顺序后聚合排名，不能把双序聚合/顺序稳健性本身称为我们提出的新方法。
[PCFJudge（GEM 2026）](https://aclanthology.org/2026.gem-main.58/)也聚合多顺序的分数、排名和不确定性；更接近的方向并非空白。

另核对[When Can You Debias an LLM Judge? v2](https://arxiv.org/html/2607.02104v2)：该文强调比较模型中的质量/项目协变量偏差未必可识别，
并研究外部锚点和成对呈现设计。搜索摘要仍显示其旧v1标题和较强主张，不能沿用旧摘要。
对我们的启发是：判断一致不等于真实可执行性/质量，必须以原提交与真实e2e成绩验证；不把平分处理或先验校正升级成性能定理。
