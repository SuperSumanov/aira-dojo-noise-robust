# 编辑范围是否把有效起点转成同预算最终收益？

2026-09-13 UTC / 2026-09-14 Hong Kong；新开发实验 EScope，不复跑 T1。

## 问题与边界

固定底座、初始可执行程序和墙钟预算时，将自由改写完整程序改成编辑模型/特征处理函数，是否改善最终提交，而不只是减少异常？
旧资产提供动机：已有共同起点，程序重写后仍有大量执行失败，单次检索修复与三条错误提示未通过扩大标准。它们不证明本方案有效；本方案也不把 T1 当作多步收益的必要条件。

这是编辑范围干预：有意改变可编辑的程序空间、返回格式与相应说明，不是严格保持相同算子空间的 critic 对照。其余变量固定；不得归因为 critic/scaling，也不把工程可行性叫论文新颖性。
AlphaEvolve/FunSearch 已有受限函数搜索；《When Models Edit Too Much》(2609.04061)已有编辑保真研究。因此“局部编辑”不是原创。候选科学价值必须来自同一 MLE 轨迹环境中的收益/损失、可复用边界和后续广泛验证，而非改名。

## 冻结矩阵

- 两任务：leaf-classification、spaceship-titanic；新 seed 42、43、44、45。
- 两臂：`whole_program`、`model_module`，共16次独立搜索、8个任务×seed配对。
- block1执行42/43两任务，block2执行44/45两任务；臂次序按(task序号+seed)奇偶交替。同一配对始终同一块物理卡。
- 两臂共用 refactor 后的原 RF 起点：同读取/编码/80:20训练内验证/100棵树/深度12/random_state0/全量重新拟合/提交；初始真实执行计入每次预算。重构只把模型构建放入 `build_model(X)`，不得用隐藏成绩挑起点。
- 原 aira-dojo/ForeTS 两生成两执行 uniform、UCT/debug/分析器/逐动作交付不变。Flash/Alibaba only、现行温度/采样参数不变。不加外部记忆、不调用critic、不更新底座。
- 每次搜索1200秒、完整程序至多300秒；原主动API准入余量不变。真实生成、执行、分析、持久化均在相同总预算内；清理与分配成本另报。
- gpu28 RTX3090，6CPU/单卡/原 July 镜像；两份至多4小时分配，共上限8GPU·h，预期约5.5–6.5GPU·h。不得用projgpu39、升级Torch或静默退CPU。

`whole_program`可返回完整新程序；`model_module`只返回 `def build_model(X): ...`，函数中允许任意可用的模型、sklearn兼容特征变换、嵌套助手和import，不预设模型名/超参答案。外部读取、验证和提交代码由同一固定起点拼接，不采用新外部成绩选取它。
模块接口只保证拼接边界不变，**不是Python安全沙箱或防标签泄漏证明**。违反接口的输出留下失败候选交给同一原生debug预算；不得补生成、自动换成好解或把它排除分母。

## 读出与决策（先写后跑）

主要终点：1200秒内原搜索可见选择器已持久化的最终 action submission，外部pristine独立重评分；次要完整iteration终点同时报告，不挑更大者。
每任务报告全部四个配对差、median、样本标准差和区间；Leaf低为好、Space高为好，不直接混合原始分值。缺失不填0，不把全零bootstrap当总体等效。另报未成功率、有效候选数、首次/后续改进交付时间、生成/执行/调试次数、费用与分配GPU·时。
开发继续门：至少6/8配对技术可比、两任务各至少3对；模块对完整改写净胜配对为正、两个任务各至少一个严格胜且不净负，同时至少一处改善超过Leaf0.02 log-loss或Space0.005 accuracy。门仅用来决定后续投入，不称统计显著或预注册确认集。
即使门通过，仍需强“提示保持其他部分不变”对照、第三任务、更强actor或更长预算及未用新seed；才能区分模块化、提示、基线弱点与可泛化原则。当前不宣称重要/独特主张已证明。

保护first960/Target300/Target522不读。旧T1、critic、单点CV、已关闭HCE/多保真/Probe/score-channel/K>=1不复活；学长分支不改。
