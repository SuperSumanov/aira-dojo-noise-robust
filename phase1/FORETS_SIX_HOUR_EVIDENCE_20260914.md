# 给学长的实质实验汇报：局部最终收益、前瞻重复与机制边界

2026-09-14 06:20 UTC / 香港14:20。核心两轮共20次真实搜索，另做24次原程序同池复跑；不是模型验收或冒烟结果。最后远端作业在香港11:10结束，完整独立读出与本报告收尾晚于原香港11:06的六小时目标。未通过改seed、改阈值或删除失败来制造正结果。

## 一句话结论

**真实最终成绩上出现了明显的局部正信号，但“短代码稳定胜出”和“类别门控带来收益”都还没有通过验证。** 本轮最有价值的进展，是把离线预测、候选本身的供给、选择器实际改变的决策、最终程序来自生成还是debug分别对上原始证据，避免把这些不同概念混成一个漂亮均值。

目前可成立的窄结论：在本轮MLE开发任务上，离线有效性选择优势不足以据此选出最终搜索策略；初次程序有效性与最终交付质量需要分别验证。这不是已经独特且充分证明的顶会主张，也不是“所有critic都无效”的结论。论文目标仍是同预算E2E收益，不改成只做语料或审计论文。

## 2. 一个比“又高了1.609pp”更重要的检查

逐池核对实际模型概率、类别分数和选中slot后发现：**Space类别门的4个双候选池都恰好一条高于0.5、一条低于0.5；其4次选择与连续概率排序完全相同。** 因此，在该run观察到的选择历史上，“类别相同则随机”根本没有被触发。最终0.81264程序来自debug；新Leaf随机的0.37782也来自debug。

所以不能写“保留探索的门控使Space提高1.609pp”。更高成绩真实存在，但现有证据不能将它归因于门控机制；随机生成、后续调试与有限样本都尚未分离。旧短代码四个好提交同样有2个来自原候选、2个来自debug，不能把收益都记作初次选中好代码。

该检查与主读出分开实现；独立直接比较概率最大值与slot也得到4/4相同。代码身份仅识别观察到的调用角色，不是修复价值的反事实估计。我们保留正数，但不以正数替代机制证据。

## 3. 用零API补齐未选候选：现在知道机会在哪里

24程序中3有效、21程序失败；24份真实GPU隔离回执通过。原先可知的12次初始有效性重测全部一致，但不能因此保证所有未来重跑确定性。

在同一批池上，随机、短代码、连续排序、类别门都只选中1个有效程序，共同错过另2个。按预先固定的有效性优先准则，四者逐池都是平局；这不是四策略普遍等效。尤其没有任何双有效池，因此这里根本不能检验“两个好程序谁分高”。

对这12个初始池，9个池即使知道两条程序的完整有效性，也选不出初次成功程序。另3个池确实存在选择机会，其中2个被所有现有规则错过。这是新的可用训练/诊断资产和明确空间，但不是整个搜索的效用上界、置信区间或已实现收益。原workspace历史、后续生成和debug均不能由此次复跑替代。

## 4. 修正了一个判断，不掩盖故障

Space随机臂原先只观察到ExecutionWitnessError，不能先归咎于GPU。闭合后定位为9052字符的原生成文本，经过原生extract_code后得到空字符串，触发既有执行代码schema校验。密钥形状命中0；不是GPU架构不兼容，也不是已证实的密钥泄漏。

原冻结读出将此类异常记为技术不合格，因此本次仍保持未知；不事后改成普通模型失败，不恢复成合格分数，不补seed。未来协议应明确区分“生成无可执行代码”和“任务基础设施异常”，避免一个坏响应终止整条搜索；修正必须对所有臂一致生效且单独成版本，不能追溯改变此轮。

## 5. 接下来怎样把资产变成可支持的主张

本轮不值得继续扩大固定HGB连续排序、0.5门控或短代码配方，也不应靠微调门槛追新seed。更有价值的问题是：**候选供给达到什么条件时，来自历史轨迹的预测能力才能在同预算下转化为最终收益？** 这是待验证的问题，不是已证明的新定律。

执行重点收紧为三件事：

1. 更强生成器形成独立的新实验层。已向用户询问学长本地27B服务的共享接口、模型名及调用许可；目前没有确认可供我方使用的服务，不能宣称已部署或借用他的allocation。原API实验与新本地模型不能直接合并。保持任务执行器两臂均原镜像3090。
2. 先固定共同候选池，在不依赖预测分歧的完整样本上分别测候选有效供给、选择是否真的改变决策、是否选到更高真实质量。不能先筛“我们能赢”的池再评估。若缺乏双有效候选，就不启动质量排序的昂贵扩大；这也不代表修复路径没有机会。
3. 值得上线的选择器必须在新E2E中跨seed提高最终成绩，并确实触发其提出的机制。保留强传统基线、随机/长度控制、总预算和生成/调试成本。不存在稳定收益就停止该配方；不会把更多工程回执计作科学突破。

历史失败节点、独立run切分、已有模型、原生轨迹、真实GPU执行与外部评分是可直接复用的优势；不重做G0、旧8B验收或访问冻结保护集。现有修复记忆T1和旧策略失败也保留，不换个名字重开。

## 6. 新颖性不能靠改名

本次再次核对的原论文摘要已足以排除几个宽泛口号：代码奖励模型用于测试时排序已有[CodeScaler](https://arxiv.org/abs/2602.17684)；由跨run结构预测失败已有[Automata from Agent Traces](https://arxiv.org/abs/2608.23670)；验证代理与生成器能力间的失配已有[The Verification Horizon](https://arxiv.org/abs/2606.26300)。这里只记录摘要支持的边界，不冒充系统性穷尽查新。

因此“廉价失败预测”“用门控避免代理过度优化”“生成器增强后重测”本身都不是原创贡献。可能的独特贡献只能来自MLE真实预算环境中被多任务、多seed和机制干预共同验证的发现或收益。当前只能说建立了检验这件事的直接证据，而非已经达到投稿证明强度。
