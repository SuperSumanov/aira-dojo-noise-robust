### 不能据此启动端到端效果实验

仍有一个已复现的阻断：ForeTS 把未执行候选加入普通 journal，节点 `is_buggy=None, metric=None`；
默认 simple_memory 会把它包含进摘要，并访问 `metric.value`，触发 AttributeError。
补丁特意没有将未执行节点伪装成失败、零分或成功。28例中一例明确保留并验证这个未解决边界。

下一接入必须区分两类记录：

- **候选台账**：所有生成候选、所属批次/父状态、原始代码、生成成本、预测及其身份，状态明确为
  unexecuted / execution-started / execution-completed / execution-failed；未执行不是失败标签。
- **已执行搜索状态**：只有真正执行后的节点进入依赖真实反馈的 memory、最优解筛选和回传。
  未选、预算不足未执行及中断状态仍在候选台账保留；所有生成成本照计。

这会影响持久化、重启、树边与后续生成上下文，不能只删一行 journal.append 后宣称修好。
先在我方隔离版本完成该接入，各选择臂一致使用，不能偷换既有逐节点即时反馈的 MCTS 对照。

## 2. 公平选择对照接入设计（未部署）

主要比较为 batch-random、固定 train-only TF-IDF、独立 critic；第一版保持相同候选数、top-k大小、
执行选择数、完整执行上限与debug规则。random臂在全池均匀抽同样数量；TF-IDF/critic臂按各自排序
取相同top-k，再使用独立、可恢复的selector随机源抽样。不要让selector抽签消耗生成器随机序列。
不把原来的逐节点 MCTS 改名为 batch-random，也不把两者系统差异归因于critic。

每批在生成前固定决策状态、实际渲染的prompt、memory、每槽位seed/解码参数、剩余时间和包列表顺序。
当前draft/improve会原地shuffle包列表，且operator重试会重新取上下文；仅复制parent ID不足以证明输入相同。
同批生成、预测与候选清单锁定完成前不执行任何候选。失败/重试开销都记录，不默认API失败免费。
恢复时不能重新生成已完成候选；未知执行状态停止对应事务，不重复收费或重评分。

学长文档的projgpu7/6GPU示例不能照抄：projgpu7在我方排除名单中，其示例checkpoint也未取得本项目评估准入。
同节点critic与执行worker必须分别计GPU；已知PRO6000只有2卡，不能同时承诺2卡critic再加1卡worker。
现在不启动该文档任何命令，后续按我方实际模型/节点和独立成本矩阵核验。

现有critic请求还有40000字符截断、默认服务编码配置和同步HTTP开销；补丁未暗改这些条件。
接入时须绑定实际模型/编码身份，核对是否截断，记录生成、推理、执行、评分及初始化成本。
完整执行预算不足时按事前停止规则处理；不缩短为1/6执行，不按早期成绩追加时间。
首轮固定候选池只说明离线选择价值；真实同预算多步 agent runs 才能支持在线搜索收益。

## 3. 数据路线：只补关键的新标签，不默认重跑整个训练池

1. 先按已有hold和保守experiment/run闭包确定角色，再读取该角色允许的训练标签；不从成绩挑任务/程序。
   开发组件的全部原程序和旧标签均不得用于训练，未抽到重执行的程序也不能回流。
2. 历史训练输入诚实标记来源不完整/弱监督，不将原source_admitted改true；相同训练记录和token预算比较
   Lbudget与G→L，保留seeds6/7和最终点规则。该比较另起开发协议，不冒用原严格四fit准入或确认标签。
3. 只对事前固定的独立开发范围做完整执行和新评分。允许在结果前固定少量完整 sibling 组的抽样范围，
   不必为角色隔离把整个组件的所有程序重新执行；但组件其余成员仍从训练中排除。
4. 原代码不改，两端使用同一新声明的执行/评分条件，保留原完整执行时限、失败/超时/无提交与实际成本。
   这是当前环境下的新标签，不是复现或追认证明旧分数。不得据少量重执行的一致率认证整个旧训练池。
5. 补标签矩阵须列确切组件闭包、任务、sibling支持、程序数、每程序时限/硬件、存储和总GPU时。
   现在这些明细尚未交叉核验，不能给一个虚构的可提交预算；也不能靠换随机seed救回超预算范围。

这是必要的覆盖支持，不是充分experiment独立性或统计功效。
