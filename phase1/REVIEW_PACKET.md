## 1. 资产

LLM coding agent(DeepSeek 为主,少量 Qwen)在 aira-dojo / MLE-bench 框架下解 Kaggle
任务产生的搜索树语料。**每个节点**都有:完整 Python 源码、agent **自己报告的验证分**、
**外部评定的真分**(MLE-bench 官方 grader)、运行时长、执行输出、树位置
(父/子/深度/step)、产生它的算子(Draft / Debug / Improve)。

- **12,383 张卡 / 约 550 个独立 run / 23 个任务**(v8,含学长 0808 批次)
- 三种搜索协议:浅 MCTS(20 步)、深 MCTS(数千步)、**无选择的顺序扩张** —— 同一生成器
  上的搜索策略自然实验
- 查证结论:**MLE-bench 排行榜上没有任何团队公开过 agent 生成的解代码**;
  HuggingFace 上不存在 MLE/Kaggle 的 agent 轨迹数据集;唯一先例是一个无 LICENSE、
  1 star 的日志仓库(`q-hwang/MLAgentBench_logs`)

## 2. 论文定位(2026-08-10 重定向)

**「MLE agent 搜索的 NAS-Bench」+ 第一个系统性预测器研究。** 模板取自:

- [NAS-Bench-Suite-Zero](https://arxiv.org/abs/2210.03230)(NeurIPS D&B 2022):13 代理 × 28 任务,
  头条发现是负面的(#params/FLOPs 打平所有零成本代理),但形态是基准发布 + 系统分析
- [How Powerful are Performance Predictors in NAS?](https://arxiv.org/abs/2104.01177)(NeurIPS 2021):
  31 个预测器,**initialization time 与 query time 分开计价**
- NAS-Bench-201 仅 15,625 个架构即顶会;我们 12,383 个**完整程序** × 23 任务

**同构性**:训一个网络太贵 → 性能预测器;执行一个程序太贵 → critic。

## 3. 主要结果

### 3.1 预测器 suite(run 级干净切分,39 个 held-out run,6,000 测试对)

| 预测器 | acc | run 聚类 95% CI | init | **query** | 看到程序的比例 |
|---|---|---|---|---|---|
| random | 0.5016 | [0.489, 0.517] | 0 | ~0 | — |
| runtime | 0.5271 | [0.471, 0.596] | 0 | 0.01ms | — |
| code_len | 0.5624 | [0.485, 0.611] | 0 | 0.01ms | 100% |
| n_lines | 0.5782 | [0.497, 0.647] | 0 | 0.01ms | 100% |
| static_lr(36 手工特征) | 0.6099 | [0.507, 0.759] | 2s | 0.31ms | 100% |
| 冻结 0.5B 嵌入 + LR | 0.6157 | [0.506, 0.710] | **16s** | 0.09ms | 63% |
| 0.5B 微调 @2048 | 0.6273 | — | ~6h | 25ms | 63% |
| **1.5B 微调 @2048** | 0.6493 | — | **~10h** | 50ms | 63% |
| static_gbm | 0.6506 | [0.556, 0.770] | 3s | 7.9ms | 100% |
| **tfidf 字符 3-5 gram** | **0.6657** | [0.556, 0.782] | 103s | 4.8ms | 77% |
| LLM 裁判(DeepSeek) | 0.5075 | [0.410, 0.606] | 0 | ~30s | 38% |
| *自报分(**事后**信号)* | *0.7780* | *[0.682, 0.873]* | *0* | ***561,077ms*** | — |

**三条主张:**

**(a) 容量不是瓶颈。** 微调 1.5B 十小时(0.6493)输给 103 秒的字符 n-gram(0.6657);
冻结 0.5B 嵌入 + 16 秒逻辑回归(0.6157)与微调统计上不可区分(CI 重叠)。
与学长在 pro6000 上的独立观察一致(0.6B/1.7B/4B 表现无明显差别)。

**(b) 覆盖率可能才是真正的轴。** 准确率排序与"读到程序比例"排序高度一致。
便宜方法读完整程序几乎不花钱,transformer 要为自己的 context 上限付税。
实测:**84% 的程序超过 2048 token,模型平均只看到 63%**;丢失的主要是特征工程
(`merge(` 仅 25% 可见、`groupby` 40%)。**context 消融正在跑**(0.5B@2048=0.6273
已落地,0.5B@8192 进行中)。

**(c) query 成本必须入表。** 自报分 0.7780 看似最强,但它的 query 成本是**一次完整
执行 = 中位 561 秒**;tfidf 是 4.8 毫秒。**七百万倍成本差换 13 个准确率点。**
在穷算力设定下这个 trade 明显不划算。

### 3.2 C2:预注册通过(唯一的预注册 PASS)

**主张**:ρ(自报分, 真分) 可在新任务上廉价测得,并**事前预测**学出来的 critic 在该任务
上能否迁移。10 折 leave-one-task-out(任务级切分,天然免疫 run 泄漏):

| 预注册判据 | 结果 |
|---|---|
| Spearman(ρ, LOTO) = **+0.7697**,n=10,精确置换(3,628,800 种)**p = 0.0063** | PASS(要求 <0.01) |
| 样本外(5 个非先导任务)= **+0.90** | PASS |
| 偏相关(控制对数 / 卡数 / 真分标准差)= **+0.8303** | PASS(要求 ≥0.5) |

**范围声明**:测 ρ 需要该任务的有标签留出集,"廉价"是相对训练 critic 而言,不是零成本;
n=10 个任务偏小;先导 n=5 时为 +1.000,加倍到 n=10 后回落至 +0.770(正常收缩)。

### 3.3 泄漏方法学(所有数字下修的来源)

- 语料 **44% 的卡是孤儿**(父节点无真分被剪),0 个真根 → 所谓"按树切分"实为碎片切分
- 卡片原本无 run 标识,按批文件连续性重建(**双验证 0 违例**)后发现
  **99.7% 的 in-task 测试对与训练侧共享同一次物理 run**
- 修正链:L1 = 0.8787(按卡)→ 0.8200(碎片)→ **0.6493(run 级重训)**
- LOTO / 跨任务迁移表**不受影响**(本就是任务级切分)

### 3.4 赢家诅咒:条件化否定(有正负对照)

signed gap = z(真分) − z(自报分),兄弟最优节点:

| k(兄弟数) | 正对照(纯噪声选择) | **真实数据** | 负对照(随机选) |
|---|---|---|---|
| 2 | −0.313 [−0.358,−0.264] | **−0.009 [−0.080,+0.046]** | +0.025(含 0) |
| 3 | −0.534 [−0.585,−0.474] | **−0.016 [−0.078,+0.054]** | +0.034(含 0) |

估计器已验证能看见植入的诅咒且不误报。**k=2-3 覆盖 95% 的兄弟集,真实膨胀只有匹配
模拟的 2-4%。** k≥4 那档看似显著但查明是 chaii 的 18 个节点撑的,已撤回。
这直接回应文献中的公开矛盾(AIRA-dojo 报 9-13pp vs Bertran 2606.11045 报 0.0-1.9pp)。

### 3.5 选择性执行(NAS 的"搜索加速比",重新框定后的主实验)

422 个兄弟集 / 54 run / 13 任务。语料里每个生成的兄弟都被执行过,所以反事实可算:

| 策略 | 执行/集 | 捕获增益 | CI |
|---|---|---|---|
| 全执行 + 自报分选 | 2.66 | 0.7500 | [0.699, 0.826] |
| critic top-2 | 2.00 | 0.7275 | [0.692, 0.799] |
| **critic top-1** | **1.00** | **0.5575** | [0.517, 0.622] |
| 随机 1 个 | 1.00 | 0.5315 | [0.505, 0.593] |
| oracle 1 个 | 1.00 | 0.9941 | — |

**critic vs 随机的配对差 +0.026,CI [−0.033, +0.082] —— 未解决。** 用的仍是
1.5B@2048(63% 覆盖),等 context 消融。

## 4. 我们已知的弱点(请重点攻击这些)

1. **有效样本量是 run 数(约 550)不是卡数(12,383)。** 功效反推:要让效应约 0.55
   的检验达到 80% 功效需要约 2,000 个 run。七个探索方向全部死于"效应约 0.55、
   run 聚类后 CI 跨 0.5"。
2. **方法广度仍不足。** NAS-Bench-Suite-Zero 有 13 个代理,我们目前 9 个
   (含 random 与事后基线)。
3. **裁判的公平性缺陷**:DeepSeek 裁判只看到 38% 的程序,其 at-chance 是下界。
   Qwen 全量上下文重跑进行中。
4. **单一生成器为主**:DeepSeek 占绝大多数,Qwen 仅少量批次。跨生成器轴基本未测。
5. **C2 的 n=10 偏小**,且 ρ 的测量需要有标签留出集。
6. **rescue 章尚未在 run 级切分下复验**(唯一残留的 churn 风险)。
