## 一、结论先行

继续 **Decision Corpus + Predictor Benchmark + Audit Protocol**。优先检验：

> 固定一批已经付费执行的 MLE 程序、独立执行记录和训练预算，怎样组织监督，才能训练出更可靠的局部决策 critic？这种改善能否转化为更好的选择质量或更低的实际成本？

G→L（先跨父节点的同任务全局比较，再适配同父候选）保留为首个真实开发候选，因为它最接近现有实现，并受到已有探索性结果启发；不把它预先认定为有效、新颖或唯一破局答案。

论文更合适的形态是：**可复用数据与系统研究，加上经过强对照的正面经验结论**。不是“首次两阶段排序算法”，也不是以审计数量代替模型效果。

## 四、方法为何可能有效，以及需要排除什么

支持假设：local siblings 相似，局部监督集中在细微差异；G 可能提供更丰富的质量约束，L 再适配决策分布。学长的 global scaling 是动机，不是干净确认。

反面解释必须同时保留：

1. **全局能力不必迁移到局部。** 学会不同程序家族的整体质量，不等于能判断同一家族的两个 child；共同基线在 sibling 比较中会抵消。
2. **跨 run 混杂。** G 可能包含环境、资源、数据划分或生产版本差异，而同 run 的 L 抵消其中一部分。不能把这类痕迹误称程序质量表示。
3. **输入信息不足。** 当前输入为任务名与代码，固定 head25/tail75 编码，不提供完整数据描述或所有运行条件。若关键修改被截断，换监督或扩大模型未必有效。
4. **派生边不是独立标签。** 同一执行分数生成很多 pair，不创造等量独立执行信息。图连通、秩或无权有效电阻改善不能替代真实模型效应。

失败时区分来源/标签不适配、输入缺失、优化失败和方法无增益；不统一归因于模型太小，也不自动上 8B。

## 六、数据来源：缩短关键路径，不降低确认标准

优先级：

1. 获得从实际生产时就保留运行/评分记录的**独立开发来源**，或可认证的已有开发包。

训练角色、experiment/run 闭包和全部保护人口隔离不可放松。新建文件夹不产生独立数据；当前自动前瞻收集不能改名挪入 train/dev。

少量重执行只用于兼容性或标签迁移诊断，高一致率不能认证整池，失败也可能来自环境/依赖变化。84-run 来源的独立支持不足必须在投入前明确，不能用派生 pair 充样本量。

## 七、正结果向真实价值的转化

### 两类目标分开预定义

- **质量增益**：同执行记录与训练预算下，可靠地改善新 run 的局部选择。
- **成本增益**：在预定义可接受的质量损失范围内，计入训练、补标签、维护及推理成本后，整体更经济。

第二类不能在第一类失败后临时拿来宣布原假设成功。小 critic 的单次推理更便宜不保证整体值得训练，应报告摊销的部署规模及硬件、实际时延和 GPU·时。RPM 作者也报告 inference-only 额外推理时间相对完整实验不大，不能先验把它当主要瓶颈。

### 离线与在线的边界

历史同父 child 可能先后生成，后者利用前者执行反馈，不能据离线排序推断当时只执行一个就能获得整个候选集合。

新的候选选择验证须先固定同一决策前状态与每槽位 prompt/memory，再生成全部候选并锁预测；同批结果不进入同批后续生成。随机、廉价 selector 和 critic 共用候选规则，只改选择器，所有生成/推理/执行计费。多步分叉后不借用其它策略的未来轨迹。

一级只证明固定候选分布上的离线选择价值；只有新完整 agent runs 的同预算对照才能证明在线搜索收益。不得恢复多保真、Probe 或 K≥1 lookahead。
