# Phase-1 基础报告：穷算力下用廉价信号预测昂贵 MLE grade 的价值 critic

日期：2026-07-09 ｜ 硬件：单卡 RTX 3090 24GB ｜ 底座：开源 Qwen2.5-Coder（7B/14B），全程无 LLM-as-judge、不微调底座

---

## 0. 一句话总结

在 LLM 自动做 ML 工程（写代码解 Kaggle 式任务）的搜索里，**一个候选解要跑满训练 + 官方评分才知道好坏，非常贵**。本工作研究：能不能用**廉价信号**（候选代码本身、廉价观测、搜索树血缘）预测该解的**真实 grade**，从而让搜索少跑昂贵评估、省算力。

**两个核心结论（都经多 seed 验证）：**
- **H1 成立**：一个**廉价的 frozen critic（probe）确实能从代码本身预测同任务 grade，且独立于自报验证分**——设障（屏蔽自报分）后它几乎不掉，而只依赖自报分的 baseline 直接崩溃。
- **H2 不成立**：让 critic「先写自然语言分析、再打分」（reasoning-first）**即使用最强的 14B teacher 蒸馏，整体仍不如直接回归**——这是一个干净的 negative。

---

## 1. 研究问题与假设

搜索控制器每扩展一个候选解，要不要花昂贵代价真实评分？若有个便宜的「价值 critic」能预测最终 grade，就能优先评估有希望的解、剪掉没希望的，省评估预算——这正是穷算力下把搜索做广的关键。

- **H1（基础）**：廉价信号能预测真实 grade，且 critic 有**独立于自报验证分**的价值（不是简单复读自报分）。
- **H2（关键/原设想的新意点）**：让 critic **先推理再打分**（reasoning-first），比直接回归**更省样本 / 更好校准**。

---

## 2. 方法

**数据（card）**：把 aira-dojo 一次真实搜索树（journal）里每个候选解节点变成一张 card：
- critic 可见：任务描述、候选**代码**、廉价观测（自报验证分等）、血缘（父分、算子、树深）；
- 标签（藏起来）：该解的**真实 MLE-bench graded 分数**（外部 pristine 评分，无 LLM-as-judge）；
- `view()`/`hidden()` 保证标签永不泄漏进 critic 输入。
- **规模**：148 卡 / 3 个真·小数据任务（spaceship-titanic 二分类、nomad 回归、tps_may 二分类），per-task min-max 归一化标签。

**6 个预测器（同台对照）**：
| 类型 | 名称 | 机制 |
|---|---|---|
| baseline | one_epoch / asha | 直接信 / 外推自报验证分（不用标签） |
| critic | zeroshot | 冻结 Qwen 单前向读代码打分（零训练） |
| critic | **probe** | **冻结 Qwen 的 hidden features + 线性 ridge** |
| critic | scalar | 7B QLoRA + 标量回归头 |
| critic | reasoning | 7B QLoRA SFT：先分析再打分（H2 主角） |

**设障（ablation，H1 干净证据的关键）**：屏蔽掉所有自报信号（自报验证分、验证曲线、父分），逼 critic 只能从**代码 + 血缘**学。baseline 因此崩溃；**能存活的 critic 就证明它从代码本身提取了 grade 信号**。

**评估**：intra（同任务 train/test）+ loto（留一任务，跨任务泛化）；**3 个 seed**（报跨 seed 方差）；指标 Spearman 秩相关。

---

## 3. 核心结果

### 3.1 H1 成立：probe 有独立于自报分的价值，且多 seed robust

Spearman，跨 3 seed × 3 task 平均（code[:4000]）：

| | one_epoch (baseline) | probe (critic) | scalar (critic) |
|---|---|---|---|
| intra 正常 | +0.605 | +0.458 | +0.028 |
| **intra 设障** | **+0.000** | **+0.407** | +0.043 |
| loto 正常 | +0.424 | +0.208 | +0.046 |
| **loto 设障** | **+0.000** | **+0.263** | −0.187 |

**读法：**
- **正常下**：自报分 baseline 极强（+0.605/+0.424），所有 learned critic 都打不过——因为自报分和真 grade 同源；
- **设障后**：baseline 塌到 0，而 **probe 几乎不掉**（intra +0.458→**+0.407**，loto 甚至 +0.208→**+0.263**）——**这证明 probe 是从代码本身学 grade、独立于自报分**，正是 H1 的核心证据；
- **跨任务也成立**：loto 设障 probe +0.263（去掉自报分后跨任务泛化反而更好，说明自报分跨任务是噪声）；
- **robust**：跨 seed 标准差仅 0.10–0.18，不是单 seed 运气；
- **probe（frozen 特征 + ridge）是明星**，scalar（QLoRA）反而弱（小数据过拟合）——**H1 的正结果主要靠廉价的 probe**。

### 3.2 H2 不成立：reasoning-first 即使用 14B teacher 也不普适

Spearman，intra（同任务）：

| 任务 | scalar | reasoning-7B teacher | reasoning-**14B** teacher |
|---|---|---|---|
| spaceship | +0.126 | −0.008 | **+0.313** |
| nomad | +0.457 | −0.087 | −0.053 |
| tps_may | +0.233 | −0.359 | −0.466 |
| **平均** | **+0.272** | −0.151 | −0.069 |

**读法：**
- reasoning-first 整体显著弱于直接回归（scalar +0.272 vs reasoning-14B −0.069）；
- **但一个重要 nuance**：14B teacher 让 reasoning 在 spaceship 上从 −0.008 跳到 **+0.313、反超 scalar**——**证明 teacher 质量是关键隐藏变量**（用 7B 自蒸馏测出的 negative 不算数，必须用强 teacher 才算测干净）；
- 只是这个提升**不普适**（nomad/tps 没跟上）——reasoning-first 的价值依赖任务性质 + 数据量，148 卡不够。

### 3.3 方法学发现（过程中的两个坑，都已定位修复）

1. **prompt 截断 bug**：reasoning 从早期起就"从没真正跑过"——代码把「分析指令」挤出了受限的 prompt，模型只是在续写代码、打分器抓到随机数字。用 dump 原始预测才发现。**教训**：generate 型 critic 光看指标会误判，必须 dump 原始输出。
2. **code 长度 confound**：为了 reasoning 的显存把代码截短（4000→1200 字符），**意外把 probe 的设障成绩从 +0.407 压到 +0.024**（一度误判 H1 不复现）。改回完整代码后 H1 复现。**教训**：probe 从代码学，代码长度是敏感变量。

---

## 4. 诚实局限（写在前面，避免过度解读）

- **数据量小**：148 卡 / 3 任务；单任务测试集只有 9–36 个候选，小样本下秩相关本身波动大（用 3 seed 缓解，但不能完全消除）；
- **任务谱窄**：3 个都是小 tabular 任务；结论能否推广到图像/NLP/更大任务未知；
- **H1 靠 probe**：scalar/reasoning（QLoRA）在这个数据量下都偏弱，H1 的正结果集中在 frozen probe 上；
- **跨任务弱**：即便 probe，loto 也只 +0.26 量级，跨任务预测远难于同任务；
- 呼应主线发现：真 grade 本身极难预测（噪声评估 R²≈0.14），这是所有结果偏弱的根本背景。

---

## 5. 结论与下一步（需要导师意见的点）

**当前可写成一篇诚实测量论文**，核心叙事是「穷算力 + 噪声评估下，廉价 learned critic 的能力边界」：
- **能**：一个廉价 frozen critic（probe）从代码本身预测同任务 grade、独立于自报分（H1，robust）；
- **不能/有限**：跨任务预测很难；reasoning-first 即使用强 teacher 也不普适（H2 negative）；
- **一个隐藏变量 + 一个方法学坑**：teacher 质量决定 reasoning 成败；代码长度决定 probe 成败。

**需要导师拍板的方向：**
1. **投稿定位**：走「诚实测量 / 负结果 + 一个正结果（H1）」的 workshop/短文，还是要补强到更完整的会议长文？
2. **要不要扩数据/扩任务**：现在 3 个小 tabular 任务 + 148 卡是主要局限。补到更多任务能显著加强，但要额外算力/时间投入——性价比请导师判断；
3. **H2 那个 nuance（14B teacher 让 spaceship 反超）值不值得深挖**：单任务亮点，扩数据验证能否推广是大投入、且可能不推广，风险偏高。

**我的建议**：先以现有结果成文（H1 正 + H2 negative + 方法学），把「诚实边界刻画」作为卖点；扩数据/扩任务作为 rebuttal 或下一篇的储备。是否如此，请导师定。
