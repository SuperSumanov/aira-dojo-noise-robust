## 0. 一句话与活口

**穷算力（单卡 3090）+ 廉价带噪评分下，怎样保住 HCE 式「评估一致 → 长程稳定」。**
- T0：评估噪声是病根（eval-noise R²=0.14）。
- T1：**清洁（完整）评估是大杠杆（full≫proxy）**；三廉价**选择臂**（单次/平均/方差惩罚）无差异 → **选择规则不是杠杆**。
- **本方向活口**：不是"廉价评估直接做决策"（T1 已否），而是 **多保真**——用廉价低保真评估搜得**广**，只把有希望的候选**晋级**到完整评估做**决策**（BAI 预算分配），并保持**保真度一致**。问：固定穷算力预算下，广度赚的能不能盖过 proxy 噪声亏的？

## 1. 公平契约（只有"保真度/分配"这一个旋钮变）

| 固定不动 | 值 |
|---|---|
| 底座 LLM | DeepSeek（v4-pro draft/debug/improve，v4-flash analyze），**绝不微调** |
| 算子集 | draft/debug/improve/analyze（aira 原生，不改） |
| 任务集 | **快任务**：spaceship-titanic（+ 备选 nomad）。**禁 tps_dec（360万行）级怪物**（②的教训） |
| 每任务总预算 | 固定为 N 个"完整评估当量"（full-eval-equivalents），逐臂相等 |
| 评分 | 外部 pristine full grade（HCE 完整性），agent 只看自报分 |
| seed / 数据划分 | 固定并记录 |
| **唯一变量** | **评估保真度 + 预算分配方式**（单保真 vs 多保真+BAI） |

## 2. 臂（arms）

- **A｜单保真基线**：每个候选都做**完整评估**；固定预算 → 候选数少。决策 = 完整评估分里选最优。
- **B｜多保真 + BAI**：每个候选先做**廉价低保真评估**（下述阶梯），**successive-halving / Hyperband** 把 top 晋级到完整评估；决策只在完整评估过的候选里做。同样固定总预算 → 候选数多、但多数只低保真过一遍。
- **C｜多保真但评估不一致（病理对照，可选）**：晋级用的低/高保真**指标口径不一致**（模拟 AIRA_2 的退化根因）→ 证明"保真度一致"是 B 成立的必要条件，不是多保真本身。

## 3. 保真度阶梯（fidelity ladder）

- 低保真档 = **同协议、少资源**：`data_frac`（如 10%/25%）或 reduced epochs；**指标、划分口径与完整评估完全一致**（HCE 教训——只减数据/算力，不换口径）。
- 成本核算：低保真成本 ∝ data_frac（近似）；完整评估成本 = 1。总预算 = Σ(保真度成本 × 评估次数)，两臂锁死相等。

## 4. BAI 分配器

- **Successive Halving（Hyperband 一档）**：全部候选低保真评估 → 留 top-⌈n/η⌉ 晋级到高保真 → 递归。η（如 3）、档数、每档预算是超参，记录并固定。
- 配置开关独立可关（可逐组件消融）。

## 5. 指标与报告

- 主指标：**固定预算下找到的最优候选的真（外部）grade**；median + 跨 seed 方差。
- 辅：预算-质量曲线（不同预算点 A vs B）；晋级精度（低保真选出的 top 里有多少真的是 top）。
- CSV 一行一 run，含 seed/commit/预算/臂名/保真度参数。

## Stage 0（先跑，便宜的 go/no-go 探针）：多保真**有没有 headroom**

> **建 B 的机器之前，先用现有数据证明多保真在我们任务上天花板够高。纯 numpy 离线、秒级、零 GPU、零 DeepSeek、复用 289 卡的自报分+真分。**

- 用现有 spaceship（+nomad/tps）卡，固定预算 B 个完整评估当量，模拟三种：
  1. **单保真**：随机 B 个候选全评 → 真-best（多次平均）。
  2. **多保真(自报分筛)**：便宜筛 N≫B 个候选、按**自报分**晋级 top 到全评 → 真-best。（现实档）
  3. **多保真(oracle 筛)**：同上但按**真分**晋级 → 真-best。（天花板）
- 判读：
  - 若 **多保真(自报分) ≫ 单保真** → 免费的自报分就能带来多保真增益 → **强力支持建 B**。
  - 若 **多保真(oracle) ≈ 单保真** → 连完美筛选都没增益（任务太易/单保真已近 oracle）→ **headroom 低，重估整条线**。
  - 中间情形（oracle 高、自报分档一般）→ 需要更好的低保真档（真·subsample 评估，见 Stage 1）。
- 成本：**~几分钟本地/一个 gpu_2h 都不用的小脚本**。脚本 `phase1/mf_headroom.py`（或新目录）。

## 风险 / confound（先说清）

- **headroom 风险**：这些任务可能"单保真已近 oracle"（③a′ 里 spaceship 部署 regret 才 ~0.10）→ Stage 0 正是查这个。
- **低保真 rank 不保真**：低保真分若不能 rank-faithfully 预测完整分，BAI 晋级就没意义（Stage 0 现实档 + Stage 1 真 subsample 查）。
- **实现改动**：aira eval 层可能没有 data_frac 旋钮，要动代码 → 破契约风险；改前给 diff。
- **预算对齐**：两臂"完整评估当量"必须严格相等，否则不公平；核算逻辑要单独验。

## 回退

Stage 0 红（无 headroom）→ 诚实记录"多保真在穷算力小任务上天花板低"，主线收敛到"清洁评估是唯一大杠杆"（T1 已证）的诚实终点；Phase-1 诚实测量论文 + 主线诚实边界一起构成完整故事。

## Stage 0 结果（2026-07-12，`phase1/mf_headroom.py`，登录节点秒出）→ 判定：**headroom 低，倾向不建 Stage 1**

真实树池 & 随机池都算（防 ③ 随机池假象）；headroom = mf(自报分筛) − single：

| 任务 | B=3 headroom | B=10 | single vs oracle | 读法 |
|---|---|---|---|---|
| spaceship | +0.015 | −0.000 | 0.954 vs 0.981 | 单保真已近 oracle，headroom 小且随预算归零 |
| nomad | +0.000 | — | 1.000 vs 1.000 | 太易，零 headroom |
| tps-may | **+0.044** | — | 0.783 vs 0.829 | **唯一有真 headroom**，但小样本 31 卡 |

**核心张力**：有 headroom 的任务（离散/难，tps 家族）恰是**穷算力搜不起**的（② 证 tps_dec 360万行）；搜得起的（spaceship）**单保真已近 oracle**。→ 在 spaceship 建整套多保真=搏 +0.01 效应=追噪声（③ 刚吃过亏）。与 T1「清洁评估是唯一大杠杆」一致。记忆 [[mf-headroom-stage0]]。

**建议**：不建 Stage 1；④ 收在此 headroom 特征化结论。两条线（critic 有信号≠有省 + 主线 多保真只在搜不起的离散任务有天花板）→ 完整诚实故事，收进论文。**下一步待用户定。**
