# 汇报：穷算力下，廉价价值 critic 在 LLM ML-工程搜索中的能力边界

汇报日期：2026-07-10 ｜ 硬件：单卡 RTX 3090 ｜ 数据：289 张真实 graded 卡 / 3 个 tabular 任务 ｜ 全程无 LLM-as-judge、不微调底座

---

## 一、背景

LLM agent 现在能自动做 ML 工程——读一个 Kaggle 式任务，写代码、跑训练、看分数，并在候选解上做**搜索**（MLE-bench、AIDE、aira-dojo 等系统）。这类搜索的**主要成本是评估**：每生成一个候选解，都要**跑满一次完整训练 + 官方评分**才知道它好不好。

在**穷算力**场景下（单张商用 GPU、且一个标签 = 一次完整训练+评分，昂贵且稀缺），一个自然的问题是：**能不能用一个廉价的"价值 critic"预测候选解的最终得分，从而让搜索少跑一些昂贵评估？**

底座 LLM 本来就读过候选代码；在它的隐藏层上挂一个轻量线性探针（probe）几乎不花钱。所以我们研究这个廉价 probe 到底能做到什么。

---

## 二、动机（三个递进的问题）

1. **能预测吗？** 廉价 probe 能不能预测候选解昂贵的真实 grade？
2. **是真本事还是复读？** 候选解自己会报一个便宜的"自报验证分"，probe 是不是只在复读它？还是**携带独立于自报分的信息**？
3. **有用吗？** 就算能预测，把它接进搜索，能不能**真的省下昂贵评估**？

这三问从"能不能预测"一路逼到"到底有没有用"，是本阶段的主线。

---

## 三、方法

**数据（card）**：把 aira-dojo 真实搜索树里每个候选解节点变成一张卡——critic 可见的部分（任务、**候选代码**、廉价观测如自报验证分、血缘），和**藏起来的标签**（外部 pristine 代码算的真实 MLE-bench grade）。标签永不泄漏进 critic 输入；评分全程无 LLM-as-judge。共 289 卡 / 3 任务。

**对照的预测器**：
- 两个 label-free **baseline**：`one_epoch`（直接信自报分）、`asha`（曲线外推）；
- 四个 **critic**：`zeroshot`（冻结模型单前向）、**`probe`（冻结 Qwen 隐藏特征 + 线性 ridge，本工作主角）**、`scalar`（QLoRA + 回归头）、`reasoning`（先写分析再打分）。

**四个关键实验**：
1. **设障（ablation）**：把自报分等廉价信号全部屏蔽，逼 critic 只能从代码本身学——baseline 会崩，能存活的 critic 就证明它有**独立于自报分**的信息；
2. **固定预算 best-of-K 模拟**：在 K 次昂贵评估的预算下，比较"按 probe 选 top-K" vs "按自报分选" vs "随机选"谁选出的解真 grade 最高——直接测**能不能省评估**；
3. **自报分失效检测（rescue）**：在自报分**排错**的候选对上，看 probe 还对不对——测 probe 在自报分失效处的独立价值；
4. **reasoning-first（H2）**：让 critic 先写自然语言分析再打分，看是否更好（含 7B / 14B teacher 对照）。

**文献定位（deep-research 调查）**：系统检索了 LLM-ML-agent 与经典 AutoML/NAS，确认本方法与最接近的几个工作的**精确区别**（见结论六）。

---

## 四、主要结论

### 结论 1（正）：probe 能预测，且独立于自报分——H1 成立、多 seed robust
设障（屏蔽自报分）后，只会复读自报分的 baseline **崩到 0**，而 **probe 仍保住 Spearman +0.356（同任务）/ +0.179（跨任务）**（3 seed，标准差 0.12–0.17）。→ **probe 确实从代码本身提取了 grade 信号，不是复读自报分。** 这是本阶段最扎实的正结果，且靠的是**几乎免费的 frozen probe**（QLoRA 的 scalar critic 在小数据上反而很弱）。

### 结论 2（负）：但这份"会排序"的本事**不能**换成省评估——rank ≠ regret
在固定预算 best-of-K 模拟里，**免费的自报分 proxy 完胜 probe**：在唯一有区分空间的任务上，按自报分选 top-K 直接选到最优（regret 0），而 probe ≈ 随机。→ **预测的 rank 相关性好，不等于搜索能省评估**（这正是 NAS 文献里著名的 rank ≠ regret 警告，我们在 LLM-agent 场景复现了它）。这也解释了为什么最接近的竞品 ArchPilot 用"便宜执行的低保真 proxy"是合理设计。

### 结论 3（有限正）：probe 的真正价值在"查自报分什么时候在骗你"
换个角度——在自报分**排错**的候选对上（自报分按定义 0% 对、随机 50%），**probe 在大样本 spaceship 上仍有 0.59 判对**（8382 个错对）。→ probe 的用途不是"帮你选最优"（自报分已够好），而是**"在自报分失效时提供独立判断"**——即 **reward-hacking / 自报分虚高检测**，正好接上项目主线关心的评估作弊防护。诚实说：这个价值**有限**（独立性是部分而非完全：0.59 < 自报分对时的 0.71；且依赖 probe 在该任务本身够强，tps 上失效）。

### 结论 4（负）：reasoning-first 无助益——H2 negative
让 critic "先分析再打分"，**即使用更强的 14B teacher 蒸馏，整体仍不如直接回归的 scalar**（mean −0.146 vs −0.065）。一个诚实的 nuance：**teacher 质量是隐藏变量**——14B teacher 在 spaceship 上把 reasoning 从负拉到 +0.31、反超 scalar，证明"用弱 teacher 测出的 negative 不算数"；但这个提升**不普适**（其他任务仍负）。

### 结论 5：两个方法学坑（都已定位）
- **prompt 截断 bug**：代码放在指令前、prompt 被截断时，"分析指令"被挤掉，模型只是续写代码——reasoning critic 曾**整整一个阶段从没真正运行过**，且光看指标发现不了，只有 dump 原始输出才暴露；
- **code 长度 confound**：为省显存把代码截短，**顺带把 probe 的设障成绩从 +0.36 压到 +0.02**——一个变量的 confound 会悄悄推翻另一个结论。

### 结论 6：文献定位——是"窄空白"而非无人区，但站得住
- 核心 SOTA（aira-dojo、SELA）**都全量评估每个候选、无 critic 省评估**——这个位子是空的；
- 三个近邻需正面区分：**ELHSR**（同是 frozen-probe，但预测二元对错、best-of-N 重排，非昂贵 ML grade）、**AgentRM**（finetuned、便宜 agent 任务）、**ArchPilot**（低保真**执行** proxy，我们**不执行**）、**I-MCTS**（prompted-LLM value，非 frozen probe）；
- **可辩护的卖点**收紧为：{**不执行的 frozen-probe + 昂贵稀缺 ML grade + 设障证明独立于自报分 + 自报分失效检测 use-case**}——这个组合没人做过。
