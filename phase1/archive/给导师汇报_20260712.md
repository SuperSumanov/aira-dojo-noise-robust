# 汇报：穷算力 LLM ML-工程搜索里,什么是杠杆?

日期：2026-07-12 ｜ 对应论文初稿 `论文初稿_v2_穷算力杠杆.md`（v1 为 critic 单线版）

---

## 一、背景

自动化的 LLM「ML 工程 agent」（MLE-bench / AIDE / aira-dojo / SELA）解 Kaggle 式任务的方式是：生成候选代码 → 跑 → 在结果上搜索。**主导成本是「评估」**：每个候选都要完整训练 + 官方打分，一次打分 = 一次完整训练。

两篇关键前作定了靶：
- **aira-dojo（2507.02554）**：把搜索形式化为 policy × operator，得到**负结论——评估固定后,搜索策略本身几乎不重要**。
- **AIRA_2**：把这种退化诊断为**评估不一致/噪声**,而非记忆。

在**穷算力**（单张商用 3090、标签又贵又少）下,真正该问的不是"哪个花哨搜索策略赢",而是更锐利、可操作的一问：**在穷算力下,什么真能推动结果,什么只是看起来能?**

## 二、动机

穷算力下有三个"便宜到单卡能做"的候选杠杆,我想诚实地把它们逐一测清、划出能力边界:
1. **评估质量**——把（仍然昂贵的）评估做得更干净/一致,或在带噪的廉价评估上做更稳健的选择;
2. **廉价 learned critic**——用**冻结** LLM 的隐层特征 + 一个线性 probe,不执行候选就预测它的分数,用来省评估或拦坏候选;
3. **多保真选择**——用便宜的低保真跑筛掉大多数候选,只把有希望的少数晋级到完整评估（Hyperband / Successive Halving 式）。

**本项目不追 SOTA 系统,追的是一张诚实的边界图:什么是杠杆、什么不是、为什么。** 全程坚持一条方法纪律:**贵的在线实验之前,先用便宜的离线探针去证伪。**

## 三、方法

- **实验台**：facebookresearch/aira-dojo（负结论的同一框架,自带 Greedy/MCTS 干净基线）+ DeepSeek 底座（OpenAI 兼容 API,**绝不微调底座**,model-agnostic 是卖点）+ 非容器解释器 + **外部 pristine 打分**（prepared/private 划分,grader 在 agent 工作区外）。**全程无 LLM-as-judge**;agent 只看分数、看不到标签。
- **公平契约**：每个对照实验里**只有被研究的那一个旋钮允许变**（评估协议 / 或 critic / 或保真度）,算子集、底座、每任务预算、任务集、数据划分全部固定并逐项记录。
- **杠杆（§4）= T0/T1 三臂评估 harness**：只变评估/选择协议——full（清洁完整）/ naive（单次 10% 廉价 proxy）/ consistency（方差惩罚的廉价 proxy）。指标 = 部署解的 held-out 真值、regret、gap。
- **critic（§5）= card + probe + 设障（ablation）**：每个真实搜索节点做成 card（task/code/廉价观测/lineage + 隐藏的真分,view/hidden 防泄漏）。289 张 graded 卡,3 任务。probe = 冻结 Qwen2.5-Coder-7B 特征 + ridge。关键手段:**mask 掉自报分,看谁还活着**（活着 = 真的从代码里读到了信号）。配套三个离线协议:best-of-K（rank→regret）、wrong-pair rescue、**在线 veto（真实树 vs 随机池 + bootstrap）**。
- **多保真（§6）= headroom 离线探针**：纯 numpy 秒级,用现有卡的自报分+真分,固定预算比 单保真 vs 多保真(自报分筛) vs oracle,**同时在真实搜索树池和随机池上算**（防随机池假象）。

## 四、主要结论

**一句话:穷算力下,「评估质量」是杠杆;廉价 critic 和多保真选择在能搜得起的规模上都不划算。两条独立的线收敛到同一结论。**

**① 杠杆 = 评估质量（§4）**
- 评估噪声是真的、且**任务相关**:spaceship（accuracy,易 overfit）上自报分只解释真分 ~14% 方差（R²=0.14, n=71）；nomad（RMSLE+5折）上反而 R²=0.72 → 噪声咬在"易灌水"的指标上,不是永远噪。
- **清洁完整评估是大杠杆**:full 部署真值 **0.803 ≫** 各种 10% proxy 的 ~0.785,regret 只有 1/3。**但"改选择统计量"（单次/平均/方差惩罚）救不了**——三者全在 0.78–0.79 噪声带内。杠杆在**保真度/一致性**,不在怎么选。（这印证了 aira-dojo"选择不重要",并点名了唯一例外 = 评估质量。）

**② 非杠杆 I = 廉价 learned critic（§5）**
- **H1(正)**:probe 能预测同任务真分,且**设障后仍活**（Spearman +0.36 intra / +0.18 cross-task,基线归零）→ 它读到了**独立于自报分**的信号。
- **但 rank ≠ regret(负)**:这份 rank 本事**换不成省评估**——固定预算 best-of-K 里,免费的自报分 proxy 打平或胜过 probe。
- **价值只在"查自报分哪里错了"(有限正)**:自报分排错的候选对上 probe 仍 59% 对（vs 构造上 0%）→ 是个**自报分失效/reward-hacking 检测器**,不是选择器。
- **★把它当在线 veto 用,收益不成立(负,本轮新做)**:v1 把这写成未来工作。我做了——**随机池上像大赢（Δregret 到 +0.18）,但换到真实搜索树上收益消失**（hard veto −0.001;soft blend 只 +0.007,bootstrap 95% CI [−0.003,+0.018] **不显著**）。随机池的赢是"候选相互独立"的假象;真实树候选靠 improve 血缘收敛,自报分自己选出的部署解本就好。→ **rank≠regret 从 best-of-K 一路延伸到在线 veto。**
- reasoning-first critic 也不行（即使 14B teacher,整体不如 scalar 头）。

**③ 非杠杆 II = 多保真选择（§6,本轮新做）**
- 多保真**只在"分数离散"的任务上有 headroom**（tps +0.044）——而 tps 家族**恰恰是穷算力搜不起的**（tps-dec-2021 训练集 360 万行,单候选 1–3 小时）;**能搜得起的任务（spaceship）单保真已近 oracle**（0.95→0.98,headroom +0.015→0）。→ **有 headroom 的搜不起,搜得起的没 headroom。** 多保真选择在 affordable 区不是杠杆。

**④ 收敛与定位**
- critic 线和多保真线**方法上无关,却以同样方式失败**:都有真信号,但在能负担的规模上**不转化为搜索收益**。→ **锐化 aira-dojo 的负结论**（不止 policy,整个"搜索侧廉价干预"家族都不划算）,并**把机制钉在评估噪声上**（AIRA_2）:你没法便宜地绕过噪声,只能花钱买清洁评估。
- **方法论主线:离线证伪先于在线投入。** 四次便宜的离线探针,在动工前就杀掉了四个昂贵的错误建设（best-of-K / 随机池 vs 真实树 veto / bootstrap / 多保真 headroom）——每个"看着正"的结果都是假象,几秒到几分钟的离线检验就溶解了它。

**⑤ 复现与产出**
- 数据 `phase1/cards_real_mm.jsonl`（289 卡）;脚本 `budget_probe.py`/`probe_rescue.py`/`veto_sim.py`/`veto_realtrees.py`/`mf_headroom.py`;T0/T1 harness。全程 pin seed/commit/预算/臂名,外部打分、无 LLM-judge。
- 可复用协议（都是离线、便宜、为"动工前证伪"而设计）:**自报分设障、best-of-K rank→regret、wrong-pair/veto rescue（含真实树 vs 随机池对照）、多保真 headroom**。
