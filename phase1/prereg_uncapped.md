# 预注册:未截断评估 + sr-cond(2026-08-09,开盒前落字)

## 为什么要做这一步(而不是 p-hacking)

五个方向死于同一处:效应约 0.55,按 run 聚类后 CI 跨 0.5。功效反推给出确切数字:

| 分析 | 效应 | 半 CI | 当时 run 数 | 80% 功效需要 | 倍数 |
|---|---|---|---|---|---|
| L1 flip 集 | 0.5474 | 0.1148 | 23 | 276 | 12× |
| **自报分判错的对** | **0.5586** | **0.0767** | **27** | **94** | **3.5×** |
| repair(code_len) | 0.5527 | 0.1388 | 29 | 410 | 14× |

**第二行是唯一一个可能靠现有语料就够的**:它只需要 94 个测试 run,而 run 级切分的
held-out 侧共有约 102 个 run、5,498 对测试对 —— **我们此前只评了 3,000 对**。

那个 3,000 的上限是 `--eval-cap` 的省算力设置,**与假设无关**,不是设计选择。用完整
held-out 集才是正确做法。因此"扩样本"在这里不是事后捞数据,而是修正一个本就任意的截断。
但为免自欺,判据在开盒前写死如下。

## 判据(不可事后修改)

**步骤 1(免训练,~15 分钟 GPU)**:用现成 `ckpt_l1_runsplit/N24000`,
`--eval-cap 6000` 评完整 held-out 侧,dump 逐对命中。

在「自报分判错」子集上,按 **run 聚类** bootstrap(4000 次)算 95% CI:

- **PASS**:CI 下界 > 0.5 **且** 去掉 spooky 之后的子集点估计仍 > 0.5。
  第二个条件是硬性的——前四次失败全都是 spooky 单任务撑着,不能再犯。
- **FAIL**:任一条件不满足 → 「代码含自报分之外的正交信息」判定为**不成立**,
  这条线终止,不做 sr-cond 训练,写进论文作为负面结论。

**步骤 2(仅当步骤 1 PASS)**:训练 `--sr-cond` 模型(代码 + agent 自报分同时入模),
在同一批对上对比 **自报分单独 = 0.780**。

- **PASS**:sr-cond 模型的 run 聚类 CI 下界 > 0.780,**且** 至少 3 个任务各自方向为正。
- **FAIL**:自报分不可被代码改进 → 负面结论,论文照写。

## 预先声明的解释边界

即便步骤 1 PASS,它只证明「信息存在」,不证明「可用」——门控实验已经证明我们
找不到该在哪介入。步骤 2 才是可用性检验。两步都过才算正面结果。
