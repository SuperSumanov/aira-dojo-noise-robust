# 方向提案：把「评估 / 算力底噪」当作 ML-agent 搜索的研究对象

日期：2026-07-18　｜　状态：便宜离线闸门 = AMBER-偏绿；但**新颖度 + 有趣性 vet = INCREMENTAL / LOW（见 §7，决定性）**——AIRA_2 已占据机制，投卡前请先读 §7

---

## 0. 一句话

不要再赌「更聪明的搜索/选择策略打赢 baseline」（结构上是一场 SOTA 竞赛，null 结果什么都发不了——这正是我们前面 T1 / D4 / 因子 / 迁移 / 幻觉 一个个塌的根因）。
**改成：把「评估条件 / 算力底噪」本身当作被操纵的自变量 + 研究对象**，在大规模受控容器 agent 运行上测它如何**因果地塑造搜索**。这样**连 null / 阈值结果都是一条定律**（"评估条件 X 下搜索行为如何"），对我们一路踩的失败模式是 anti-fragile 的。

---

## 1. 核心命题（主线方向②）

**固定 LLM + seed，只改变容器的计算环境**（GPU 型号 / CUDA·cuDNN 版本 / 数值精度 FP32-vs-BF16 / determinism flags），检验：

1. **幅度**：分数漂移是否大到能跨 Kaggle medal 阈值 / 重排 method ranking；
2. **放大机制（新意所在）**：因为分数会回流到 agent 的**节点选择**，底噪在搜索里被**放大成发散轨迹**，而不是像单次静态训练那样被平均掉；
3. **修复**：方差感知 / 一致性评估（HCE）选择能否恢复「环境-鲁棒」的排名。

底噪幅度不是我们编的：GPU 非确定性文献里，它可占 ResNet 精度标准差的 74–87%，BF16 可致约 9% 精度 SD，换 cuDNN 版本改结果。**没人把这个噪声源放进 agent 的决策循环里测过。**

## 2. 为什么现在能做 + 为什么是我们独有

- **容器刚在 CSE 跑通**（`singularity-ce 4.3.0`，setuid 版；`singularity exec docker://busybox` 在 `userns=0` 下 pull+run 成功，rc=0）。→ 只读容器 exec 可用 = **干净地、可复现地「变环境」的稀有仪器**。多数实验室没法可复现地变环境。

反例：FML-bench（2605.17373）刻意把执行基础设施**控制掉**去归因策略；我们做**相反**——把基础设施当研究对象。

## 3. 两个便宜离线闸门的结果（诚实，含坑）

### 3.1 (σ, Δ) 任务散点 —— 「有没有让噪声起作用的空间」
脚本 `phase1/task_scatter.py`。每任务估 **Δ=headroom（beat_ratio 排行榜百分位的 IQR）** 与 **σ=评估噪声（1−Spearman(自报分, 真分)）**。

- **确认了老问题（MF-Stage0）**：便宜/tabular 任务多为低 headroom（spaceship≈0、insults 0、pawpularity 0、ventilator 0.07、nyc-taxi 0.11、pizza 0.12）——解都挤在天花板附近，搜索/噪声没空间 reroute。
- **但高-Δ 的 affordable-ish 任务存在**：tabular-playground-dec-2021（0.31）、spooky-author（0.19）、aerial-cactus（0.25，小图像）、denoising-docs（0.49）、lmsys-arena（0.38）、google-quest（0.21）。
- **σ 跨任务确有变化**（agent_runs 可信）：cactus 0.59、covid 0.49（自报分很噪）vs iceberg 0.12（干净）。→ dose/对照的原料是有的。
- **结论：方向活，但绝不能用默认 spaceship/便宜 tabular，必须 curated 一个高-Δ 子集。**

### 3.2 底噪 flip 闸门 —— 「底噪会不会被选择 reroute + 损失真质量」
脚本 `phase1/task_substrate_flip.py`。在高-Δ 任务的 logged 解上注入 ε·(任务内分数 SD) 的高斯扰动。

- 干净高-Δ 任务在**可信底噪幅度 ε=0.05–0.2（≈指标 1–3%，正是文献量级）**下：
  - **argmax 翻转率 30–90%**（选到的「最优解」被底噪换掉）；
  - **且真质量掉了（regret，beat_ratio）**：aptos +0.04→0.31、denoising +0.09→0.29、lmsys +0.03→0.27、spooky +0.18→0.39。
  - → **翻转不是白翻：被底噪骗去选了真质量更差的解。机制在合理幅度成立。**
- 树上（cactus）逐决策 argmax-child 翻转 36–70%，沿 ~37 步路径累积发散 ~100%。

**坑（诚实）：**
1. 翻转率高，部分是因 top 解 score 挤得极近（top-gap 仅 0.00–0.06 个 SD）。这是双刃：选择确实脆弱（真），**但并列解若真质量也相同，翻了不亏**（tps-dec-2021 翻 68% 但 regret=0；cactus 近饱和）。→ **方向只在「score 近并列但真质量有差」的任务上有牙 = aptos/denoising/lmsys/spooky。**
2. 池化数字被 artifact 灌水：google-quest（nan 退化）、volcanic（分数 SD 是均值 7 倍，离群主导）——干净信号在那 4 个任务上。
3. 「路径发散 100%」部分是平凡数学（逐步翻转在 37 步复合）；cactus 仅 5 个决策、近饱和，不算强证明。
4. **离线不能测真实底噪 σ**——只能模拟；真值必须靠容器重打分。

**离线裁决：AMBER-偏绿。** 机制（底噪→选择 reroute→真质量损失）在合理幅度、干净高-Δ 任务上成立，是我们一路搜下来第一个通过 make-or-break 的正面信号；但有牙的任务偏中/贵，且真验证要容器。

## 4. 下一步实验（需 GPU/容器）——配置矩阵草案，供讨论

**目标**：把「模拟的 ε」换成「实测的真实底噪 σ」，并测真实翻转/rerouting/recovery。

**Pilot 1（先测真 σ，最便宜）**：
- 任务：先挑 2 个便宜的高-Δ-有牙任务（如 spooky-author、tabular-playground-dec-2021）。
- 环境矩阵：{FP32-deterministic, BF16-default} × {cuDNN benchmark on/off}（= 4 环境）。
- 做法：取每任务 ~20 个 logged 解，在 4 环境里**各重打分 3 次**，测同一解跨环境/跨重复的分数 σ。
- 规模：2 任务 × 20 解 × 4 环境 × 3 次 = 480 次重评分；估 ~15–30 GPU·时（单 3090）。
- 闸门：真 σ 是否达到 flip 闸门假设的量级（ε~0.05–0.2 of task-SD）。达到→上 Pilot 2；不达→方向证伪，省下大卡。

**Pilot 2（真实 rerouting，仅当 Pilot 1 绿）**：
- 在同一批高-Δ 任务上，**跑完整 agent 搜索 × 每个环境 × ≥5 seed**，测 method-ranking / medal 结论是否跨环境翻，以及方差感知/HCE 选择能否恢复。
- 规模：~4 任务 × 4 环境 × 5 seed = 80 次完整搜索；这一步才是大头，规模待 Pilot 1 后定。

**硬约束照旧**：不微调底座 LLM；只有被研究的旋钮（环境）变，其余固定；报 median + 跨 seed/环境方差；一行一 run 存 CSV；pin 依赖 + git commit。

## 5. 诚实的风险清单

- **有趣性/新颖度（已查，见 §7）= INCREMENTAL / LOW**：AIRA_2 已拥有「评估噪声 → 被搜索放大 → 一致性评估修复」这条机制，本提案只是把噪声源改名叫「算力底噪」；且离线 flip 高估了效应（真实 agent 里采样方差远大于底噪）。**这是投卡前的决定性负面信号。**
- **有牙任务偏中/贵**：能同时满足「高 Δ + score 近并列但真质量有差 + affordable」的任务偏薄，跨任务定律的统计力是真实约束。
- **真 σ 可能不够大**：Pilot 1 若测出真实底噪远小于 flip 闸门假设，方向就弱——但这正是 Pilot 1 便宜先证伪的价值。
- **「近并列解等价」反驳**：需明确只在真质量有差的近并列上宣称，且给 recovery（方差感知/HCE）当正面贡献，否则退化成「PyTorch determinism flag 消融」。

## 7. 新颖度 + 有趣性 vet 结果（2026-07-18，决定性）

两组独立文献调研（一组查是否被 scoop、一组模拟顶会 PC 审稿）收敛到同一结论：**新颖度 INCREMENTAL、有趣性 LOW。** 诚实列出：

**（1）机制已被 AIRA_2 占据。** AIRA_2（2603.26499）已证明：评估噪声（而非记忆）驱动搜索退化，且一致性评估（HCE）消除退化。本提案把这条机制的噪声源命名为「算力底噪」并测其搜索放大的翻转——**缩成套在 AIRA_2 机制上的一个 attribution wrapper**，不是新现象。

**（2）三条腿两条已发表 / 平凡。** 底噪幅度大 = ResNet 非确定性（2001.11396，占方差 74%）的平凡应用；方差感知 / HCE 恢复 = AIRA_2 + 既有 MCTS-variance 方法已有；而离线那个「argmax 翻转 30–90% + 选到更差解」= **教科书 optimizer's curse（Smith & Winkler 2006）**，是已知统计人工，不是新发现。

**（3）关键技术反驳（杀招）。** 真实 agent 在 temp>0 下每次写不同代码，**采样方差远大于底噪扰动**——离线 flip 闸门固定解、只扰动分数，**高估了底噪效应**；真实里底噪很可能被采样噪声淹没。且落地的负面名篇（Deep RL that Matters / Sober Look / Are-we-really-making-progress）都是「重跑一个 named 结论、证明它在控制下崩塌」——本方向只有做到这个才够顶会。

**（4）唯一没死的窄路（很窄、经验上不太可能）。** 要翻身，须证明底噪是 AIRA_2 解释不了的 qualitative break：**系统性（方向性、非零均值）混淆**，能**扛住 ≥16-seed 平均**（破了「多跑几次平均掉」的逃生口）、翻一个 **named cross-method 结论**、且连 HCE 的 held-out 选择本身都被同底噪污染。两组调研都判「经验上不太可能」，且**我们自己的 T1（一致评估才是杠杆、方差感知选择无差异）本身就是反证**。

**（5）投卡前唯一该做的便宜决定性测试。** temp=0、固定 agent+seed+采样、只变环境，看一个 method-level 翻转能不能**扛住 seed 平均**（= 系统性 vs 零均值）。红 → 关掉，别写别烧卡（先验倾向红）；绿 → 那条窄路才真开。

**（6）供讨论的战略问题。** 这已是我们在「LLM-ML-agent 搜索 × 评估」空间的多轮尝试（表征探测、幻觉、评估噪声…）中又一次被 AIRA_2 + 大厂占尽「有趣」claim。诚实的问题是：**有没有一个真能打过 AIRA_2 的评估-噪声故事（最懂 AIRA_2 的人最有资格判）？还是该真正换题？**
