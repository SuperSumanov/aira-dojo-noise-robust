## 二、核心结果:RM "学得会、迁不动"

用 Qwen2.5-1.5B + LoRA 训 Bradley-Terry 偏好模型(底座 DeepSeek 仍然完全冻结,只训这个小模型)。

**(a) 同任务内:随数据量单调爬升**

| 训练对数 N | 500 | 2,000 | 8,000 | 24,000 |
|---|---|---|---|---|
| 准确率 | 0.535 | 0.605 | 0.746 | **0.757** |

(运行间噪声实测 ±0.002,所以这个上升是真的。)

**(b) 跨任务(留一任务 LOTO):微弱**

| 留出的任务 | 准确率(1500 个测试对) |
|---|---|
| tabular-playground-may-2022 | 0.613 |
| spaceship-titanic | 0.597 |
| random-acts-of-pizza | 0.525 |
| tabular-playground-dec-2021 | 0.520 |
| mlsp-2013-birds | 0.511 |
| **同任务内参照** | **0.769** |

**排查过程(为什么这不是 bug)**:第一版我怀疑三件事,逐一修掉后差距依旧——①代码被截断(中位代码 3074 token,我原设 1024,97.5% 被截 → 改成头+尾保留 2048,保住模型定义和训练循环);②输入里没有任务信息(→ 加了任务名前缀);③折选得偏(→ 从 1 折扩到 5 折)。修完 in-task 从 0.746 升到 0.769,LOTO 也从 0.51 升到 0.60,**但 0.77 vs 0.55 的鸿沟没有动**。

**含义**:MLE 解质量 RM 的瓶颈不是"同类数据不够多",而是**跨任务的可迁移表征**。这正好是我们论文要回答的一等公民问题,而且两种结局都能发表。

## 三、噪声地板 τ(我们独家的标注)

同容器重执行 K=3 次 + 外部重评分,已完成 288 次(4 个任务),第二轮 595/798 在跑(覆盖 suite 任务)。

- **τ 呈三档**:69–90% 的节点三次重跑**分数逐位相同**;少数微小抖动(1e-4~4e-3);全语料只有 1 个剧烈随机节点;
- 同环境噪声 ≤ 各任务分数范围的 1% → **执行分可以放心当标签**;`effective-pairs`(超过噪声地板的对)占 **98.2%**;
- 真正的不确定性是"**换环境能不能跑**":54/288 次重跑失败,几乎全是包差异(LightGBM 找不到 OpenCL、sklearn 删了旧参数)和超时截断,不是随机死亡。

## 四、两个工程成果(你可能直接用得上)

**① 容器里 LightGBM GPU 修复(已验证,不用改镜像)**
根因:`--nv` 会带进 `libnvidia-opencl.so.1`,但**不带 `/etc/OpenCL/vendors/nvidia.icd`**;而且只补 ICD 还不够,还缺 `libnvidia-nvvm.so`(OpenCL 内核编译器)。做法:bind 宿主的 `nvidia.icd` + 运行时从当前节点拷一份驱动匹配的 `libnvidia-nvvm.so.4` 进去 + 设 `LD_LIBRARY_PATH` 和 `HOME=/tmp`(boost 缓存要可写)。A/B 实测:不修 = `No OpenCL device found`,修了 = 正常 GPU 训练。代码在 `phase1/tools/regrade_worker.py`(自动探测,探不到就退回原行为)。

**副产品**:救活的节点重跑后分数**系统性比原环境高约 0.09%**(7 个节点全部正偏移,而同环境抖动比这小一个数量级)。这是"执行环境影响成绩"的第一个连续型证据(此前只有"能跑/不能跑"的离散证据)。诚实说明:这个偏移混合了容器、库版本、GPU 型号三个变量,我没有分离它们。

**② 被 SLURM 杀掉的 run 能恢复多少**:逐步 journal 是完好的,`journal_to_tree.py` 可以还原**树结构和自报分**;但 workspace 里**没有 submission 残留**,所以**外部真分只能靠重新执行**。结论:被杀的 run 不是全废(结构可用),但真分拿不回来。
