> 写给你的版本:每个实验讲三件事——**为什么做、做了什么、读出了什么**。术语第一次出现时给通俗解释。

## 〇、我们到底在研究什么(一段话版)

现在流行让 LLM 当"机器学习工程师"(MLE agent):给它一个 Kaggle 任务,它写代码、跑实验、反复改进,长出一棵"尝试树"。一个自然的想法是训一个**评委模型(RM,reward model)**来判断"哪份代码更好",用来指导搜索、省下昂贵的真实执行。我们的研究回答一个此前没人系统回答的问题:**这样的评委,到底需要什么数据才能训得起来?它学到的是真本事还是死记硬背?** 答案(剧透):它学到的比想象的窄得多——而证明这件事,需要一种此前不存在的数据集,我们把它造了出来。

## 一、数据集:我们造了什么

**4,349 个"卡片"**,每张 = 一次尝试的完整档案:代码 + agent 自己估的分 + **官方真实评分**(用 Kaggle 隐藏测试集打的,agent 看不到)+ 它是谁的孩子/父母(树结构)+ 用了哪个操作(初稿/改进/修 bug)+ 运行环境记录。

覆盖 **20 个任务**(表格、文本、音频、部分视觉)× **3 个生成器**(DeepSeek、Qwen、GLM)× 多随机种子 × 两种执行环境。树深最大 36 层。

**三个别人没有的标注**(这是数据集的护城河):
1. **τ(噪声地板)**:同一份代码重跑 3 次,分数会抖多少?我们实测了——大部分代码逐位不变(τ=0),少数抖一点,极个别抖得厉害。**用处**:如果两份代码分差比 τ 还小,那这对比较是噪声,不该拿来训练评委。实测 94.6-100% 的比较对高于噪声地板 → 我们的标签是可信的,而且可信度是量出来的,不是声称的;
2. **树血缘**:每个节点知道父母子女——"这一步是从哪来的、后来通向了哪"才能定义(见实验五);
3. **环境敏感性**:同一份代码换台机器可能就跑不了(缺库/显存不够/联网限制)。我们把四种失败机制的计数表做了出来——证明"执行环境必须被记录"不是口号。

**对照组(竞品)**:ForeAgent 也发了类似数据,但他们 8,460 份代码里**只有 895 份带真实评分**,没有树、没有 τ、基本单一生成器。我们所有发现恰好都需要他们缺的那几样才能做出来。

## 二、实验逐个讲

### 实验 1:评委学得会吗?(规模曲线)

- **怎么做**:训练一个小评委(Qwen2.5-1.5B + LoRA*)看代码对:"这两份哪个分高?"训练对从 500 加到 24,000。
  (*LoRA = 不动大模型本体,只训一小撮附加参数,便宜十倍。)
- **结果**:准确率 0.535 → 0.605 → 0.746 → **0.776**,随数据量稳定爬升(三个随机种子重复,波动仅 ±0.016)。
- **怎么读**:在"见过的任务+见过的生成器"范围内,评委真的能学,数据越多越强,还没饱和。这是数据集"有用"的第一证据。
- **常识校准**:0.5 = 抛硬币(两选一瞎猜);0.776 = 四对里能判对三对。

### 实验 2:换个任务还行吗?(LOTO 交叉验证)

- **怎么做**:LOTO = leave-one-task-out,把某个任务完全藏起来不给训练,训完再考它——模拟"遇到新任务"。做了 5 个任务的版本。
- **结果**:0.511 / 0.520 / 0.525 / 0.597 / 0.613——全部远低于任务内的 0.769。
- **怎么读**:评委在新任务上几乎失灵。它没学会"什么是好代码"这个通用概念,学的是"这个任务上什么样的代码分高"。
- **有意思的花絮**:学长说他做 RL 时 critic 也这样(多环境训练,零样本进新环境照样拉胯)——这可能是价值模型的普遍宿命,我们给出了 MLE 领域的定量版。

### 实验 3:换个"作者"还行吗?(跨生成器——本文最重磅)

- **怎么做**:评委只见过 DeepSeek 写的代码。考它 **Qwen 写的代码,任务完全相同**。
- **结果**:**0.496,精确等于抛硬币**。三个种子重复:0.499/0.535/0.491。
- **我们自己的三轮找茬**(这段是科研方法课):
  1. *会不会是 bug?* 查了七种:标签方向、id 碰撞、数据泄漏、分数尺度、代码字段污染、"Qwen 对更难"、评测管线。杀手锏是**体内对照**:同一个模型同一次运行,一半考 DeepSeek 留出题(得 0.64-0.76)、一半考 Qwen 题(得 0.47-0.50)——同一段代码不可能只对一半测试集坏掉。**管线无罪**;
  2. *会不会是表面风格?*(变量名、注释习惯)用程序把所有代码"整容"——变量统一改名 v0/v1、注释全删——重训重考。**结果纹丝不动**(0.482)。而整容后的分布内准确率还有 0.66-0.82,说明整容没有毁掉可学性。→ 绑定在更深的**结构模式**(控制流形状、库使用习惯)上;
  3. *是不是所有任务都这样?* 不是——tps_dec(最"模板化"的表格任务,人人都写差不多的 XGBoost 流水线)完美迁移(0.653)。**绑定程度取决于任务解法的多样性**。
- **怎么读(论文的核心句)**:单一生成器的数据训出的评委,会把"这个模型的写码风格"误当成"质量"。而且这个缺陷**在单一生成器的语料内部原理上测不出来**——你需要第二个生成器的带真分数据才能发现,而这种数据只有我们有。

### 实验 4:这病治得好吗?(治愈曲线)

- **怎么做**:往训练里加少量"新作者"的标注数据,看恢复多少。
- **结果**:掺 160 对(稀释在大池子里)= 没用;**551 对专门微调 = 0.566**(+7 个点);外推 ~1000 对 ≈ 0.66-0.71;而"跨任务预训练 + 1000 目标对"= **0.707**,比单用任何一种数据(~0.62)都高。
- **怎么读**:①治得好但药不便宜——每个新风格要几百上千个标注;②**两种数据互补可叠加**,不是替代关系。这给"该采什么数据"提供了带价格的操作指南。

### 实验 5:学长的新任务(lookahead,"这步棋通向胜利吗")

- **动机**:比较两份**完成的**代码是旧任务(ForeAgent 也做);搜索时真正需要的是判断**半成品**:"这个节点继续走下去,能到多好?"这就像围棋评估"这步棋的前途",而不是"这盘棋现在谁领先"。
- **怎么做**:每个节点的标签 = 它子树里最好的真实分数(可按预算截断:再走 1 步/3 步/不限)。**只有带树+真分的数据才能定义这个任务**——这是数据集从"有用"升级为"必需"的地方。
- **结果**:①**26% 的节点对上,"现在谁好"和"谁前途好"答案相反**(预算越大,分歧越大:15%→21%)——新任务不是旧任务换皮,是可测量的差异;②训出的前瞻评委在"答案相反"的那部分对上达到 **0.609**(只会看眼前的捷径模型在这里必得 0 分);
- **附赠的方法学发现**:如果切分数据时不按"整棵树"切,同一棵树的近亲节点(代码几乎一样)会一半在训练一半在考试,**成绩虚高 21.6 个百分点**(0.825 → 0.609)。我们把这个警告和量化证据写进数据集使用规范——这类"怎么用才不骗自己"的指南正是数据集论文的责任。

### 实验 6:插回搜索有用吗?(T3,诚实的 null)

- **怎么做**:把前瞻评委接进 MCTS 的选点环节(严格对照:同任务同种子同预算,唯一区别=选点时是否咨询评委;处理组带"确实咨询了"的日志证明)。
- **结果**:8 组配对,4:4,无效果。tps_dec 上的分差甚至小于我们自己测的噪声地板——连"差异是否存在"都读不出来。
- **怎么读**:不意外也不丢人——评委本身只有 0.61 的前瞻力,每局只被咨询 5-6 次,20 步的小预算里翻不了盘。**这个 null 和主发现是自洽的**:正因为评委学不到可迁移的价值概念,插回去才没用;"要什么数据才能让它有用"恰好就是论文的主题。我们如实报告,不美化。

## 三、发现的逻辑链(一张图版)

```
评委在分布内很能打(0.78,还在涨)
    ↓ 但是
换任务 → 掉到 0.51-0.61        换作者 → 掉到 0.50(抛硬币)
    ↓ 排查                          ↓ 排查
不是 bug(体内对照)             不是表面风格(整容实验)
    ↓ 所以
它学的是「任务×作者的结构性风格-分数关联」,不是「质量」
    ↓ 治疗
新域标注几百上千对可部分恢复;跨任务预训练+目标数据互补叠加
    ↓ 含义
单一生成器语料原理上测不出此病 → 多生成器+树+真分+噪声标注的数据集是必需品
    ↓ 顺便
「前瞻」是比「比较成品」更贴近搜索需求的新任务,我们定义了它并给出基线
```

## 四、工程经验(踩过的坑,按类别)

**采集/集群**:SLURM 提交机要 `SLURM_CONF`;`--export` 里的逗号会切碎参数(两次踩坑,改分号);同名批次目录复用会瞬死(改名归档再跑);墙钟杀死的 run 会丢外部评分(解法:solver 自己限时干净退出);共享代理是单点(熔断器保命);消费级 GPU 节点 NCCL 跨卡通信可能坏(P2P/SHM 都试过,最终单卡绕行);能跑容器的机器和大显存机器可能互斥。

**训练**:97.5% 截断把模型变瞎(量化你的输入长度分布!);last-token 池化必须右 padding;`--local_rank` 要接住;DeepSpeed CPU offload 需要 ninja **可执行文件在 PATH**;OOM 换梯度检查点+bs1;管道 `rc=$?` 接的是最后一环(用 PIPESTATUS 或直写文件)。

**实验设计**(最值钱的一类):**极端结果先怀疑自己**——0.496 经过七项审计才敢宣布;**体内对照**是洗清评测管线的杀手锏;**处理组要带交付证明**(否则 null 无法解释);**剂量要够**(160 对稀释=无效不等于 551 对微调=无效);**树数据必须按树切分**;**per-task 分解**能抓住"平均数掩盖系统性翻转";运行间噪声(±0.002)要实测,差异小于它的都不算数。

**协作**:每个关键数字入 CSV 带 seed/config 列;每次自纠都留档(审稿人问起来是加分不是减分);给合作者的 runbook 附上你踩过的每个坑。

## 五、ICLR 把握:4-5 成,以及它取决于什么

**为什么不是更高**:①T3 是 null,论文没有"我们的方法赢了"的时刻——ICLR 主会对纯发现+数据集类论文向来严苛;②lookahead 的 0.609 还偏薄;③模型规模 1.5B 为主(7B 等 H200);④审稿人方差在这个档位就是巨大的。

**为什么不是更低**:跨生成器塌陷+机制+治愈曲线这条链完整、极端、可复现、别人做不了;lookahead 是真新任务;每个 claim 都带 CI 和审计记录;诚实的 null 反而增加可信度。

**四件事会移动这个数字**(按影响排序):
1. **学长的 H200 全 context 实验(E1)**:塌陷在无截断下依然成立 → 发现终版坐实(+1 成);若明显减弱 → 需要降格为"截断依赖的现象"(−1 到 2 成,但庆幸投稿前发现);
2. 7B 规模(E4):大模型也塌 → "不是模型太小"的反驳预埋(+半成);
3. lookahead 加厚版结果(测试分歧对已从 1,675 → 3,590);
4. 写作质量本身——故事线已经在了,剩下的是执行。

**备胎**:NeurIPS D&B(明年 5 月)约 7 成——这份工作在那个赛道是标准的强投稿形态,ICLR 的审稿意见还能拿来改进。
