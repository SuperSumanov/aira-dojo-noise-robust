## 一、核心结果:转移谱系(全部经体内对照审计)

| 迁移粒度 | 准确率 | 说明 |
|---|---|---|
| **任务内、版本内** | **0.776**(3 seed:0.757/0.783/0.787) | N=24,000,还在随数据上升 |
| 跨任务(LOTO,5 折) | 0.48-0.62 | birds .497 / pizza .525 / spaceship .606(各 2-3 seed) |
| **同家族跨版本** | **0.48-0.55** | v1-flash 训 → v2-flash 测,同任务 |
| 跨家族(DeepSeek→Qwen) | **~0.50** | 同任务,per-task 0.468-0.545 |

**读法**:这个 RM 的有效范围精确到"**特定任务 × 特定模型版本**"。换任务、换厂商、甚至**同一个 API 的一次静默推送**,都会让它退化到随机。

### 1.1 版本塌陷(本次新增,最刺眼)

体内对照(同一模型、同一次运行、同一套评测代码):

| 测试集 | 准确率 |
|---|---|
| v1-flash 留出对:petfinder / spooky | **0.751 / 0.783** |
| v2-flash 对:quest / petfinder / spooky | **0.483 / 0.505 / 0.545** |

**难度混杂已隔离**:v2 的 quest/spooky 对分差确实略窄(约 v1 的 55-63%),但 **petfinder 两版分差几乎相同(0.79 vs 0.74),准确率照样从 0.751 掉到 0.505** —— 难度解释不了 25 个点。

**为什么这条特别有价值**:`dojo_config.json` 里 `model_id` 一字未变(`deepseek-v4-flash`)。这个轴**只存在于你那句人工标注里**。含义:任何对着 API 模型训的执行分评委,会在服务商下次推送时静默作废,且配置层零征兆。这同时论证了"数据必须带 provenance 标注"不是洁癖而是必需。

### 1.2 跨生成器塌陷(上次已报,已加固)

DeepSeek 训 → Qwen 测(同任务):**0.496**(3 seed:0.499/0.535/0.491)。
体内对照:同跑中 DS 留出 0.64-0.76 vs Qwen 0.47-0.50。
**例外**:tps_dec(最模板化的表格任务)完美迁移 0.653 —— **绑定程度取决于任务解空间的同质性**。

### 1.3 机制:不是表面风格,是结构

用 AST 把所有代码"整容"(变量统一改名 v0/v1、注释与 docstring 全删,2,959 张零解析失败)后重训重测:

| 测试(均为整容后) | 准确率 |
|---|---|
| DS 留出(分布内) | 0.66-0.82 ← 整容没有破坏可学性 |
| Qwen 对(跨生成器) | 0.49-0.54 ← **塌陷纹丝不动** |

→ 绑定在**控制流形状、库使用习惯、解的组织方式**等结构性模式上。**"清洗代码"这条捷径不通,多样性数据是唯一出路。**

### 1.4 修复代价(治愈曲线)

| 干预 | 结果 |
|---|---|
| 掺 160 个新域对(稀释在大池) | 无效(0.486) |
| **551 对专门二阶段微调** | **0.566**(+6.7pt,≈2.9σ) |
| 外推 ~1,000 对(参照 LOTO 少样本) | 0.66-0.71 |
| **跨任务预训练 + 1,000 目标对** | **0.707**(单用任一条 ≈0.62)|

→ 两类数据**互补可叠加**;每个新风格的入场券是几百到上千个标注对。

## 二、你提的 lookahead 任务(进展)

- **不是旧任务换皮(可量化)**:节点自身分 vs 子树最优分相关性仅 0.13-0.60(饱和的 spaceship 除外 0.96);
  **26% 的节点对上"现在谁好"与"谁通向更好"答案相反**;预算越大分歧越大(1 步 15.2% → 全子树 21.1%);
- **训练结果**:树级切分(防泄漏)下,分歧对准确率 **0.609-0.617**(只看眼前的捷径模型在该子集必得 0);
- **测试集已加厚一倍**:分歧对 1,675 → **3,590**(你的深树直接供货);
- **方法学警告(数据集使用规范)**:按节点切分而非按树切分,会让成绩**虚高 21.6 个百分点**(0.825→0.609)——
  血缘相邻节点代码高度相似。这条会写进 datasheet。

## 三、T3(RM 插回 MCTS 选点):null,如实报

8 组 seed 配对(spooky+tps_dec,唯一变量=选点时是否咨询 RM,处理臂带"确实咨询了"的日志证明):**4:4**。

## 五、训练流程(按你的要求重写,已验收)

- `phase1/rm_train_hf.py`:**HF Trainer + DeepSpeed ZeRO-3**(优化器 CPU offload)+ bf16 + cosine/warmup +
  梯度裁剪 + gradient checkpointing + flash-attn2(缺则 sdpa)。**默认全参微调**,`--lora` 可选;
- **对齐验收**:同配置下新旧 trainer 数字 0.593/0.733 vs 0.605/0.746(差 ~1pt,来自 cosine 调度,方向合理);
- **context 实测**:单张 24GB 3090 + ZeRO-3 + 全参 1.5B,**16,384 context 放得下** → H200 上 12k-16k 无压力,
  **不需要 sequence parallel**(已核:HF Trainer 无 SP 参数;accelerate 的 context parallel 走 FSDP 与 DeepSpeed 互斥;
  DeepSpeed Ulysses 需手改注意力层——都不必);
- runbook 已附**多卡故障速查表**(`--local_rank`、ninja 需在 PATH、扩展缓存目录、NCCL P2P、Triton 缓存),
  你那边报错可直接照查:`phase1/实验记录/2026-07-31/H200_RUNBOOK.md`。
