# 实验记录 2026-08-03 —— L2 预算条件化:标签重做 + 基线补齐

> 诚实版:本日**两次自我推翻**(一次废弃标签定义,一次误判 L2 死刑),都记在下面。

## 一、起点:主线拉回 lookahead

学长原话是「在给定的时间、硬件、agent 下,对比树中两个节点哪个可能通向更优解」。
此前实现只覆盖了「哪个通向更优解」,**「给定的时间」从未作为模型输入存在过**(只存在于数据里)。
L2 = 把预算变成模型输入。

## 二、第一次推翻:废弃 v1 标签(深度截断)

v1 定义 `value(node, B) = 深度 ≤B 的子树内最优真分`。**跑训练前先用纯 CPU 测平凡基线**,结果:

| 规则(只用结构特征) | 紧预算 | 松预算 | 均值 |
|---|---|---|---|
| 任一**预算盲**规则 | — | — | 恰好 0.500 ✓(解析性质,框架自检通过) |
| **子树深度**单独预测松预算标签 | 0.121 | **0.879** | 0.500 |
| 「紧预算看自身分 → 松预算看子树深度」 | 0.846 | 0.879 | **0.862** |

**判为伪影的依据是对照组**:同一特征在**非翻转对**上只有 **0.435(低于随机)**。
它不是通用质量信号,只在翻转对上灵 —— 因为翻转对本身就是被子树大小不对称定义出来的。

机制:标签 = 子树内最大值,**子树越大 = 抽样次数越多 = 最大值越高**;而子树多大是 MCTS 自己
决定的。所以 v1 的「谁通向更好」有很大一部分在测「搜索器当初更偏爱谁」。

**废弃 `budget_pairs_v1.jsonl` / `budget_flip_eval_v1.jsonl`。**

## 三、第二次推翻:误判「配额对齐 = L2 死刑」

修法 = **配额对齐**:`value(node,K) = 节点自身 + 按 lineage.step 时序的前 K 个后代`中的最优分,
且**要求配对双方都有 ≥K 个后代**(抽样次数相等)。

第一版脚本产出**只有 10 个翻转对**,我据此写下「这基本判了 L2 死刑」。**这是错的** ——
脚本先按每任务 6000 对截断、再过滤 holdout(两端都在留出树 ≈ 4% 的对),顺序反了。
先分流再截断后:

| 标签定义 | 翻转率 | 可用对 |
|---|---|---|
| v1(抽样次数不等) | 6.08% | 422,622 |
| 配额对齐 K=1 vs K=3 | 8.14% | 181,027 |
| 配额对齐 K=1 vs K=5 | **12.79%** | 46,551 |
| 配额对齐 K=1 vs K=8 | **17.35%** | 12,453 |

**配额对齐不是消掉效应,是放大效应**(2-3 倍)。v1 是在用抽样噪声稀释真实的预算效应。
结构 oracle 从 0.862 降到 0.754;残留是**搜索分配内生性**(MCTS 在那里多展开是因为早期效果好),
任何标签定义都消不掉 → 写进 limitations。它也不是模型的竞争对手:模型只看代码,看不到子树,
且 subtree_depth 在决策时根本不可观测。

## 四、评估设计(可复用)

**翻转对上,任何预算盲模型的均值恰好 0.500 且方差为零** —— 同样输入两次、两个标签相反。
基线是**解析的**,不是实测的。这同时是评估框架的自检项。

实测(两次 smoke,v1 数据与配额对齐数据各一次):预算盲臂在**每个预算档**都打印
`mean=0.5000 / model_switched=0.0000`,逐位吻合 → 框架无误。

评估集 = **剂量-反应阶梯**:K1→K2 / K1→K3 / K1→K5 各 686 / 526 / 252 个翻转对 + 等量非翻转对照。
若预算条件化为真,收益应随预算差单调上升。

**泄漏核验**:2,268 个评估对中,**0 个** pair-level、**0 个** node-level 出现在训练集 —— holdout
逐位复刻了训练数据构造器(含消耗同一条 rng 流的方式,否则任务序会错位)。

## 五、L4 基线(纯 CPU,论文表的对照列)

| 预算 K | 节点自身真分 | **自报分** | 父节点分 | 运行时长 |
|---|---|---|---|---|
| K=1 | 0.870 | 0.795 | 0.739 | 0.634 |
| K=2 | 0.829 | 0.760 | 0.734 | 0.620 |
| K=3 | 0.802 | 0.730 | 0.710 | 0.586 |
| K=5 | **0.761** | **0.703** | 0.699 | 0.594 |

**单调下降 = lookahead 任务存在的定量证据**(预算越大,「只看眼前」越不管用),且在配额对齐下测得。

**修正了一个即将犯的比较错误**:全集上「节点自身真分」= 0.838,若模型在全集报 0.6x 会显得被碾压 ——
但自身真分要**先执行再做一次外部评分**,而模型只读代码。可部署的对手是**自报分**:
全集 0.760 / 分歧子集 0.272。此前报告的 0.609 是**分歧子集**数字(该子集上自身真分定义为 0.000),
两个口径不能放进同一列。

## 六、基建

- **`train_pool.sbatch`**(用户提议):把多个单卡训练打包进一张 allocation。QOS 限 **4 个 job / 8 张卡**,
  打包后训练与采集不再互相排队。坑:**DeepSpeed 一旦收到 `--num_gpus` 就忽略 `CUDA_VISIBLE_DEVICES`**
  (它自己的启动日志里就写了),按该变量分卡会让所有臂挤在 GPU 0 → 必须用 `--include localhost:N`。
- **采集重启**:pool worklist 自 07-31 起耗尽(心跳一直 `un=0 topped=0`)。`step_limit`/`time_limit_secs`
  从硬编码改为可配(默认值不变,向后兼容),新增 23h 深树线 `pool_collect_deep.sbatch`
  (`PC_STEPS=10000`,`PC_TIMELIM=75600`,比 23h 墙留 2h —— 外部真分只在 solver 干净退出时落盘)。
  优先级闸门:`.l2_hold`(smoke 未验证则不发 L2)→ `.deep_hold`(L2 未排上则不发采集)。
- **修掉一个静默 bug**:`ee02805` 提交的 `render(cid, budget)` 调用点在、函数签名没跟上 →
  **任何新 run 都会在第一个 batch 崩**;当时在跑的 job 已加载旧模块所以没炸出来。
