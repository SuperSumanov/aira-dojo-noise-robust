# 实验记录 2026-08-03 —— L2 预算条件化:标签重做 + 基线补齐

> 诚实版:本日**两次自我推翻**(一次废弃标签定义,一次误判 L2 死刑),都记在下面。

## 一、起点:主线拉回 lookahead

学长原话是「在给定的时间、硬件、agent 下,对比树中两个节点哪个可能通向更优解」。
此前实现只覆盖了「哪个通向更优解」,**「给定的时间」从未作为模型输入存在过**(只存在于数据里)。
L2 = 把预算变成模型输入。

## 二、第一次推翻:废弃 v1 标签(深度截断)

v1 定义 `value(node, B) = 深度 ≤B 的子树内最优真分`。**跑训练前先用纯 CPU 测平凡基线**,结果:

| 规则(只用结构特征) | 紧预算 | 松预算 | 均值 |
|---|---|---|---|
| 任一**预算盲**规则 | — | — | 恰好 0.500 ✓(解析性质,框架自检通过) |
| **子树深度**单独预测松预算标签 | 0.121 | **0.879** | 0.500 |
| 「紧预算看自身分 → 松预算看子树深度」 | 0.846 | 0.879 | **0.862** |

**判为伪影的依据是对照组**:同一特征在**非翻转对**上只有 **0.435(低于随机)**。
它不是通用质量信号,只在翻转对上灵 —— 因为翻转对本身就是被子树大小不对称定义出来的。

机制:标签 = 子树内最大值,**子树越大 = 抽样次数越多 = 最大值越高**;而子树多大是 MCTS 自己
决定的。所以 v1 的「谁通向更好」有很大一部分在测「搜索器当初更偏爱谁」。

**废弃 `budget_pairs_v1.jsonl` / `budget_flip_eval_v1.jsonl`。**

## 三、第二次推翻:误判「配额对齐 = L2 死刑」

修法 = **配额对齐**:`value(node,K) = 节点自身 + 按 lineage.step 时序的前 K 个后代`中的最优分,
且**要求配对双方都有 ≥K 个后代**(抽样次数相等)。

第一版脚本产出**只有 10 个翻转对**,我据此写下「这基本判了 L2 死刑」。**这是错的** ——
脚本先按每任务 6000 对截断、再过滤 holdout(两端都在留出树 ≈ 4% 的对),顺序反了。
先分流再截断后:

| 标签定义 | 翻转率 | 可用对 |
|---|---|---|
| v1(抽样次数不等) | 6.08% | 422,622 |
| 配额对齐 K=1 vs K=3 | 8.14% | 181,027 |
| 配额对齐 K=1 vs K=5 | **12.79%** | 46,551 |
| 配额对齐 K=1 vs K=8 | **17.35%** | 12,453 |

**配额对齐不是消掉效应,是放大效应**(2-3 倍)。v1 是在用抽样噪声稀释真实的预算效应。
结构 oracle 从 0.862 降到 0.754;残留是**搜索分配内生性**(MCTS 在那里多展开是因为早期效果好),
任何标签定义都消不掉 → 写进 limitations。它也不是模型的竞争对手:模型只看代码,看不到子树,
且 subtree_depth 在决策时根本不可观测。

## 四、评估设计(可复用)

**翻转对上,任何预算盲模型的均值恰好 0.500 且方差为零** —— 同样输入两次、两个标签相反。
基线是**解析的**,不是实测的。这同时是评估框架的自检项。

实测(两次 smoke,v1 数据与配额对齐数据各一次):预算盲臂在**每个预算档**都打印
`mean=0.5000 / model_switched=0.0000`,逐位吻合 → 框架无误。

评估集 = **剂量-反应阶梯**:K1→K2 / K1→K3 / K1→K5 各 686 / 526 / 252 个翻转对 + 等量非翻转对照。
若预算条件化为真,收益应随预算差单调上升。

**泄漏核验**:2,268 个评估对中,**0 个** pair-level、**0 个** node-level 出现在训练集 —— holdout
逐位复刻了训练数据构造器(含消耗同一条 rng 流的方式,否则任务序会错位)。

## 五、L4 基线(纯 CPU,论文表的对照列)

| 预算 K | 节点自身真分 | **自报分** | 父节点分 | 运行时长 |
|---|---|---|---|---|
| K=1 | 0.870 | 0.795 | 0.739 | 0.634 |
| K=2 | 0.829 | 0.760 | 0.734 | 0.620 |
| K=3 | 0.802 | 0.730 | 0.710 | 0.586 |
| K=5 | **0.761** | **0.703** | 0.699 | 0.594 |

**单调下降 = lookahead 任务存在的定量证据**(预算越大,「只看眼前」越不管用),且在配额对齐下测得。

**修正了一个即将犯的比较错误**:全集上「节点自身真分」= 0.838,若模型在全集报 0.6x 会显得被碾压 ——
但自身真分要**先执行再做一次外部评分**,而模型只读代码。可部署的对手是**自报分**:
全集 0.760 / 分歧子集 0.272。此前报告的 0.609 是**分歧子集**数字(该子集上自身真分定义为 0.000),
两个口径不能放进同一列。

## 十一、证伪:「解空间同质性 → 迁移率」假设(0 GPU,20 分钟)

**动机(事后看,这个动机本身就是警号)**:想把塌陷从「负面发现」升级成「可预测的定律」,
这样它就能当正面主线而不是支撑章。**为体裁需要而推的假设,应该让人更怀疑,而不是更兴奋。**

假设:任务解空间越同质 → RM 越能跨生成器迁移。指标 = 代码里 import 的顶层模块的香农熵。

**阶段一(看起来很好)**:在 `cards_for_crossgen.jsonl`(2,959 卡)上算,4 个任务**完全单调**;
熵对样本量有偏,于是子采样到共同 n=112、重抽 200 次做校正 —— **仍然单调,且四个 CI 完全不重叠**
(3.352 / 3.675 / 3.822 / 3.928)。

**阶段二(当场死亡)**:换**全语料**(7,190 卡)重算同一指标 —— **排序翻转,R² = 0.011**。

| 任务 | 子集算的 H | 全语料算的 H | 落差 |
|---|---|---|---|
| spooky | 3.928(最高) | **3.325(最低)** | 32.7 |
| tps_dec | 3.352 | 3.426 | 4.2 |
| pizza | 3.675 | 3.668 | 17.5 |
| leaf | 3.822 | 3.876 | 26.6 |

根因:spooky 在全语料有 2,274 卡(学长数据已合入),在 crossgen 子集只有 129 卡。
**「完全单调」是子集选择的产物。**

**独立的第二击**:用户同时指出,该假设即使成立也 trivial ——「分布越接近越好迁移」是分布偏移的
教科书结论,审稿人不会惊讶。**同意。**

**教训**:①对子集选择敏感的指标不可信,任何跨任务指标都必须在全语料上复算;
②预检的价值 = 20 分钟 0 GPU 杀掉一个本来要花 1-2 天采集去验证的方向;
③**先写下证伪判据再看数据**(本次判据是「Spearman rho < 0.6 即死」,写在 `prereg_predict.py` 里)。

## 十三、L2 快速点判决 + 基线严格化

**快速点(N=4000,配额对齐数据,两臂):**

| | 预算盲 | 预算条件化 |
|---|---|---|
| in-task acc | 0.7640 | 0.7633 |
| flip K1→K2 (n=686) | 0.4993 | 0.5029 |
| flip K1→K3 (n=526) | 0.5000 | 0.5010 |
| flip K1→K5 (n=252) | 0.4980 | 0.5020 |
| **模型改变偏好比例** | 0.15–0.40% | **0.19–0.58%** |

三档合并 n=1464,均值 0.5021,SE 0.013 → **距解析基线 0.16 个 SE,零效应,无剂量-反应**。
诊断性数字是最后一行:**模型几乎完全无视预算输入**。

**基线严格化(必须记的方法学)**:此前把「模型在采样评估集上的分」与「基线在全体 test 池上的分」
并列,这不是比较。trainer 的采样是确定的(`Random(seed)` → shuffle(train_pool) → shuffle(test_pool)
→ 截断),**两次 shuffle 消耗同一个生成器,所以顺序必须一致才能复现**。在**同一批 1500 对**上:

| 预测器 | 需要什么 | 准确率 | 能判 |
|---|---|---|---|
| 节点自身真分 | 执行 + 外部评分(需真实标签) | 0.8350 | 100% |
| **自报分** | 执行一次 | **0.7163** | 84% |
| 父节点分 | 已有 | 0.6313 | 59% |
| **模型** | **只读代码** | **0.7640** | **100%** |

判不了的对按 0.5 计(模型被迫回答每一对)。只算自报分能判的 84%,它是 0.7586,模型仍高。

## 十五、12 项审计(用户要求「不要到后面再修」)

**干净 5 项**:切分完整性(0 pair / 0 node 泄漏)、budget 一致性(同一对在 4 个预算下同侧)、
跨切分代码 0 份逐字节相同、**step 字段完美**(0 缺失 / 0 重复 / 0 个子节点步号 ≤ 父节点)、
切分内代码重复仅 1%。

**查出并已修 4 项:**

| 问题 | 数字 | 影响 | 修法 |
|---|---|---|---|
| 预算信号密度 | N=4000 里仅 **166** 条带信号 | **很可能就是 L2 null 的主因** | `--flip-boost 5` → 591 |
| 无 τ 过滤 | 8% 的对在噪声内,**birds 25%** | 污染训练与评估 | `--tau-filter` |
| 评估采样偏倚 | spooky 81%,nomad 仅 18 对 | 逐任务数字不可引用 | `--eval-stratify` |
| **长度混杂** | 长度启发式 birds=**0.4056**,模型=**0.411** | **模型在 birds 上退化成长度启发式** | `--eval-len-control 0.15` |

长度启发式逐任务:petfinder 0.676 / tps_may 0.741 / chaii 0.600 / spooky 0.590 /
**birds 0.406 / nomad 0.247**。训练集 78% 是「长的赢」的任务 → 模型学到该关联 →
在关联反向的 birds 上系统性做反。**这是长度混杂的教科书案例,必须进 limitations。**

**无法修、必须写进 limitations 3 项:**
1. **代码多样性天花板 = 1,498 份**。配额对齐要求节点有后代,而 7,190 卡里**只有 2,109 个有子节点**。
   53,745 个训练对全部来自这 1,498 份代码的重组 → **加 N 只买重组不买信息**,只有更深的树能突破。
   这条把深树采集从「补充」升级为整条线的前提;
2. 训练任务不均衡(spooky 33% / chaii 24% / petfinder 21% / birds 12%),而 birds 恰是长度关联反向的任务;
3. 2 epochs 在 1,498 份代码上有过拟合迹象(loss 在 epoch 1.0→1.2 从 0.349 骤降到 0.206)。

**训练健康**:loss 单调下降,grad_norm 18.5→5.2 无爆炸,0 处 NaN/inf。

## 十七、跨生成器 lookahead:测不了(需采集)

Qwen 仅能配出 **22 条** lookahead 记录,GLM **10 条**。根因是结构性的:`build_cards` 只保留有外部
真分的节点,**父节点一旦没真分,父子链就断**;125 张带真分的 Qwen 卡片散在 8 棵浅树(maxdepth 5–8)里,
配额对齐几乎无解。**这是采集问题,不是分析问题。**
