# 给学长的补充(2026-08-09 晚)——采集口径要改,越早越好

前一封说的都还算数,这封只讲一件时间敏感的事:**我算出了我们缺什么,和还差多少。结论是我们该冲的是 run 数,不是卡片数。** 你现在正在采,每多一天用旧口径就多浪费一天,所以先发这个。

---

## 1. 一句话

**统计单位不是卡片,是物理 run。我们有 10,755 张卡,但只有 515 个 run;而要让手上任何一个效应变得可判,需要大约 2,000 个 run。**

## 2. 怎么算出来的

run 级泄漏坐实之后(同一次 run 里的节点互相高度相关,不能当独立样本),所有置信区间都必须按 run 聚类。这一改,我们试过的每个方向都变成同一个形状:效应约 0.55,CI 跨过 0.5。

我把每个方向反推了一遍"要多少独立 run 才能达到 80% 功效":

| 分析 | 观测效应 | 当时测试 run 数 | 需要 | 倍数 |
|---|---|---|---|---|
| L1 前瞻 flip 集 | 0.547 | 23 | 276 | 12× |
| 自报分判错的对 | 0.559 | 35 | 94 | ~3× |
| 修复价值(值不值得 debug) | 0.553 | 29 | 410 | 14× |

held-out 是 20%,所以总量要 ×5。**最难的那条需要约 2,000 个 run,我们有 515。**

按你这两天的实测速度(0806+0807 = 58 个 run / 2 天 ≈ 29 run/天),补齐大约需要 **50 个有效采集日**。NeurIPS D&B(明年 5 月)来得及;ACL 的 ARR(11-12 月)来不及。

## 3. 所以口径改成这样

**要 run 数,不要卡片数。多 seed 浅树 > 少 seed 深树。**

具体说:同样的算力,与其用 4 个 seed 各跑 100 步的深树,不如用 20 个 seed 各跑 20 步的浅树。前者给 4 个独立样本,后者给 20 个。对我们所有的统计检验来说,后者的价值是前者的 5 倍。

**你 0805 之后那个新协议(压时限、压子节点数)方向完全正确**,产出的就是更多更浅的树。建议继续沿这个方向,并且可以再激进一点。

两个约束不变:
- **children 保持 ≥ 2**(压到 1 的话树变成链,同父兄弟的决策集为空,那一整类分析都做不了)
- **卡片带 run id**(现在只能靠批文件连续性反推)

另外,现在薄的任务优先级已经变了 —— 不再看卡片数,要看 **run 数**。目前 ≥20 个 run 的任务只有 9/22:

| 还很缺 run 的任务 | 现有 run |
|---|---|
| whale-categorization | 4 |
| histopathologic-cancer | 6 |
| us-patent-phrase | 7 |
| tweet-sentiment | 9 |
| kuzushiji-recognition | 10 |

## 4. 为什么这个说法值得信(它是可证伪的)

我这两天把能想到的正面方向都试了一遍,七个,全部死在同一个地方。这种一致性本身就是信息:**不是我们的想法不对,是样本量不够,所有效应都卡在可分辨的边缘。**

好处是这个诊断可以被证伪:**同样的实验在 4 倍 run 上重做,如果效应是真而小,会解析出来;如果是零,会明确显示为零。两种结果都能写。** 现在这种"看起来有一点但说不清"的状态才是最没价值的。

## 5. 顺带一个真结果(不用加数据就成立)

搜索过程里挖到一个我认为可以单独成节的发现:

**MLE agent 的 val→test gap 不是"赢家诅咒"(best-of-k 选择噪声)造成的** —— 至少在我们实际运行的分支度下不是。

我在同一批数据上放了正负对照:人为植入一个纯选择噪声造成的诅咒,估计器能清楚看到(k=2 时 −0.31,k=3 时 −0.53,单调加深);随机选兄弟则看不到(全含 0)。而**真实数据在 k=2-3 上只有 −0.012**,是模拟值的 2-4%。k=2-3 覆盖 95% 的兄弟集,逐任务也没有单一任务主导。

这个有意思在于它回答了文献里一个没人调和的矛盾:AIRA-dojo 报 9-13pp 的选择性 gap,另一篇(Bertran 2606.11045)报每 checkpoint 只有 0.0-1.9pp。我们的数据给出机制解释:**诅咒随分支度增长,而 MLE agent 的分支度很低,所以那个 gap 必然另有来源。** 要测这个恰好需要我们这种语料(逐节点自报分 + 真分 + 树位置),别人手上没有。

（这一条我自己改了两次口径才敢写:第一版用错了统计量、第二版把正对照的生成模型写反了。现在这版有正负对照和逐任务检查。）

---

**一句话总结**:采集继续,但口径换成"最大化独立 run 数";目标 ~2,000 个 run;children≥2、带 run id 不变。到那个量级之后,我们那七个方向可以一次性重做并给出确定结论。
