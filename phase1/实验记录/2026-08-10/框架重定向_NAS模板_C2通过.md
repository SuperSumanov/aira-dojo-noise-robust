# 2026-08-10:框架重定向 + 第一个预注册通过的正面结果

## 1. 学长的两条批评,都成立,而且改变了实验设计

**① 「为什么说自报分是免费的?执行一次远慢于 critic 预测一次。」**

成立,而且它作废了我两天的评估框架。自报分只在节点**执行完之后**存在;critic 的价值
是在执行**之前**判断。我一直在拿事后信号当基线否定事前工具。

量化之后这条批评有多重:**自报分的 query 成本 = 一次完整执行 = 中位数 561 秒;
tfidf 预测器 4.8 毫秒。七百万倍成本差,换 13 个准确率点。**

**② 「参考 MCTS+神经网络 / NAS 的做法。」**

这条给了我们现成的、顶会验证过的模板:
- [How Powerful are Performance Predictors in NAS?](https://arxiv.org/abs/2104.01177)(NeurIPS 2021,31 个预测器)
  明确把 **initialization time 与 query time 分开计价** —— 正是 ① 的解法。
- NAS-Bench-101/201/301:**tabular benchmark 让人不训网络就能公平比较**。
  NAS-Bench-201 只有 15,625 个架构;我们 10,755 个**完整程序** × 22 任务,量级相当。
- **[NAS-Bench-Suite-Zero](https://arxiv.org/abs/2210.03230)(NeurIPS D&B 2022)= 我们该照抄的形态**:
  13 个代理 × 28 任务,头条发现是负面的(**#params/FLOPs 打平所有零成本代理**),
  但论文形态是**基准发布 + 系统性分析**,不是"我们失败了"。而且他们另挖一个正面:
  代理间有互补信息,全部并入可提升 42%。

**结论:我们不需要"负结果论文",需要的是"基准 + 第一个系统性预测器研究"。**
缺的是**方法广度**(他们 13 个,我们 1 个)。

## 5. LLM 裁判(suite 第二个方法族):随机水平,但带一个必须标注的公平性缺陷

学长清单 A2 要求方法广度。裁判是最明显的第二族,且查证无人在 MLE 节点选择上做过
(AIDE / aira-dojo 都靠执行反馈)。DeepSeek-v4-flash,400 对 × 双向(控位置偏差)。

| | 1500 token 预算 | **8000 token 预算** |
|---|---|---|
| 解析成功 | 99.2% | **100%** |
| 答案从截断轨迹捞出 | 79% | **41%** |
| **双向平均准确率** | 0.5178 | **0.5075**,CI [0.410, 0.606] |
| 顺序一致性 | 0.584 | **0.690** |
| 完成组 / 截断组 | 0.621 / 0.490 | 0.540 / 0.460 |
| 花费 | ¥6.69 | ¥18.69 |

**给 5 倍推理预算,准确率没动**(0.518→0.508),只有一致性改善。完成组 0.540 的 CI
也跨 0.5。所以「裁判在这个任务上随机」可以写。异常点:google-quest **0.5/18 = 0.028**
(系统性反向,n 小但极端),值得单独看一眼。

**必须随结论同写的缺陷**:裁判每个程序只看 5,000 字符 = **中位程序(13,031 字符)的 38%**,
比 RM 在 2048 token 下的 63% 覆盖还差。所以这个 null 是**下界**。公平重跑需约 ¥30,
当前余额 ¥17.78 且 Qwen 采集(已批准)还需约 ¥12 —— **停在此处,等预算决定。**

## 6. 由此发现的一件对论文更重要的事:截断是 transformer 方法独有的成本

盘点各预测器实际读到多少程序:

| 预测器 | 看到的程序比例 | acc |
|---|---|---|
| static 手工特征 | **100%**(正则扫全文) | 0.6506 |
| tfidf 字符 n-gram | 20,000 字符 ≈ **77%** | **0.6657** |
| RM 1.5B @2048 | **63%** token | 0.6493 |
| LLM 裁判 @5000 字符 | **38%** | 0.5075 |

**便宜方法读完整个程序几乎不花钱,昂贵方法被自己的 context 限制卡住。** 这不只是
"容量不是瓶颈",而是"**贵的方法要为自己的 context 上限付一笔便宜方法不付的税**"。
准确率与覆盖率的排序几乎完全一致,这个关系应当作为 suite 表的一列(而非脚注)呈现,
并由 context 消融四格给出因果证据。
