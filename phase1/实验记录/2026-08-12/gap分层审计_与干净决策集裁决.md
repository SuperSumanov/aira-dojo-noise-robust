## 1. 先修的三个数据问题

### 1.1 分层轴用错了变量(我第一版的错)

`gap_strat.py` 把前瞻对按 `|graded(better) − graded(worse)|` 分层。**这不是标签的边距。**
前瞻对的 better/worse 按**子树最优分**定,文件里的 `gap_raw` 才是那个边距。

对账(`gapcheck.py`):

| 对文件 | `gap_raw == \|graded 差\|` |
|---|---|
| `hits_l1_uncapped.jsonl` | 10.42% |
| `value_pairs_runsplit.jsonl` | 10.46% |
| `decision_pairs_runsplit.jsonl` | 81.44% |

铁证(`confirm_gap.py`):按 `steps_to_best` 分组后

| `steps_to_best` | n | `gap_raw == \|graded 差\|` | better 自分也更好 |
|---|---|---|---|
| **`[0,0]`** | **3804** | **100.00%** | **100.00%** |
| 含一个 0 | 21763 | 7.51% | 83.13% |
| 都不为 0 | 31331 | 1.69% | 80.03% |

`[0,0]` 就是"节点本身即其子树最优"的子集,两个量必然重合 —— 重合率正好 100.00%。
判定:`gap_raw` 是标签边距,**第一版分层判决作废**。

这也解释了第一版唯一的异常:最小桶 `[0,1e-4)` 是唯一没塌的小 gap 桶(RM 0.6346)——
那些"自分几乎相同"的对,标签其实来自完全不同的子树。

### 1.2 决策对的标签是预算相关的,12.14% 的行自相矛盾

`contradict.py`:

| 对文件 | 反向重复(同两点双向都在) | 完全重复行 | 同一对带多个 `gap_raw` | 卷入冲突的行 |
|---|---|---|---|---|
| `decision_pairs_runsplit` | 185 (5.38%) | 830 | 460 (13.37%) | **541 (12.14%)** |
| `value_pairs_runsplit` | 0 | 0 | 0 | 0 |
| `hits_l1_uncapped` | 0 | 0 | 0 | 0 |

区分字段是 **`budget`(0/1/2)**。所以决策对标签是"在这个预算下谁更好",**预算盲的预测器
被构造性地压在 100% 以下**。按预算拆开后(`mk_decision_clean.py`):

| budget | 测试对 | 反向冲突 | 重复 | `gap_raw==\|graded 差\|` | 顺序与当前语料一致 |
|---|---|---|---|---|---|
| **0** | **947** | **0** | **0** | **100.00%** | **100.00%** |
| 1 | 170 | 0 | 0 | 31.06% | 75.78% |
| 2 | 144 | 0 | 0 | 16.67% | 71.97% |

**budget=0 是干净靶子**,而且它的标签边距就是自分边距,所以 regrade 推出的噪声上界在这里
**精确成立**,不是上界。

### 1.3 排除掉的(都实测,不是推理)

- **语料漂移**:`cards_current` → v6 → v7 → v8 四版之间 graded **零漂移**(`drift_all.py`)。
  用最早的语料复算,矛盾对数一模一样 293/4417,说明标签当天就矛盾,不是陈旧。
- **orientation**:没有任何任务的矛盾率接近 100%(spooky 9.02%、petfinder 7.14%)。
- **标签字段**:`fieldcheck.py` 枚举全部数值字段,只有 `label.graded` 能对上
  (顺序 93.4% / gap 82.1%);`y_norm`、`val_at_low`、`runtime_s`、`step` 全部 ≈ 0%。
- **切分**:`value-TRAIN runs ∩ decision-TEST runs = 0` —— 兄弟对可以合法地用价值对训的
  模型打分,不构成泄漏。

## 4. LLM 判官在难区 0.1667:不是 bug,是标签的结构产物

`judge_paired.py` 查过:800 行判官对与前瞻对 **100% 同向、0% 反向**,不存在标签反转 bug。

机制:Debug 算子作用在**坏代码**上,坏节点被修好后子树最优分很高 → 前瞻标签把
"代码看起来差"的节点标成 better。任何读代码质量的预测器,在小边距处必然反相关。
→ **前瞻标签在难区带结构性人工产物,不能当唯一评测靶。**(与
`实验记录/2026-08-08` 的 lookahead 标签混杂记录同源。)
