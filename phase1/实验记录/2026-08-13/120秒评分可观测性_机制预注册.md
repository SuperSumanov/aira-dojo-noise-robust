# 120 秒评分可观测性：一次性机制可行性预注册（2026-08-13）

状态：**输入、特征、模型、外层切分、推断与裁决门冻结；尚未运行真实数据模型。**

## 1. 问题与边界

前一冻结分解显示：在 120 秒已经得到可评分 `submission.csv` 的候选中，pristine 分数值有用；
但“是否及时得到 artifact”本身相对 stdout 是负向选择信号。这里检验一个更窄的问题：

> 仅凭执行前代码与任务身份，能否在未共享 physical run 的候选上预测 120 秒时 pristine 外部分是否
> 可观测？

这不是 selector 实验，不读取 child 最终质量来开发策略，不比较搜索收益，也不允许在旧 100 sets
上继续扫 override/margin/fallback。即使通过，只说明显式 propensity/censoring 模型具有可行性；
真正方法必须在新的 discovery split 开发并在独立新 runs 上验证。

| `phase1/fidelity_results.jsonl` | `b1266d04912596b1e37e13f79ce2387a962f5510cfa264aa1a97b7a1c443180d` | 30/120 秒 replay；只从 120 秒行构造标签 |

必须为 230 个唯一 card、460 个 replay 行、每 card 恰有一个 cap=120 行、52 runs、19 tasks，且
run map 100% 覆盖。任一 SHA、计数、card/task 对齐或 cap 唯一性不符即 fail closed。

主标签固定为 `usable_score_120 = isfinite(numeric sub_score)`，JSON boolean 不视为数值分数；不是仅

20,000 字符上限被截断。

## 3. 严禁进入特征的字段

`graded`、`sub_score`、`sub_exists`、`stdout_val`、`stdout_tail`、`stderr/err_tail`、`val_at_low`、
`stratum`、wall time、return code、输出字节数、parent/child 最终比较及任何执行后字段均不得进入模型。

允许输入只有：

- 截断到前 20,000 字符的原始 `code`；
- `competition`，仅供预先声明的 task-only baseline 与 code+task 主模型；
- `card_id`、`run_id` 仅用于确定性控制与切分，绝不作为学习特征。

## 4. 冻结模型与外层预测

主外层切分固定为 `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=9173)`，group 为
physical run。另以 9174、9175、9176、9177 四个 seed 完整重做外层 OOF 作为切分敏感性检查；
不按结果选择 seed，headline、bootstrap 与 sign 始终使用 9173。报告五个 seed 的主模型 AUC、
median、sample variance 与 minimum。任何 seed 中 run 跨 fold即 fail closed。所有词表、IDF、任务
one-hot 与模型参数只在各自 outer-train fold 拟合。

按以下固定顺序报告，不挑 champion：

1. `global_prevalence`：训练 fold 全局比例；
2. `task_prevalence`：训练 fold 内按任务比例，使用强度 5 的全局比例平滑；未见任务回退全局比例；
3. `code_tfidf`：代码字符 3—5 gram，`min_df=2`、`max_features=20000`、`sublinear_tf=True`、
   L2 normalization；`LogisticRegression(C=1, solver=liblinear, max_iter=2000, random_state=9173)`；
4. `code_task_tfidf`（唯一主模型）：同一代码表示加训练 fold 内拟合的 task one-hot，同一 LR 设置。

跨任务压力测试固定为 leave-one-task-out，只运行 `code_tfidf`，每次整个任务完全留出。pooled AUC
固定使用全部 held-out rows（单类任务的行仍属于合法 pooled 预测）；macro task AUC 只平均同时含
正负标签的任务。不得以压力测试结果反选主模型或改参数。

代码路径控制：`label_oracle` 的 AUC 必须严格为 1；`crc32(card_id)` 是固定负控制，只用于发现
评估代码异常，不构成裁决门。

## 5. 指标与推断

主指标：230 个 outer-fold OOF 预测上的 ROC-AUC。校准主指标：Brier score；报告
`task_prevalence Brier - code_task_tfidf Brier`，正值表示主模型更好。另报 average precision 与
log loss，不参与裁决。

- physical-run cluster bootstrap 为主，task cluster bootstrap 为必要压力检查；各 20,000 次，
  percentile 95% CI，seed=9173；按 cluster multiplicity 加权，不把 card 当独立样本；
- 对每 run 的平均 Brier gain 做双侧 exact sign test，零差 run 作为 ties 排除；
- 数值零差固定为绝对值不超过 `1e-12`，不得看结果后修改；
- LOTO 报 pooled AUC、仅在同时含正负标签的任务上的 macro task AUC，以及 task-cluster bootstrap CI；
- 不删除 task/run，不报告事后最优子集，不以 hard/easy、artifact-present 子集或 set-size 子集替换主结果。

## 6. 裁决门

- **GO-FEASIBLE**：以下全部满足：
  1. `code_task_tfidf` OOF AUC `>=0.65`，且 run/task cluster CI 下界均严格 `>0.50`；
  2. 相对 `task_prevalence` 的 Brier gain `>0`，且 run/task cluster CI 下界均严格 `>0`；
  3. run-level Brier-gain exact sign `p<0.05` 且正向 runs 多于负向 runs；
  4. `code_tfidf` LOTO pooled AUC `>=0.60`，task-cluster CI 下界严格 `>0.50`；
  5. 五个 split seeds 的主模型 AUC median `>=0.65` 且 minimum `>0.50`；
  6. 全部完整性与控制检查通过。
- **KILL**：主模型 AUC `<=0.50`，或 run-cluster AUC CI 上界 `<=0.50`，或完整性检查失败。
- **BORDERLINE**：不属于 KILL，但任一 GO-FEASIBLE 门未过。

GO-FEASIBLE 也不授权在论文中声称搜索改进，只授权在新 discovery/validation split 开发一个显式
删失模型。BORDERLINE/KILL 时关闭“从现有代码预测可观测性”的近期方法路线，优先评估独立的
schema-first operator 干预。
