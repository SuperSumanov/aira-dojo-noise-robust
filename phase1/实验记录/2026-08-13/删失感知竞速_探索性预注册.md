## 1. 问题与固定策略

旧机制审计已经冻结地显示：在 120 秒已经有 finite pristine artifact score 的候选中，分数值有用；
但“是否及时产生 artifact”本身相对 stdout 是负信号。因此普通 successive-halving 式做法——只保留
已有低保真分数的候选、淘汰暂时 silent 的候选——可能恰好丢掉最终赢家。

对每个真实 sibling set，在 120 秒定义：

- `O`：已有 finite pristine `sub_score` 的候选；
- `M`：其余候选（包括无 artifact、artifact 不稳定或 grader 未给 finite score）；
- `B(O)`：按任务方向在 `O` 中取得最优分数的全部并列候选。

冻结三种策略：

1. `full_continue`：保留全部候选；
2. `observed_only`：若 `O` 非空，只保留 `B(O)`；若 `O` 为空，保留全部。这是把缺失当差的普通
   scalar race；
3. `censor_aware`：若 `O` 非空，保留 `M ∪ B(O)`、只淘汰 `O \ B(O)`；若 `O` 为空，保留全部。

`censor_aware` 不训练模型、不设 margin、不看 stdout/parent/final grade 作决策，也不在 outcome 后扫阈值。
它的核心是：**只淘汰已经得到可比较分数且被另一 observed candidate 严格支配者；对未观测者 abstain。**

## 3. 冻结指标

真实最终最优集合记作 `T`，所有 tie 以 utility `abs_tol=1e-12` 处理。

主安全指标：

- `any_winner_survival = 1[K ∩ T ≠ ∅]`；
- `winner_fraction_survival = |K ∩ T| / |T|`；
- `censor_aware − observed_only` 的 any-winner survival 配对差；
- 与**同样保留全部 `M`、再从 `O` 中均匀随机保留 `|B(O)|` 个**的结构匹配随机策略比较。
  它固定 abstention 集合，只隔离 observed 分数排序的贡献。随机基线不用 Monte Carlo：若 `M`
  已含最终 winner，survival 期望为 1；否则在 `O` 内用超几何精确期望
  `1 - C(|O|-|T∩O|, |B|)/C(|O|, |B|)`。

资源指标：

- aggregate pruned-card fraction；
- 被淘汰候选的历史 full-runtime 占比；
- optimistic no-restart accounting：120 秒 probe 后只补 survivor 的历史剩余 runtime；
- pessimistic restart accounting：probe 后从头重跑 survivor；
- artifact/grader-attempt 数。

历史 worker 没记录 grader wall，因此上述 runtime 只作 accounting bound，**不得据此声称真实加速**。
新 continuous watcher 已记录 grader wall，实际方法实验必须把 grader、容器启动与失败重试全部计费。

推断以 physical run 为主、task 为次，10,000 draws、seed=20260813。描述性报告 set-macro mean；
推断分别先在每个 cluster 内求 set mean，再对等权 cluster means bootstrap，报告 run-macro/task-macro
point 与 CI；同时报告 run-level exact sign test、每任务结果和 leave-one-task-out。单 set 不能当独立样本。

## 4. 预注册裁决门

同时满足才记为 `GO-FEASIBLE`：

1. `censor_aware` any-winner survival ≥0.90，run/task clustered CI 下界分别 ≥0.80/0.75；
2. aggregate pruned-card fraction ≥0.10；
3. 相对 `observed_only` 的 survival 差 ≥+0.10，run/task CI 下界均 >0，至少 10 个 informative runs，
   且 run-level exact sign `p<0.05`；
4. 相对结构匹配 random 的精确期望差 ≥+0.10，run/task CI 下界均 >0；
5. optimistic avoidable-tail fraction ≥0.10（只作必要的资源空间门，不宣称实测加速）；
6. 任一拥有 ≥5 sets 的任务，其 censor-aware survival 不低于 0.60、相对结构匹配 random 的差不为负；
   leave-one-task-out 的两项主差均不为负。

若 censor-aware survival ≤ structured-random 或 pruned-card fraction <0.05，则 `KILL`；其余为
`BORDERLINE`。任何 GO 仍只是旧发现集上的**方法可行性**，只能授权在新 discovery split 开发
`TaskHazard × ScoreValue`，不能写作独立复现。

## 5. 正负控制与停止规则

- `full_continue` 必须对每个 set 保留最终 winner；
- synthetic self-test 固定覆盖：silent winner、observed dominated candidate、artifact tie、lower-is-better、
  超几何随机期望；
- 独立 verifier 不 import 主脚本，从 raw inputs 逐 set 重建策略并复核 CSV/summary；
- 只运行一次冻结分析。不因 BORDERLINE/KILL 修改 cap、margin、tie、任务子集或 gate；不继续在旧
  100 sets 上调策略。

## 6. 若通过后的唯一方法化路线

新 run 按 physical run 隔离：先保留前瞻机制确认集，再划 discovery / validation / certification。
`TaskHazard` 只决定任务通常应等待到哪个 checkpoint；`ScoreValue` 只在 score 可见后做支配淘汰；
未见任务、support 不足任务和认证未过的任务全部 abstain/full-continue。最终成功候选 recall 在独立
certification 上使用 exact lower bound；确认集绝不进入训练、阈值选择或模型比较。
