## 最新配置缺陷

`BradleyTerryConfig` 当前同时设置：

```python
save_strategy = "best"
metric_for_best_model = "eval_pair_accuracy"
greater_is_better = False
load_best_model_at_end = False
```

`eval_pair_accuracy` 应最大化，因此 `greater_is_better` 应为 `True`。当前配置会把更低 accuracy 当作更优
checkpoint。逐 checkpoint 日志数值本身不受影响；因为 `load_best_model_at_end=False`，训练结束不会自动装回
错误 checkpoint，但 best-only 保存和后续“加载 best”可能反向。修复后应先用两次人为递增 metric 的最小测试
确认保存 step，再重启昂贵训练。

0812 outcome 使用较早的 `eval_loss + greater_is_better=false`，不能把旧约 0.55 结果事后归因于这个新 bug。
