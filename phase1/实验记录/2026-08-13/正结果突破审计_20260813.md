# 正结果突破审计：从“可行 probe”到可投稿的方法结果

日期：2026-08-13
状态：路线备忘；V2 可行性门已正式 PASS，下一步为独立小规模因果 A/B，不是效果结论

## 1. 最值得押注的主张

最强版本不是“early metric 能预测 final score”，而是：自由形态 MLE 搜索存在可分解的
**observability loss** 与 **ranking loss**；普通执行前 critic 主要攻击后者，但当前真实 sibling 上后者难学，
而赢家经常在决策时刻完全不可评分。一个 host-verifiable、候选特异、不可变的 artifact contract 能先降低
observability loss，再让成熟的外部 grader/BAI 方法有信号可用。

该主张有三个必须同时成立的因果台阶：

1. compliance：不同任务上的候选能在固定时限内稳定产 probe；
2. fidelity：probe 对 final quality 的排序价值高于同成本 stdout/presence；
3. utility：固定总 GPU/API/grader 预算下，完整搜索的 best-final 或 regret 改善，且 final quality 不劣。

V2 已在两个新任务上以 2/2 probe、2/2 full transition 通过第一步；它没有 original-prompt 对照，
也没有触发 debug，因此不能越级到 fidelity、utility 或 debug 有效性结论。

## 2. 路线优先级

### A. Contract-constrained Probe-First Search（首选，已获小规模 A/B 资格）

在全新 discovery tasks 上比较 original 与 probe-first operator。两臂固定底座、task×seed block、
候选数、conditional-debug、执行/grader/API 预算；arm 请求顺序按 block 随机交错，防止服务端时间漂移。
每个 operator 的同一批候选离线复用 stdout 与 pristine selector，形成 operator×selector 的 2×2 分解。

先做 6 tasks×2 seeds 的 safety/discovery，不做显著性声明；只有 probe coverage 明显提升、代码失败率不升且
final score 没有方向性损害，才冻结约 60 个 task×seed blocks 的确认实验。主推断使用 task/run block，
McNemar 只作候选级补充。headline 是固定总预算的 best-final、observability/ranking/total regret、wall time、
grader 次数和失败全分母，而不是 observed-only accuracy。

### B. Frozen Instrumenter on Identical Base Code（prompt-only 失败后的候选）

先生成一次原始 base code，再由冻结的独立 instrumenter 产生 scoreable-probe 版本；原始和 instrumented 在相同
容器、数据与上限下配对执行。该设计减少“两个 prompt 生成了不同算法”的混杂，但必须把代码重写成本和
破坏率算入结果，并保存 AST/diff/provenance。

这条路线不能声称首个环境 instrumentation：ICLR 2026 的 RL for MLE Agents 已用静态 LM 插入 print milestones
提供 partial credit；ML pipeline logical-plan 工作也已自动重写和插桩。可区分点只能是：不微调底座、产生可由
pristine grader 评分的候选特异 artifact、不可变 host contract、真实 sibling 决策和固定预算搜索收益。

若 instrumenter 只能插入“loaded data/trained model”之类共同 milestone，而不能产候选特异分数，它只能作为
prior-art baseline，不能成为我方正方法。

### C. Observability Frontier Benchmark（D&B 保底主贡献）

无论方法是否通过，都可在新 run 上冻结一张二维 frontier：时间 `tau`×artifact coverage、winner visibility、
observability loss、ranking loss、total regret 与真实成本。它把 NAS-style predictor benchmark 从一个 headline
accuracy 扩展为“何时可观测、观测后能否排序、最终是否值得继续”的统一协议。

正结果必须来自前瞻数据：例如 pristine probe 在相同覆盖上接近 full signal、并稳定优于 stdout；旧 100 sets
只作为发现集。150-run channel confirmation 仍有价值，但不能用晚入库的旧源数据冒充前瞻。

## 3. 已有工作划定的禁区

- KompeteAI 已做 reduced-epoch logs、final-score prediction 与 pipeline 加速；不能声称首次 early metric；
- AutoDL challenge 已以 learning-curve area 奖励 anytime learning；不能声称首次 anytime ML；
- learning-curve extrapolation、freeze-thaw BO、multi-fidelity BAI 已处理可暂停迭代 learner；selector 本身不是 novelty；
- delayed-feedback BAI、censored/failure-aware BO 已处理缺失或延迟 objective；不能只写“MNAR feedback”；
- RL for MLE Agents 已发现 variable-duration bias，并用静态 LM instrumentation 给中间步骤 partial credit；
- 自动 logical-plan instrumentation 已能重写常见 ML pipeline；不能笼统声称首次 pipeline instrumentation；
- ContractBench 已把外部 API 中间产物的时效/字节完整性称为 observation contracts，并用虚拟时钟和 SHA-256
  测合规；Proof of Execution 也已形式化 contract、事件流和 replay context。因而“contract、hash、replay”这些
  机制词本身不是 novelty，我方必须证明它们解决了 MLE 搜索中的候选可评分性和固定预算选择问题；
- SandMLE 已使用 valid-output milestone；合法输出本身不是 novelty。
- [Gome](https://arxiv.org/abs/2603.01692) 已主张丰富执行反馈和定向更新优于把反馈压成标量的树搜索；
  我们不能把“利用 rich feedback”本身当新意，差异应是先让真实自由形态候选在早期产生可外部验证的反馈。
- [Optimal Multi-Fidelity Best-Arm Identification](https://openreview.net/forum?id=gKMTM1i8Ew) 已给出
  不同 arm/fidelity 成本与精度的理论和算法；selector 或最优 fidelity 本身不是新意。我们的实证问题是候选
  在给定时刻可能根本没有可评分 observation，而 contract 是改变该观测过程的干预。
- [Static and Dynamic Values of Computation in MCTS](https://proceedings.mlr.press/v124/sezener20a.html)
  已直接量化 computation 对最终动作质量的价值；后续 controller 可以引用其 metareasoning 视角，但不能
  声称首次按 value-of-computation 分配搜索预算。
- [EnCompass](https://openreview.net/forum?id=IKVkpjSJzJ) 已把 agent workflow 与 inference-time search
  strategy 解耦；我们的 operator×selector 分解应作为严谨实验设计，不是单独的 novelty claim。
- [AgentExecutor](https://arxiv.org/abs/2608.05959) 已用 agentic context generation 改善 partial code
  execution；“让部分代码可执行”也不是主张。我们要求完整 MLE 候选产生由真实标签/特征训练、可由
  pristine grader 比较的 task output，并检验真实 sibling 搜索收益。

因此可投稿的差异必须是这组组合证据：真实开放式代码 + 真实 sibling 搜索 + 候选特异且可外部评分的 immutable
artifact + host/pristine provenance + observability regret 分解 + 独立 run/task 因果收益。

## 4. 明确不再投入的方向

- 扩大 1.5B→8B 静态 critic 或继续换 LLM judge；现有结果没有规模单调性；
- 在旧 frozen 100 sets 上继续调阈值、confidence、gap 或 censoring 规则；
- 把 artifact presence 当质量，或把共同 sample submission 当候选信号；
- 用 V1 的成功任务补写跨任务成功率；
- 在 V2 失败后继续改 schema prompt；
- 任何底座 LLM 微调/RL-finetune。
