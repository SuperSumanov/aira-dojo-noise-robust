# 覆盖感知多保真：冻结兄弟集离线裁决（2026-08-13）

## 裁决

**保留为主线的正面突破口，但当前证据等级是 exploratory，不是预注册确认性结果。**

在冻结的 100 个真实兄弟集上，策略先让每个候选运行 120 秒；有 schema-valid
`submission.csv` 的候选由同一个 pristine 外部 grader 评分，沉默候选升级到完整外部评估，
最后在同一评分尺度上选择。该策略的 top-1 为 **0.9600**，physical-run clustered 95% CI
**[0.9010, 1.0000]**。相对完整 self-report 且所有候选都有自报分的 89 个同集决策，提升
**+0.1798**，run-clustered CI **[+0.0854, +0.2727]**。

这不是“用 120 秒替代完整执行”的结果：120 秒时仅 **86/230** 个候选有可评分 artifact，
其余 **144/230** 仍做完整评估。按独立测得的语料完整执行中位数 561 秒校准，重启式总成本
为全量的 **0.7721**，若执行可连续恢复则为 **0.6382**。这是一个约 23%–36% 的
质量—成本改进候选，不是数量级加速。

## 研究问题与策略（开盒前固定于本次脚本）

1. 所有兄弟先运行固定 wall-clock cap；
2. 只信任能够生成合法提交并通过 pristine grader 的 artifact；
3. 沉默候选不能当失败，必须升级到完整外部评估；
4. 部分和完整 artifact 均由同一 grader 计分，再按任务方向选择；
5. 同分随机打破，脚本解析计算其期望，不依赖集合迭代顺序。

该规则是在 30/120 秒剂量实验及其覆盖率已经可见后提出，故本次只算探索性策略发现。
确认性版本必须在后续新增 run 上先冻结规则、再开盒。

## 预检与输入不变量

- 冻结样本：`fidelity_manifest.jsonl`，100 sets / 230 children / 19 tasks；恰好 50 hard +
  50 easy，因此 ALL 是设计平衡总体，不代表自然难度比例。
- 120 秒结果一候选一行，230/230 完整覆盖；外部真分 230/230 有限值。
- 100 个 parent 来自 **52 个 physical runs**；全部子节点均能唯一映射到一个 run，0 mixed-run set。
- 主 CI 按 physical run 聚类，parent 聚类仅作次级报告。
- 正控 `full_external` 必须 top-1=1、regret=0；两项断言均通过。
- 任务方向来自固定 `task_orientation.json`；lower-is-better 在 utility 层统一取负。
- 输入 SHA、base git commit、Python 版本、命令和 bootstrap seed 写入每个 `summary.json`。
- 无训练、无 GPU、无 test 行进入训练；本实验只是冻结决策集上的政策模拟。

## 结果

### 120 秒

| policy | top-1 | physical-run 95% CI | 平均 restart/full（按 set） |
|---|---:|---:|---:|
| random | 0.4598 | [0.4368, 0.4790] | 0 |
| sub@120，有 artifact 才参与；全沉默时随机 | 0.5783 | [0.4865, 0.6703] | 0.147 |
| 完整 self-report，可用候选中选 | 0.7800 | [0.6957, 0.8673] | 1.000 |
| 完整 self-report，完整覆盖的 89 sets | 0.7865 | [0.6989, 0.8765] | 1.000 |
| **artifact@120 + 沉默升级完整** | **0.9600** | **[0.9010, 1.0000]** | **0.795** |
| full external oracle | 1.0000 | [1.0000, 1.0000] | 1.000 |

按全部候选加权的账本：低保真实测总 wall time **18,846.0 秒**；完整评估 **144 次**，
对照全量 **230 次**。561 秒中位数情景下，restart/full = **0.7721**，
continue/full = **0.6382**。

关键配对差值（run-clustered）：

- 升级策略 − random：**+0.5002** [+0.4479, +0.5429]
- 升级策略 − sub@120 available-only：**+0.3817** [+0.2926, +0.4670]
- 升级策略 − 完整覆盖 self-report（89 sets）：**+0.1798** [+0.0854, +0.2727]
- 升级策略 − full external：**−0.0400** [−0.0990, +0.0000]

hard/easy 均成立：hard top-1 **0.9400** [0.8444, 1.0000]，easy **0.9800**
[0.9375, 1.0000]；在 self-report 完整覆盖子集上，相对差值分别为 hard **+0.1957**
[+0.0682, +0.3137]、easy **+0.1628** [+0.0488, +0.2857]（run-clustered）。

### 30 秒负对照

30 秒只有 **20/230** 个 artifact，升级策略 top-1=**1.0000**，但仍需 **210 次**完整评估；
aggregate restart/full = **0.9610**，continue/full = **0.9122**。质量高只是因为几乎全量升级，
没有实用节省。120 秒相对 30 秒首次形成有意义的成本—质量前沿。

## 评分尺度核验

`sub_score` 与 `graded` 均由 MLE-bench pristine `grade-sample` 通道产生。独立重算发现：

- 30 秒：20 个 artifact 中 18 个与历史 full grade 精确相同，最大绝对差 0.00251；
- 120 秒：86 个中 56 个精确相同，最大绝对差 0.09654；85 个正常完成、1 个超时前已落提交。

差异来自独立重执行/部分训练，不应强行要求逐值相等；它正是升级策略相对 full oracle 丢失
4/100 个决策的来源。独立、未 import 主脚本的第二实现也重算得到 **96/100** 命中。

## 不能越过的解释边界

1. **成本秒数不是逐候选实测 full runtime。** 当前冻结 manifest 没保存这一列；0.7721/0.6382
   只是 561 秒中位数校准情景。精确成本前沿必须从 v9 卡片补回每个候选的 `runtime_s`。
2. **样本不是自然分布。** 50 hard + 50 easy 是刻意平衡抽样；只能分别报告或以后按自然比例重权。
3. **独立 n 是 52 runs，不是 100 parents。** 所有主 CI 已按 run 聚类。
4. **策略仍做了大量完整评估。** 正面主张是 coverage-aware allocation，而不是“120 秒评分已足够”。
5. **后见策略风险。** 规则在覆盖率可见后形成；本批不能作为确认性最终表。
6. **单次低保真有随机性。** 尚无重复 120 秒估计方差，不能声称完成了“均值−λ×波动”的一致性选择。
7. **当前旧 HCE 代码不合约。** 既有实现是 50/25/25 且低保真为标签子集；不能拿来支持新的
   80/10/10 + time-fidelity + full_locked 主张。

## 下一步关口

1. **零/低成本先做**：从 v9 原卡片补回这 230 个候选的逐候选 `runtime_s`，重算精确成本；
   当前 GitHub LFS 对象缺失，需远端恢复后同时修复发布对象。
2. **前瞻确认**：在学长后续新增 run 上，在看结果前冻结 cap=120、artifact-valid 条件、沉默升级、
   tie 规则与 run-cluster 分析；不调阈值。
3. **主线工程**：重建 80/10/10 full_locked 外部评估；time fidelity 必须生成同 schema artifact，
   grader pristine，silent escalate。旧 HCE 结果全部隔离。
4. 300 秒点或重复 120 秒方差实验会新增 GPU 成本，按项目规则先报矩阵和 GPU·h，不在夜间擅自启动。
