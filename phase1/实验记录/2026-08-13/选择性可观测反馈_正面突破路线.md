# 正面突破路线：从“低保真”改写为“选择性可观测反馈”（2026-08-13）

状态：路线设计；不替代已冻结的 150-run 前瞻确认，不授权在旧 100 sets 上继续调规则。

## 1. 目前能诚实主张的机制

严格共同候选子集上，120 秒 pristine 外部分相对 stdout 的 top-1 差为 +0.2083，但只有 5 个
informative physical runs，exact sign p=0.0625，因此仍是候选机制。coverage-complete 分解进一步给出：

- 已观察到 artifact 时，使用其分数值相对只使用 presence 提高 +0.1447，run/task CI 均在 0 以上；
- artifact presence 本身相对 stdout 降低 -0.0747，run/task CI 均在 0 以下；
- naive artifact-first 只提高 +0.0700，parent-certified 只提高 +0.0300，两者均为 BORDERLINE。

这组结果把问题从“找一个更好的低保真标量”改写为：**高价值的低保真分数只在选择性的一部分候选上
可见；缺失本身不能当低质量。**

令 `Z_t` 表示时刻 `t` 是否已经产生可评分 artifact，`S_t` 是仅在 `Z_t=1` 时可见的 pristine 分数，
`Y` 是完整执行质量。普通 multi-fidelity 方法通常直接建模 `S_t≈Y`；这里必须同时处理
`P(Z_t=1 | history)` 与 `Y | history,Z_t,S_t`，并明确允许 abstain。

## 2. 首选方法候选：CensoredScore controller

执行前可观测性冻结审计的结果为 BORDERLINE：现有任务内 `code+task` AUC=0.8629，但 task-only
AUC=0.8642；Brier gain 的双聚类 CI 跨 0，whole-task LOTO 的 task-CI=[0.4554,0.8388]。因此下面
路线只能在新 split 上作为 **task-conditional** 候选，并对未见任务 abstain；不能声称已有通用
propensity model。

### 2.0 先做低容量版本：TaskHazard × ScoreValue

冻结审计里 task-only AUC=0.8642，略高于 code+task 0.8629；因此近期不应先堆代码级 propensity 模型。
更稳的控制器把两个已验证/候选信号分工：

- `TaskHazard`：只用新 training runs 的 task-level time-to-artifact 生存曲线决定“该任务通常要等多久”；
- `ScoreValue`：artifact 稳定出现后才用 pristine 分数排序，不把未出现视为低分；
- 对训练中未见任务、support 不足任务或 exact recall certification 不过的任务直接 abstain，回退完整执行。

这一路线容量低、解释清楚，也直接响应任务管线异质性。只有在新 validation/certification 上证明相对
统一 120 秒预算节省 GPU 时间且成功候选 recall 达标，才升级到代码/trace 条件的两部分模型。

### 2.1 数据地基

每个候选只连续执行一次，由容器外 pristine watcher 在固定时刻复制 artifact 并事后评分，记录：

- 首次 schema-valid 且可评分 artifact 的时间 `T_art`；到预算仍无 artifact 时记右删失；
- 固定 checkpoints 的 stdout、artifact hash、pristine `S_t` 与 grader provenance；
- 完整执行 `Y`、physical run、task、parent、硬件、镜像、数据和代码 SHA；
- watcher 只观测/复制，不向 agent 泄露标签，不改 workspace 或执行逻辑。

一次连续执行能产生整条 fidelity curve，避免当前 30/120 秒各自 fresh restart 的重复成本；但两种口径
估计量不同，旧 fresh-cap 剂量曲线保留作历史基准，不混在同一 headline。

### 2.2 两部分预测与保守决策

在新的 discovery/validation runs 上，按 physical run cross-fit：

1. survival/propensity：估计 `P(T_art≤t | code,task,trace_t)`；
2. outcome：分别估计 observed branch 的 `Y | S_t,history` 与 silent branch 的 `Y | Z_t=0,history`；
3. controller 不把 `Z_t=0` 设成低分，而比较继续执行的保守价值与成本；证据不足时 abstain/继续；
4. 对“最终会成功/优于 parent 的候选不得被提前淘汰”设 recall 目标，在独立 certification runs 上用
   exact binomial lower bound 认证；未过门就退化为不提前淘汰。

如果只用 propensity 做 inverse weighting，需要额外的 conditional-MAR 与 positivity 假设；现有数据没有
证明这些假设。因此首版不把 IPW 当因果修复，而使用最终 `Y` 齐全的新训练样本直接训练两分支模型，
并在未见 runs 上评价整个固定策略。

### 2.3 必须比较的固定基线

- full execution；
- stdout-only；
- naive artifact-first；
- parent-certified（已关闭，只作冻结历史基线）；
- 标准 scalar multi-fidelity / successive halving；
- CensoredScore；
- hindsight oracle（只量化剩余空间，不参与方法比较）。

headline 同时报固定总 GPU 时间下的 best final score、成功候选 recall、pristine grader 调用数、墙钟与
artifact coverage；不能只报节省率，也不能把评估 grader 成本藏起来。

## 3. 备选正干预：schema-first operator

若执行前代码无法稳定预测 `Z_120`，更直接的瓶颈干预是让 agent 先写出 schema-valid cheap baseline，
再继续复杂建模。它改变 operator/prompt，不能伪装成评分协议改进。公平实验采用 2×2 分解：

- operator：原始 vs schema-first；
- offline selector：stdout-only vs pristine score channel。

同一 operator 产生的候选离线复用两种 selector，因此无需把生成成本复制两遍。先看 artifact coverage 与
grader-valid rate，再看固定总预算下 final score；只有 coverage 上升且 final quality 不降，才进入扩大验证。
prompt、底座、任务、seed、每任务 API/GPU 预算、算子集和外部 grader 必须固定。

## 4. 与最近工作的边界

- [FOREAGENT](https://arxiv.org/abs/2601.05930) 以 task/report/code 做执行前 pairwise preference，并在
  5 个任务上做 Predict-then-Verify；我们已在真实 sibling 决策点复现到接近随机，不能再把“换更大 judge”
  当主突破。我们的差异应是 run-aware 真实决策评测与选择性执行反馈，而非笼统声称首次预测 MLE 代码。
- [Multi-Fidelity Multi-Armed Bandits Revisited](https://proceedings.neurips.cc/paper_files/paper/2023/hash/64602b87c31db70a3ef060f6c5d5b01d-Abstract-Conference.html)
  处理不同成本/精度的 pull；我们的关键偏离是低保真 objective 可能完全不可观测且缺失有选择性。
- [Failure-Aware GP Optimization](https://proceedings.neurips.cc/paper_files/paper/2023/file/4ccf72339d1f650cb898c55dccbc5cda-Paper-Conference.pdf)
  已研究“成功时才看到 objective”；因此 novelty 不能只是加一个 failure classifier，而要落在 MLE-agent
  的时间到产物、真实 sibling 决策、run/task 泛化与固定预算策略上。
- [Bayesian Optimization With Censored Response Data](https://arxiv.org/abs/1310.1947) 与
  [Neural Model-based Optimization with Right-Censored Observations](https://arxiv.org/abs/2009.13828)
  说明删失反馈不是新概念；我们需要证明 artifact-time censoring 与 quality selection 的实证结构及其
  对 agent search 的实际后果。
- [RL for MLE Agents](https://openreview.net/forum?id=mfIbSouoaZ) 已指出 variable-duration updates 偏向
  快但次优动作。我们不微调/RL-finetune 底座，只学习轻量搜索控制器，并将偏差定位为评分通道选择性。
- [EET](https://aclanthology.org/2026.findings-acl.1652/) 与
  [Doomed from the Start](https://arxiv.org/abs/2607.06503) 已覆盖 agent early termination 和
  recall-controlled certification；我们应借用严格 certification protocol，不能把“会早停”本身当 novelty。

## 5. 分阶段门与停止规则

1. **可观测性机制审计**：已完成，BORDERLINE；任务内有强信号，但任务先验已几乎解释全部排序，
   跨任务不稳。关闭旧数据上的通用 propensity 开发。
2. **被动 watcher smoke**：已 **PASS**。2 cards × 3 checkpoints 共 6 records；1 个 stable artifact、
   0 个 racy copies、1 个 finite pristine grade；存活 checkpoint 最大定时偏差 0.000156 秒，worker、
   validator、Slurm job 均 rc=0。它只证明基础设施可用，两个 card 的 coverage/score 不作科学解释。
3. **旧发现集的一次性无阈值诊断**：Selective Feedback Racing 已完成，**BORDERLINE**。winner
   survival=0.9800，observed 排序相对 structured random +0.1413 且双聚类 CI>0；但淘汰 19.13% cards
   只对应 2.62% optimistic tail，restart ratio=1.0250。关闭统一 120 秒直接 race 和旧 100 sets 调参；
   下一步只问昂贵 silent 候选能否在更晚 checkpoint 转为可评分。
4. **新 discovery split**：只能使用机制冻结后新 physical runs；先冻结 run/task 分区，再开发模型。
5. **独立 validation/certification**：选择阈值与成本点后冻结；certification 只做一次并允许 abstain。
6. **论文 test**：现有至少 150-run 前瞻实验仍是评分通道机制的唯一确认集，不因方法开发而挪作训练。

任何阶段若被单 task 主导、run-level 推断不过、artifact/grader provenance 不完整或成本优势只来自
隐藏 grader/重启开销，立即降格或停止。
