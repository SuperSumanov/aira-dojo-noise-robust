## 0. 一句话摘要

你上周提出的两点——“self-report 不是免费的，它需要先执行候选”和“应该参考 NAS/MCTS predictor 的成本口径”——
改变了我们的问题定义。现在论文不再围绕“critic 能否在事后打败 self-report”展开，而是研究 MLE-agent 搜索中
**什么时候能获得可信评分、可信评分在同一候选上比 stdout self-report 多提供多少决策价值，以及把评分缺失计入后
是否真正改善搜索效用**。

目前最强的正向发现是：在同一 120 秒、共同产生可评分 artifact 的真实 sibling 候选上，pristine external score 的
tie-aware top-1 为 `0.9167`，stdout self-report 为 `0.7083`，差值 `+0.2083`。这仍是发现集上的机制候选，尚未写成
已确认结论。唯一主实验是机制冻结后至少 150 个新 physical runs 上的前瞻复现；当前正式累计 47/150，0814 又上传了
9 个 archive、声明上限 64 runs，正在按固定安全门入库。

与此同时，数据集贡献已经从“一批 run-clean pairs”增强为一个 **failure-censored source-opportunity resource**：我们能
恢复发布 pair 文件漏掉的 sibling 身份和真实执行状态，并确认缺失主要来自 execution failure，而不是任意漏标。

## 1. 新方向到底在测什么

### 1.1 `external submission score` 的定义

这里不是让 agent 自己汇报分数，也不是读取 workspace 内可能被修改的 evaluator。对每个候选，在固定 120 秒执行窗后：

1. 候选若生成 schema-valid `submission.csv`，由 workspace 外的 pristine evaluator 在固定隐藏 split 上评分；
2. agent 只产生候选，不能读取 evaluator 代码、隐藏标签或分数文件；
3. stdout self-report 是 agent/候选在运行过程中自行打印的估计；
4. 主比较只在同一 parent、同一执行窗、两种通道共同覆盖的候选上配对，避免换候选、换预算或换任务造成混杂。

因此它不是“另一个 critic”，而是对 **评分通道** 的识别：同一候选如果能得到可信外部分数，这个分数是否比 self-report
更能选出真实较优 sibling。

### 1.2 三个必须同时报告的 estimand

- `C(τ)`：候选在时间 `τ` 前产生 schema-valid、finite pristine score 的概率；
- `V(τ)`：在同一 parent、同一共同覆盖候选上，external score 相对 stdout 的 top-1 差；
- `U(τ)`：把 coverage、失败和 missingness 全部计入后，完整策略相对基线的效用差。

当前强正向证据集中在 `V(120)`；`C(120)` 明显具有选择性；现有 `U(120)` 尚未通过预注册方法门。因此现在可以主张
“可信评分值有条件决策价值”，不能主张“端到端搜索已经加速”。

## 3. 当前最重要的证据

### 3.1 Score channel：强正向机制候选，尚待前瞻确认

冻结发现集上的严格配对结果：

| 量 | 结果 | 解释边界 |
|---|---:|---|
| external top-1 | `0.9167` | 共同覆盖候选内 |
| stdout top-1 | `0.7083` | 同一候选、同一 120 秒 |
| external − stdout | `+0.2083` | 24 sets / 15 runs / 9 tasks；run-CI `[+0.0769,+0.3810]`，task-CI `[+0.0690,+0.4667]`，run sign `p=0.0625` |
| score cascade − presence cascade | `+0.1447` | run-CI `[+0.0717,+0.2241]`；task-CI `[+0.0541,+0.2510]` |
| presence cascade − stdout | `−0.0747` | 及时出现 artifact 本身不是质量的无偏代理 |
| naive utility − stdout | `+0.0700` | 未达到预注册 `+0.08` 与双聚类/sign 联合门 |

这组结果支持一个比“critic 普遍无效”更正面的主张：**external score 的数值确实携带稳定选择价值，但它并不总能及时
被观察到；只在成功候选内报告 predictor accuracy 会改变真实部署 estimand。**

### 3.2 Failure-censored source opportunity：已通过预注册与双实现复核

v11 的 3,252 个 parent 发布片段在结构上有效，但不是完整 source choice set。进一步 outcome-blind 恢复得到：

- source-incomplete parents：870；精确恢复 721，parent-equal recovery=`0.8287`；
- 恢复 missing sibling identities：996；
- 唯一绑定回真实 journal node：902，recovery=`0.9056`；collision=0，parent mismatch=0；
- 其中 `EXECUTION_ERROR`：893/902=`0.9900`；
- `OFFICIAL_GRADE_ABSENT`：9/902；
- 尚未恢复的 94 个目标保持 unknown，不按已恢复分布外推。

因此数据发布单位可以升级为：同一 source opportunity 下的 retained labeled candidates、missing generated identities、
execution/evaluation status 与 physical-run provenance。它直接解释了为什么只在成功候选中训练和评估 pair ranker 会遗漏
feasibility，并形成区别于普通 global-pair 数据集的 D&B 贡献。

### 3.3 标签噪声不是主要解释

修复旧 noise-ceiling 实现后，新的独立 attestation 使用 original grade 与第一份独立 regrade 两个单次测量，并用其余
regrade 做独立 gap 分层。3,017 个可比同任务 node pairs 上：

- raw ordering agreement=`0.9658601`；
- task-macro=`0.9801808`；
- task-cluster 95% CI=`[0.9438144,0.9913403]`；
- first repeat vs second repeat=`0.9891089`。

这不能被解释成所有任务共享同一 noise process，但足以说明当前 run-clean critic 与高可靠标签之间的主要差距不是由
随机重评分噪声造成。

### 3.4 执行可行性存在预测信号，但现有方法尚未改善 utility

failure-censored hurdle baseline 中，执行前 static scoreability 模型相对随机的 scoreability 增量为 `+0.120444`，
task-CI `[+0.059630,+0.160741]`。这证明“候选能否产生可评分 artifact”不是完全不可预测。

但是 `hurdle_tfidf` 相对 conditional-quality-only 的 frozen parent utility 增量为 `−0.001350`，task-CI
`[−0.015266,+0.017847]`。因此只能主张机制可预测，不能主张 hurdle critic 已经改善搜索。

## 4. 前瞻主实验：现在到了哪一步

### 4.1 冻结协议

- 至少 150 个机制 commit 后的新 physical runs；
- dominant task share 不超过 0.25；
- label vault 在 run gate 前保持关闭；
- gate 通过后，受信任 selector 每 run 按固定 SHA-256 顺序最多选 2 个 finite-sibling parents；
- replay manifest 不读取 label，只绑定盲化代码、parent/card identity、120 秒和固定 shard；
- 两个不 import producer 的 verifier 分别重建 parent selection 与 replay manifest；
- 得到真实 replay 数与 GPU·h 上界后，再由用户批准矩阵和预算，才允许提交 GPU。

当前基础设施远端完整测试为 335 passed。47-run registry 在一个刻意不存在的 intake root 前即 fail-closed，证明 gate 未过时
不会先打开 vault。

### 4.2 当前积累与补量计划

- 正式有效：47/150 physical runs，8 tasks，dominant=`8/47=0.1702`；
- 0814 新到：9 archives，文件名声明上限 64 runs；实际 physical 数必须等 credential-first intake 后确认；
- 上一批声明 52、实际 47，说明不能把文件名 seed 数直接当 run receipt；
- 建议 0814 后再生产一批 64 runs，固定为 8 tasks × 8 seeds，尽量使用不同任务并保持同一 producer 配置。

当前 47 加后两批共 128 个声明 runs；只要后两批 physical yield 达到 `103/128=0.8047` 就能跨过 150。上一批 yield 为
`47/52=0.9038`，因此再一批 64 比只补理论缺口更稳妥。停止条件只依据 outcome-blind physical-run metadata，不依据
score、label 或 effect size，不构成 optional stopping。

## 5. 与 critic 训练线的关系

你当前 Qwen3 1.7B/4B/8B 结果非常有用：旧 decision split 上 final accuracy 都在约 55% 左右，没有稳定的规模单调收益；
4B best=`58.79%`、final=`55.41%`，8B best=`56.64%`、final=`55.18%`。1:1 混入 value 数据后，Qwen3 final 均值从
`55.13%` 变为 `54.00%`。因此现阶段更适合把模型规模结果作为完整 predictor study，而不是继续用 frozen test 搜索模型。

当前唯一允许的支持实验是：复用在旧 validation 上事先锁定的 Qwen3-4B 和 8B checkpoint，对 v11 frozen b0/b1/b2
各评分一次。它不重训，也不在 frozen 上挑 checkpoint。为了执行，需要两条 checkpoint 的：

1. 绝对路径；
2. base model 与 `max_len/task_cond/budget_cond/head_frac` 等实际训练配置；
3. 在查看 v11 frozen 之前形成的 checkpoint selection receipt；
4. 若使用 Trainer raw checkpoint，明确 checkpoint step 与对应日志。

这些信息齐全后，我们可以把 4B/8B 防守性结果加入 suite；extension 单列，不与 frozen 混报。

## 6. 当前明确不能说什么

1. 不能说 score channel 已前瞻确认；当前 `+0.2083` 仍来自发现集。
2. 不能说系统已经端到端加速；coverage-complete utility 尚未过门。
3. 不能把 v11 pair 文件称为完整 source choice set；准确名称是带显式 missing registry 的 labeled sibling fragment。
4. 不能说 hurdle critic、Balanced Continuation 或扩大 Qwen 参数已经改善搜索；对应方法门均未通过。
5. 不能说 critic 普遍无效。正确结论是：不同 predictor/feedback channel 的成本、覆盖和 estimand 不同，必须分层比较。
6. 不能把 150-run gate 改小或把机制冻结前的旧数据并入前瞻 cohort。

## 7. 希望你配合的两件事

1. **再保留一批约 64 个同协议 runs。** 最好 8 tasks × 8 seeds；保持与 0813/0814 相同的 agent/model、搜索配置、
   时间预算和归档格式，并记录 aira-dojo commit、模型配置、seed 与 run creation time。
2. **提供事先锁定的 4B/8B checkpoint 收据。** 给出绝对路径、实际训练参数、checkpoint step 和锁定依据；我们只做
   v11 frozen b0/b1/b2 的一次性外部评分，不重训、不根据 frozen 结果换 checkpoint。

## 8. 当前判断

一周前的论文形态更接近“大规模搜索树数据集 + critic 负结果 + run-leakage 审计”。现在已经形成更正面的三层结构：

1. **已验证的数据贡献**：byte-exact、run-clean、gap/noise-aware、failure-censored source-opportunity resource；
2. **强机制候选**：同候选 trusted external score 相对 stdout 的 `+0.2083` 条件决策价值；
3. **待确认的 headline**：150-run 前瞻 score-channel replication。

真正缺少的不是再试一个模型，而是把第三层按冻结协议做完。如果前瞻效应复现，论文可以从“诚实的 predictor benchmark”
升级为“数据集使能的 execution-cliff / score-channel 机制发现”；如果不复现，前两层仍是可独立成立的 D&B 资产。
