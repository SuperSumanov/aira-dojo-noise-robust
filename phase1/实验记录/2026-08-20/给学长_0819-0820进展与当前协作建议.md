# 给学长：8 月 19—20 日进展与当前协作建议

日期：2026-08-20。本文只汇报已经有固定协议和可复核产物支撑的结论；预测托管、工程通过和支持门不会写成方法效果。

## 一句话结论

这两天最大的推进不是又找到一个事后看起来不错的 critic 数字，而是把论文的正面中心收敛成了更可信的
**MLE-agent Decision Corpus + Predictor Benchmark + Audit Protocol**。目前已经有三类硬正资产：真实 sibling
决策语料质量、critic 相对真实执行的成本优势、以及结果盲的时间外确认链。新的 predictor 效果仍未揭盲；正式确认
cohort 目前是 223/960 runs，尚不能报告 accuracy 或 search utility。

## 1. 当前唯一口径

- 论文容器仍是 NAS-Bench-style 的 MLE-agent 搜索树数据集与系统性 predictor study；不微调或 RL-finetune
  agent 底座。
- 旧 HCE、多保真、TD/RL、early-trace、Probe-First 和 score-channel 方法线均不自动恢复。
- 正式确认集固定为按 `(generation_started_at_utc, source_sha256, run_id)` 排序的 first-960 eligible physical
  runs，并要求独立的 accrual-closure receipt。first-240 只是 pilot，1,500 pairs 只是 cohort 内支持门，都不是提前
  揭盲的替代条件。
- 现有 label/outcome、0812 temporal vault 和 prospective scorer predictions 继续封存。当前
  `vault_open_allowed=false`。

## 2. 已验证的正面进展

### 2.1 前瞻 Decision Corpus 的结构质量

0818 语料完成安全摄取后，固定快照累计：

- 42 个不可变 transactions；249 physical runs，其中 223 个 eligible；
- 5,643 个 eligible endpoints、25 个任务、1,473 个 canonical sibling pairs；
- 222/223 runs 含 finite sibling decision，coverage=`0.9955156950672646`；
- 最大 pair-task share=`0.1887304820095044`，effective pair tasks=`11.095236634194983`；
- 5,631/5,643 endpoints 的 exact-code SHA 唯一；8 个重复组全部限制在同一 physical run 和同一任务，跨 run=0、
  跨任务=0。

浅层规范化审计进一步得到：

- tokenizer 覆盖 5,638/5,643；去注释、格式并归一化数字/字符串后，跨 run 和跨任务 clone 都是 0；
- Python 3.11 AST 覆盖 5,488/5,643；AST literal normalization 和更激进 skeleton 下，覆盖子集内跨 run/跨任务
  clone 仍都是 0。

这里需要保留一个负面限定：AST coverage=`0.9725323409533936 < 0.99`，所以预注册强门失败。我们只能说高覆盖
子集内没有浅层规范化 clone，不能声称全语料无语义重复。即便如此，它已经明显加强了“不是跨 run 复制、无决策
run 或单任务堆量”的 D&B 数据资产主张。

### 2.2 critic 的部署成本优势通过双跑验证

固定 v11 b0 的三类轻量 predictor（static-LR、static-GBM、char-TF-IDF-LR）完成 A/B 独立执行：

- A/B 各 3 models × 3 fits × 256 measured pairs，共 18 fits / 4,608 online queries；
- 真实候选 execution 的 ideal-parallel p50=`199.62654004304204` 秒；
- 三模型 A/B query p50 覆盖约 33—49 ms；
- execution/query-p50 比值覆盖 `4048.4579396764457`—`6037.084759488165`；
- 最坏 query p95 只占 execution p50 的 `0.05797248618597878%`；
- init p50 覆盖约 98.6—155.0 秒，六格 break-even 都是 1 pair；
- 0 warning、0 tie、antisymmetry=1，A/B 的输入 decision digest 一致，独立 verifier 全过。

因此，“critic 查询远便宜于真正执行候选”现在是测出来的系统正结果，不再是口头假设。它不等于准确率优势，也不
证明端到端搜索一定提分，但足以支撑 benchmark 为什么值得做。

### 2.3 时间外 prediction escrow 已形成

8 月 19 日完成了 0812 temporal blind 的 prediction escrow：805 endpoints / 57 runs / 9 tasks / 103 sibling
pairs，`static_lr` 和 `char_tfidf_lr` 全覆盖、无 tie；pre-cutoff endpoint ID 与 exact-code overlap 都为 0，独立
scorer 最大绝对差为 0.0，label vault content open=0。它目前只是可审计预测资产，不是效果结论。

8 月 20 日又完成 train-only 的四臂 WL/multi-view bundle：

1. `step_only_lr`；
2. `wl_graph_lr`；
3. `wl_graph_static_lr`；
4. `wl_graph_static_tfidf_lr`。

bundle 的独立 refit 最大数值差为 0.0；自动 activation receipt 时间为
`2026-08-20T05:20:27.656860Z`。当前 223 runs / 1,473 pairs 全部早于 activation，因此只记为
`outcome_unread_support_only`，strict post-activation pairs=0。后续只有 activation 后生成的新 runs 达到预注册的
1,500 pairs / 150 decision runs / 15 tasks / dominant≤0.25，才一次性比较完整多视图 arm 与既有 char-TF-IDF。

### 2.4 一个可写进 benchmark 的机制发现

score-channel 的“external score 排序显著优于 self-report”主张已被预注册实验否定，但 320/320 replay 留下了
清楚的 execution-cliff 结果：120 秒内 finite external score 只有 15/320，keyed stdout self-report 为 92/320，
两通道共同支持只剩 3 个 parents / 3 runs / 3 tasks。也就是说，external evaluator 在短时预算下的主要问题不是
已证明排序差，而是经常根本不可观测。这个 selective-observability/missingness 现象适合写成数据集诊断，不应再
包装成 evaluator 优越性。

## 3. 昨天定位并修复的训练语料问题

对 augmented train 数据的结果盲审计发现：原始结构有 11,946 train pairs / 1,574 test pairs，frozen-test runs
没有进入 train/dev；但 9,001 条 full-train pairs 中有 708 条跨
`(client, hardware, time_limit, execution_timeout)` 配置比较，占约 7.9%。根因与 builder 在 batch 内只按 task
组合、没有机器检查 exact experiment stratum 相符。

已经在学长当时的精确 base 上交付 future-only exact-stratum patch：在 shuffle/cap 前按 task+execution config
分层，写入 stratum/batch receipt，并在 concat 前独立验收。补丁的 Linux apply、py_compile 和 6 个 focused tests
均通过。旧 708 条不能过滤后追认为确认性结果；修复只服务后续新 cohort。

训练侧仍应同时保证：

1. `intask_split=="test"` 不进入训练期周期 eval；应从 train physical runs 内固定切 dev，checkpoint 固定后才
   一次性读 frozen test；
2. `eval_pair_accuracy` 的 checkpoint 选择应使用 `greater_is_better=true`，并保存选中 checkpoint SHA、step、seed
   与 one-shot test receipt。

## 4. 已正式关闭、不能再包装的方向

- **score-channel 排序优越性**：common support 过小，预注册状态为 `SCORE_CHANNEL_MECHANISM_KILL`；
- **Probe-First / prompt-only artifact contract**：正式实验无 coverage 净收益且 full validity 更差；
- **E2-A matched continuation**：支持门曾通过，但统一 1,200 秒 warm 仍有任务超时，边界不稳定，formal 关闭；
- **cross-client transfer**：共享支持不足，未启动效果实验；
- **广义 graph critic / pre-rollout value novelty**：Guided Evolution、I-MCTS、ML-Tool-Bench、CUARewardBench 等已
  覆盖相邻甚至部分直接问题，不能再写 first/only。

仍可守住的窄边界是：完整 Python MLE solution 的真实同-parent choice sets、physical-run-clean split、连续 hidden
score 的 gap/noise/missingness、query/init/execution 成本分账，以及 outcome-unread 的时间外确认。WL/AST 只能作为
benchmark baseline completeness，不作为算法 novelty。

## 5. 关于今天 `dojo-reproduce` 更新的对齐建议

我看到最新 `d44f4b0347154417ee5adc7a3b5b59ddd22ccb2c` 增加了 draft/improve decision-pair builder 和三份 LFS pair
文件。目前还没有新的 `docs/outcomes` 结果；最近一份 outcomes 文档仍是 8 月 17 日。

在把这批 pair 接入 canonical decision benchmark 前，建议先对齐两点：

1. `draft_pairs` 当前会把一个 experiment 中多个 physical runs 的 root children 合并到一个伪 parent 下。它可以作为
   单列 synthetic augmentation，但不是 journal 中真实发生的同-parent sibling decision，不能与 canonical sibling
   pairs 混报；最好显式写出两端 source run IDs 和 `pair_semantics=synthetic_cross_run_draft`。
2. 当前训练说明写“激活 Qwen3-8B”，但 launcher 实际未注释的命令是 Qwen3-1.7B。正式跑前应让文档、命令、输出
   目录和 seed receipt 一致，避免之后无法判断结果对应哪一臂。

这不是否定新的 augmentation 思路；它更适合回答“额外合成偏好数据能否提高 critic”，而我们的 canonical benchmark
回答“在 agent 真正面对的 sibling choice set 上预测是否有效”。两个 estimand 分开会更干净。
