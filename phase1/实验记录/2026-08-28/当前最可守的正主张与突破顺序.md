# 当前最可守的正主张与突破顺序

日期：2026-08-28

## 一句话主张

当前最可守的正主张不是“某个 critic 已经很强”，而是：**在真实 MLE-agent 搜索树中，pair graph、physical-run
provenance、task weighting 与 opportunity yield 共同决定 predictor accuracy 实际测量的 estimand；本项目把这套
决策语料、成本/噪声账本和结果盲时间前瞻审计做成可重建 benchmark。**

“第一次”在正式论文中仍需完成系统检索后再决定是否保留；现阶段应写成差异化组合，不写通用概念首创。

## 三层正资产

### A. 数据与 split 可信度（当前最硬）

- run-clean、parent-local、comparison-component 与 exact-config provenance；
- append-only、outcome-blind future intake 和独立 closure receipt；
- future 内部高相似链接严格 lineage-local；
- 固定 historical critic-train→future 未发现 identifier/literal-erased 高相似链接；
- 正在正式验证完整、可逐字节重建的 v11 release→future population expansion。

这层是 NeurIPS D&B 的核心正资产。它不依赖 predictor 是否最终超过强基线。

### B. benchmark measurement insight（已有真实正现象）

- 同一 endpoint score 在真实 sibling graph 与 matched cross-run graph 上发生 predictor-family 排序反转；
- run-level coverage 变均衡不推出 pair-micro 权重变均衡；
- task→pair opportunity yield 会改变隐式任务权重，因此 pair-micro、task-macro、parent/run-macro 不是同一 estimand；
- 统一 estimand panel、task bootstrap/LOTO、exact common support 与撤回链已机器冻结。

相关工作的通用“pair distribution matters”不能冒充我方首创；可守的是完整 Python MLE solution distribution 上的真实
search-induced instance、影响量级、版本轨迹与发布协议。

### C. predictor 容量信号（最可能成为方法侧正结果，但尚未确认）

学长的 experiment-level 0.6B→8B value scaling 是当前最强探索性方法信号；旧实验的 cross-config mixing、shared
endpoints、outer-test 周期观察与非正常停止使其不能升级为确认。唯一合法确认仍是：真实 producer 在 outcome 前写入
config-v2 sidecar，train-run-disjoint dev 选 checkpoint，再对全新 immutable frozen cohort 一次揭盲。

最新防撞检索同时确认：BigCodeReward、Themis-CodeRewardBench、Similar/SRM、SWE-TRACE 与 CodeScaler 已分别覆盖
真实代码偏好、多维代码 RM、agent step-wise RM、PRM 搜索剪枝和 execution-free code critic。故 C 层即使确认，也只能
主张“真实 MLE search distribution 上、严格 run/config/time transport 下的容量规律”，不能主张通用 code/agent RM
或 critic-guided search 首创。这个收紧反而让 A+B 的 D&B 定位更清楚。

更直接的 ML-Agent、Frontis-MA1/OpenMLE 与 mle-traj-v1/v3 又分别覆盖了 10k execution-grounded MLE 轨迹上的
step-wise actor learning、26,259 条公开 MLE SFT traces 与 operator+evolution，以及约 15k 逐版本 human/agent 节点和
forest view。因此连“首个/最大 MLE trajectory dataset”也必须关闭。mle-traj 的 canonical agent tables 虽线性化为
189 branches，但 gated raw layout 同时列出 `tree_summary.json`，未审计前不能声称它无法恢复 siblings。当前真正
可守的是我方**已物化的 provenance-bound sibling-fragment benchmark**：canonical 表不线性化真实 search branch，
在同一 parent 的完整 Python 候选程序上公平比较独立 critics，并把 run/config/time、outcome-blind closure、
成本/噪声/pair weighting 做成机器契约；“首个/唯一 true-sibling”保持关闭。

## 突破优先级

1. **完成 full-release temporal certificate**：补“只覆盖 critic-train subset”的证书缺口；CPU-only、当前正在运行。
2. **等待 v3 first-successor structural audit**：只接受公开 protocol 后自动捕获的最早 successor，不挑 snapshot。
3. **推动 config-v2 producer 真部署**：这是 clean scaling confirmation 的唯一当前阻塞，不允许事后回填旧 archive。
4. **first-960+closure 后一次性揭盲**：严格按统一 estimand panel报告全部 predictor、成本、coverage 与 noise，不按 1,500
   pairs 提前停。
5. **方法扩展只作第二层**：COTA/Guided Evolution 已覆盖一般 comparator→runtime gate；除非能给出 MLE-specific、
   可学习且在固定预算端到端 utility 上确认的机制，否则不把工程 selector 当主创新。

## 明确不做的叙事替换

- 不把 split certificate 写成 semantic/pretraining decontamination；
- 不把结构门通过写成 predictor effect；
- 不把学长探索性 scaling 写成我方确认结果；
- 不用旧 HCE、多保真、Probe、score-channel 或 K≥1 lookahead 填补等待期；
- 不因新文档标题较新就覆盖 `CURRENT_DIRECTION.md` 顶部的撤回链。
