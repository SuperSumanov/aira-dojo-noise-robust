# 实验详解：逐步走读（动机 → 怎么做 → 结果 → 读出什么）

日期：2026-07-12 ｜ 配套 `论文初稿_v2_穷算力杠杆.md` / `给导师汇报_20260712.md`
用途：**明天自学用**。按时间+逻辑顺序把每个实验讲透，重点是**每一步为什么承接上一步**（这条推理链才是精华）。

---

## 全局逻辑链（一段话先建立地图）

> 穷算力下 MLE 搜索的成本主要在**评估**。先问评估到底有多噪（**T0**）→ 确认噪声真实且任务相关 → 问"清洁评估是不是杠杆、换个选择规则能不能省"（**T1**）→ 发现**清洁评估是大杠杆、但选择统计量不是** → 于是换思路：能不能用一个**廉价 critic** 便宜地预测分数来省评估？先证明它**能预测且独立于自报分**（**H1**）→ 但"能预测"不等于"有用"，测它能不能**省评估**（**rank≠regret**）→ 不能 → 换角度测它能不能**查自报分失效**（**rescue**）→ 配对上有限成立 → 想把这个"查失效"用起来（扩数据 **②** 撞算力墙；在线 veto **③** 真实树上不显著）→ 都不成立 → 回主线的另一半：**多保真**能不能省评估（**④ headroom**）→ 只在穷算力搜不起的任务上有空间。**两条线收敛：清洁评估是唯一杠杆，廉价 critic 和多保真在能搜得起的规模上都不划算。**

一条方法纪律贯穿始终：**贵的在线实验之前，先用便宜的离线探针证伪**（省下了 4 个错误的大建设）。

---

## T0 — 预实验：评估到底有多噪？（go/no-go 裁决器）

**动机**：项目开局有两条候选线——主线（评估一致性：评估噪声伤搜索吗？）和扩展线（RL：父→子价值能不能池化回传）。T0 是**同一个裁决器**，用真实数据决定哪条线有据。

**怎么做**：aira-dojo + DeepSeek 在 spaceship-titanic 上跑 9 个 seed 的 AIRA_MCTS（185 节点，71 个 working）。用**外部 pristine 真分**算两件事：① 候选**自报验证分** ↔ **外部真分** 的 R²（主线证据）；② working 节点里**父→子真分**的结构（RL 线证据）。

**结果**：
- 主线：自报↔真分 **R²=0.14**（r=0.37, n=71, p≈0.002）→ 自报分只解释真值 14% 方差 = **评估确实噪/不一致**，统计稳。
- 第二任务 nomad：**R²=0.72**（n=6）→ 和 spaceship **反向**！
- RL 线：父→子 R²=0.92 是**单个杠杆点撑起来的假高**（去掉后带内 R²≈0.3），nomad 上连 scored 父子边都凑不出（n=0）。

**读出什么 / 下一步**：① **评估噪声真实，但任务相关**——咬在"易灌水"的指标上（spaceship 的 accuracy），不咬"更诚实"的（nomad 的 RMSLE+5折CV）。② RL 线两任务都没稳健可池化结构 → **按 gate 搁置**。③ 主线进 T1。**教训：报数一律用 robust 版，别被 0.92 这种单点虚高骗。**

## T1 — 清洁评估是不是杠杆？换选择规则能不能救？

**动机**：T0 说评估有噪。那么两个自然问题：(a) 把评估做**清洁完整**能不能明显改善部署解？(b) 在带噪的廉价评估上，换个**更稳健的选择统计量**（平均 / 方差惩罚）能不能不花清洁评估的钱就把噪声压下去？

**怎么做**：三臂 HCE harness，**只变评估/选择协议**：`full`（清洁完整）/ `naive`（单次 10% 数据 proxy）/ `consistency`（方差惩罚：均值−λ·std）。greedy + DeepSeek，spaceship+nomad，**5 seed/臂**。指标 = 部署解的 held-out 真值 `sel_dval` + regret（vs 树内 oracle）+ gap（proxy − 真）。

**结果**（spaceship）：

| 臂 | sel_dval | regret | gap |
|---|---|---|---|
| **full** | **0.803** | **0.009** | +0.018 |
| naive | 0.784 | 0.030 | +0.077 |
| mean(λ=0) | 0.780 | 0.032 | +0.050 |
| consistency | 0.787 | 0.025 | −0.007 |

**读出什么 / 下一步**：① **清洁完整评估是大杠杆**（0.803 ≫ 各 proxy ~0.785，regret 只 1/3）。② **换选择统计量救不了**：naive≈mean≈consistency 全在 0.78–0.79 噪声带内——方差惩罚的**机制**确实把乐观 fluke 杀了（gap +0.077→−0.007），**但净真值增益≈0**。→ **杠杆在保真度，不在怎么选**（印证 aira-dojo"选择不重要"，点名例外=评估质量）。③ 主线卖点从"方差感知选择"改为"**多保真 + 固定预算分配 BAI**"（后来的 ④）。**教训：小 n 别下结论**——离线扫和 n=2 曾把 λ=0 高估到 0.80，5 seed 跑满才落回 0.780。

## H1 — 一个廉价 critic 能预测分数、且独立于自报分吗？

**动机**：既然清洁评估贵、又是唯一杠杆，能不能用一个**几乎免费**的东西**预测**那个贵分数，从而少跑几次完整评估？最便宜的候选 = **冻结** LLM 的隐层特征喂给一个线性 probe（不执行候选代码）。但要有用，它必须携带**超出候选自己那个免费自报分**的信息——否则不如直接用自报分。

**怎么做**：把真实搜索节点做成 **289 张 card**（task/code/廉价观测/lineage + 隐藏真分；view/hidden 防标签泄漏），3 任务。比 6 个预测器（2 个 label-free 基线 + probe/scalar/reasoning/zeroshot）。**关键手段 = 自报分设障（ablation）**：mask 掉 `val_at_low`/`val_curve`/`parent_val`，看谁还活着——活着 = 真从**代码本身**读到了信号。

**结果**（Spearman，3 seed×3 任务）：

| 条件 | 自报分基线 | probe | scalar |
|---|---|---|---|
| intra 正常 | +0.619 | +0.381 | +0.060 |
| **intra 设障** | **0.000** | **+0.356** | −0.023 |
| loto 设障 | 0.000 | **+0.179** | −0.015 |

**读出什么 / 下一步**：设障后**基线归零、probe 几乎不掉**（intra 0.381→0.356；跨任务 0.103→0.179 还**升**了）→ **probe 携带独立于自报分的真分信号，H1 成立且 robust**。（QLoRA scalar 在这点数据量下弱到负，H1 全靠**冻结 probe**。）→ 接着问：这份"能预测"到底**有没有用**。

## H2 — 让 critic「先推理再打分」会更好吗？

**动机**：probe 是纯特征读出。一个自然假设：让 critic 先生成一段自然语言分析、**再**给分（reasoning-first，蒸馏自更强 teacher）会不会更准？

**怎么做**：7B QLoRA SFT 的 reasoning critic，teacher 用 14B。**（中途逮到并修了一个隐蔽 bug：** prompt 里 code 放在指令块**前面**，长度截断把"先分析再打分"的指令挤掉了 → 模型直接**续写代码**、parser 抓了个随机数 → reasoning critic 整整一个阶段**根本没真跑**，光看指标发现不了，只有 dump 原始生成才看出来。）

**结果**（intra Spearman，code[:1200] 对齐）：

| 任务 | scalar | reasoning(14B teacher) |
|---|---|---|
| spaceship | +0.058 | **+0.310** |
| nomad | +0.143 | −0.444 |
| tps-may | −0.396 | −0.304 |
| **均值** | **−0.065** | −0.146 |

**读出什么 / 下一步**：reasoning-first **整体不如 scalar 头**。但 **teacher 质量是真的隐藏变量**（7B→14B teacher 让 spaceship 从 −0.01 翻到 +0.31）——所以"弱 teacher 得出 reasoning 不行"是无效结论；用了 14B 才敢下"不划算"。**两个坑（截断 bug + code 长度混淆）都写进论文当方法论教训**（code 截短会把 probe 设障分从 +0.41 压到 +0.02——一个臂的混淆会悄悄推翻另一个臂的结论）。

## rank ≠ regret — probe 能预测，那能不能省评估？

**动机**：H1 证明 probe「能排序」。但**能排序 ≠ 能省评估**（NAS 里的经典教训）。直接测：固定预算下用 probe 选候选，比"免费自报分"和"随机"选得好吗？

**怎么做**：`budget_probe.py` 离线 best-of-K 模拟（**不烧 DeepSeek**）：固定预算 K，用 critic(probe) / proxy(自报分) / random 各选出解，比真 grade。`regret(K)=oracle−best-recovered`。

**结果**（K=3）：

| | probe | proxy(自报分) | random |
|---|---|---|---|
| intra tps-may（分数离散） | 0.215 | **0.000** | 0.171 |
| loto tps-may | 0.292 | **0.000** | 0.227 |

**读出什么 / 下一步**：唯一有区分空间的任务（tps）上，**免费自报分 proxy 完美（regret 0），probe ≈ random**（跨任务还**差过** random）。top-heavy 任务上谁选都行。→ **没有任何情形 probe 是对的选择器**，+0.4 的 rank 换不成省评估。**rank≠regret 应验。** → 那 probe 到底有没有用？换角度。

---

## rescue — probe 的价值是不是在「自报分出错的地方」？

**动机**：选择失败是因为**自报分在它对的地方已经够好**了。H1 的价值是**独立性**——那价值应该出现在**自报分错的地方**。换个测法。

**怎么做**：`probe_rescue.py`。在**自报分排错**的候选对上（构造上 0% 对，random 50%）看 probe 的补救率；用 5 折 CV probe（防泄漏）。

**结果**：

| 任务 | wrong-pairs | probe@wrong | probe@right |
|---|---|---|---|
| **spaceship** | 8382 | **0.59** | 0.71 |
| nomad | 204 | 0.55 | 0.68 |
| tps-may | 90 | 0.28 | 0.60 |

**读出什么 / 下一步**：大样本 spaceship 上 probe 在自报分 0% 的地方仍 **0.59** → **真实、可信的独立信号 = 自报分失效/reward-hacking 检测器**（不是选择器）。**有限**：部分独立（0.59<0.71）、不普适（tps probe 本身弱）。→ 想把这个"查失效"用起来：**普适吗（②）？在线有用吗（③）？**

## ② 扩数据（撞算力墙，弃）

**动机**：rescue 几乎全靠 spaceship 撑。要坐实"普适"，得在**没见过的新任务**上验 probe@wrong。

**怎么做**：先盘存量（84 个 journal 全在老三样，无白捡）→ 发现 s3e18 / tps_dec 的配置早建好、从没跑过 → 对两个新任务冒烟。

**结果**：**s3e18 数据没下载**，`mlebench prepare` 撞 Kaggle **403（竞赛永久关闭、无 Join 入口）**→ 拿不到。**tps_dec 能跑但太大**：train.csv **360 万行**，单候选训练 **1–3 小时**，4 个采集作业 6 小时全卡在第 1 步、近 0 卡 → scancel。

**读出什么 / 下一步**：**穷算力硬碰撞**——可用的"新任务"恰好都太大或关闭。**这本身是诚实发现**（廉价采集新 MLE 任务卡撞穷算力预算），写进论文当边界。→ 放弃扩数据，转在线验证。**教训：冒烟 step5 会漏掉规模化的慢；要看 `Execution time` 和 `wc -l train.csv`。**

---

## ③ 在线 veto（rescue 有没有部署收益？——本轮重头戏，负结果）

**动机**：rescue 是离线诊断。真正的问题：把 probe 接进搜索当**否决器**（自报分高但 probe 不信任的节点，别部署它），能不能真的选出更好的解？这正是 v1 论文写的 future-work，且 v1 自己警告"rank≠regret 说在线收益不保证、必须测"。

**怎么做（三步收紧，全离线、便宜）**：
1. **③a 随机池**（`veto_sim.py`）：随机候选池里比 baseline(发自报分最高) vs veto。
2. **③a′ 真实树**（`veto_realtrees.py`）：候选池换成**18 个真实 spaceship 搜索 run**（靠 improve 血缘相关），probe 用**叶一-run-留出**（杜绝同 run 泄漏）。
3. **bootstrap 显著性**：对 18 run 重采样，固定 λ=1，给 Δregret 的 95% CI。

**结果**：
- ③a 随机池：veto/blend **大赢**，Δregret 到 **+0.18**（K=20）。
- ③a′ 真实树：**hard veto 是 wash**（Δregret −0.001，3赢4输11平）；soft blend 只 **+0.007**（regret 0.104→0.095）。
- bootstrap：**95% CI [−0.003, +0.018]（含 0），P(Δ>0)=0.90 → 不显著**。

**读出什么 / 下一步**：随机池的大赢是**"候选相互独立"的假象**（随机池爱拼进"自报高真分低"的节点给 veto 补救空间）；**真实树候选靠 improve 收敛、自报分选出的部署解本就好**（11/18 平手）。→ **rescue 无稳健部署收益，rank≠regret 从 best-of-K 延伸到在线 veto。③b 真在线不做**（小又不显著几乎不可能在线活）。→ critic 支线到此收束，回主线的另一半。**这一步的价值：几分钟离线探针挡住了一个"要改 aira eval 层 + CPU-torch 集成"的大工程。**

## ④ 多保真 headroom（多保真能省评估吗？——负结果）

**动机**：主线另一半（T1 指向的）。既然杠杆在保真度，那用**廉价低保真筛、晋级 top 到完整评估**（Hyperband 式）能不能在固定预算下逼近 full？建整套机器前，先问：**它在我们任务上到底有没有 headroom（天花板）？**

**怎么做**：`mf_headroom.py`，**纯 numpy 秒级、零 GPU**。用现有卡的自报分+真分，固定预算 B：single(全评 B 个随机)、mf(自报分筛→晋级 top-B)、oracle(池 max)。**真实树池 + 随机池都算**（吸取 ③ 教训）。headroom = mf − single。

**结果**：

| 任务 | B=3 headroom | B=10 | single vs oracle |
|---|---|---|---|
| spaceship | +0.015 | −0.000 | 0.954 vs 0.981 |
| nomad | 0.000 | — | 1.000 vs 1.000 |
| tps-may | **+0.044** | — | 0.783 vs 0.829 |

**读出什么 / 下一步**：**affordable 任务没 headroom**——spaceship 单保真已近 oracle（0.95→0.98），nomad 太易。**唯一有真 headroom 的是 tps（+0.044，离散分数）**——但 tps 家族正是**穷算力搜不起的**（② 已证 360 万行）。→ **有 headroom 的搜不起，搜得起的没 headroom。多保真选择在 affordable 区不是杠杆。** → ④ 收在这个特征化结论。

## 收敛（把所有步串成一句）

- **critic 线**（H1 有信号 → rank≠regret / rescue / 在线 veto 都不转化为省）和**多保真线**（④ 无 headroom）**方法上无关，却以同样方式失败**：都有真信号，都在能负担的规模上换不成搜索收益。
- 唯一真推动部署解的是 **评估质量**（T0/T1），且payoff 在**保真度/一致性**、不在选择统计量。
- → **锐化 aira-dojo 负结论**（不止 policy，整个"搜索侧廉价干预"家族都不划算）+ **把机制钉在评估噪声**（AIRA_2）：便宜绕不过噪声，只能花钱买清洁评估。
- **方法论主线**：离线证伪先于在线投入——4 次便宜探针（best-of-K / 真实树 vs 随机池 veto / bootstrap / 多保真 headroom）在动工前杀掉 4 个错误建设。

## 明天自学的抓手（3 个最该记住的点）

1. **rank ≠ regret**：能排序不等于能省评估——本项目在 3 个框架（best-of-K、wrong-pair、在线 veto）上反复验证。
2. **随机池 vs 真实树**：③ 里同一个方法，随机池 +0.18、真实树不显著——**候选相关性**会造出假的"有用"，必须在真实结构上验。
3. **离线证伪先于在线**：每个"看着正"的结果先用秒级离线探针捅一刀，省下的都是几天的大工程。
