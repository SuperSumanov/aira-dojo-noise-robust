## 线程 H1 — 冻结 code-LLM 的表征探测（证据最硬，导师的"表征探测"重构有充分文献支撑）

### 可落地改进（单卡、不微调底座,大概率抬高 +0.36）
1. **探针类别做消融**（现在是单层 ridge）：
   - **多层 stacking**：跨层集成线性探针 >> 最优单层（+12.7% 均值,个别任务 +29%/+78% AUROC;learned logistic stacking over k=3–5 层）——`arXiv:2604.13386`。
   - **attention probe**（可学 query 对逐 token 隐状态 softmax 加权 → 线性头）> mean-pool 线性,最多 **+23.1 ROC-AUC**(3 QA 数据集×5 个 <9B 模型)——`arXiv:2606.21917`;AutoProbe 同思路、model-agnostic、6 个 code LLM——`arXiv:2510.02934`。
   - **小 MLP**(2 隐层 128/64,末 token)——OPENIA `arXiv:2501.12934`。
   - → **建议:linear ridge(现) vs 多层 stacking vs attention-probe vs 小 MLP,同一表征上对比**。这既抬性能又是干净的 H1(b) 消融。
2. **选层**:别默认末层。信号**分布在深度上、中层最富**;扫 `{1, L/4, L/2, 3L/4, L}`——`arXiv:2606.21917 / 2502.02013 / 2510.02934 / 2501.12934`。对 Qwen2.5-Coder-7B 很可能中层 Spearman 更高。
3. **confound 控制(最重要,直接回应导师"要严格")**:把每维隐状态**对 code 长度/复杂度/表面特征做残差化**,证明 grade 信号在残差后仍在。模板:对 prompt 长度残差化后探针仍 **AUC 0.940 vs 长度-baseline 0.720**——`arXiv:2606.14530`。**必须做**,因为有反例警告:线性探针近满分可能**纯是表面/格式 confound 假象**(残差化后 100%→33.5% 随机)——`arXiv:2606.02907`;"高线性探针精度本身不是内部编码的充分证据"。

### 最接近的前作 + 我们的可辩护差异(novelty)
- **OPENIA `arXiv:2501.12934`** / **AutoProbe `arXiv:2510.02934`** / **对比方向 code ranking `arXiv:2512.07404`(用的正是 Qwen2.5-Coder-7B-Instruct!)** / **ELHSR-SWIFT `arXiv:2505.12225`(线性层打败 7B 文本 RM,<0.005% 参数)**——都证明"冻结(code-)LLM 隐状态(近)线性编码质量/正确性"。
- **它们全做"单个代码单元 vs 自己测试的二元正确性"**;**我们 H1 做的是"连续的、下游最终 TASK grade"(ridge/Spearman)+ 独立于自报分的设障** —— **没有前作做后者**。→ **这就是可辩护的 novelty,写论文必须显式引用它们并划清界限**(否则被当增量)。
- **一个必须小心的坑(被验证否掉的声明)**:`2606.14530` 那种"**prompt 生成前**探 prompt 末隐状态预测代码对错(AUC 0.955)"**不是** H1——H1 探的是**已写出的候选解**。别把两者混为"更强证据"(workflow 3-0 否了这个混淆)。

### 警告
- 不做 confound 残差化,H1 会被 reviewer 一句"这是不是在读代码长度"打穿(`2606.02907` 就是这个 attack)。**残差化 + 报"残差后仍显著"是 H1 能不能立住的关键。**

## 线程 H2 — rationale/推理蒸馏 + 特权信息(导师的想法有名字,也有明确的坑)

> 本线声明多在 unverified(撞上限),源可靠、结论待复核。

### 导师"给 teacher 真值再蒸馏"= 有名字的方法,但**是记录在案的坑**
- **泄漏**:用"带答案/特权信息的轨迹"当唯一学习信号 → **系统性泄漏 + 长训不稳**——RLSD `arXiv:2604.03128`(标题直译"自蒸馏 RLVR:特权信息泄漏及其防治",**正对导师这个想法**)。
- **train/test 失配(最根本)**:PI 蒸馏的核心难题 = "带 PI 训"的能力要迁移到"测试时无 PI"的策略;学生**从输入本身复现不了 answer-conditioned 的推理**——`arXiv:2602.04942`。**这正是我上次给你点的第 2 个坑,文献坐实了。**
- **做对的方法**:**pi-Distill / PI-bridging**(`arXiv:2602.04942`)——专门设计来弥合"训练有 PI、推理无 PI"的鸿沟,报告能超过 CoT-监督蒸馏。→ **要做就用它,别用朴素"teacher 看答案→蒸 rationale"。**

### reasoning 到底能不能超线性读出?——文献说"只在难例上"
- **Fast-Slow Thinking RM `arXiv:2603.20212`**:标量 RM **在易例上碾压**,生成式 CoT critic **只在难例上赢**——两者互补。
- → **含义**:reasoning 不会全局超过 probe;顶多在**难子集**(probe/自报分都拿不准的地方)多榨一点。**把 H2 重构成"显式推理能不能榨出线性 probe 榨不到的信号——只在难例上?"→ 直接和 H1 统一**(线性解码 vs 推理抽取),而且设了诚实预期。
- 经典参照:distilling step-by-step `arXiv:2305.02301`;TRACT(regression-aware CoT for LLM-judge,Google Research)——回归/打分场景的 CoT 蒸馏。

### 警告
- **rank≠regret 天花板仍在**:H2 就算预测更准,也不买搜索收益。H2 的价值是**科学问题**(推理 vs 线性能多抽多少),不是系统赢点。别把它包装成"更好的 critic 能省评估"。

## 线程 rescue — 代理失效/reward-hacking 检测(框架有,但"检测≠收益"要认)

> 本线具体声明多在 unverified,框架源可靠。

- **canonical 框架**:reward model 过优化 / Goodhart —— **Gao et al. "Scaling Laws for Reward Model Overoptimization" `arXiv:2210.10760`**:proxy 与 gold 的差距随对 proxy 的优化**可预测地增大**。**rescue = 检测这个 proxy↔真值背离**,自报分就是那个 proxy。这是 rescue 该挂的理论框架。
- **"probe 恰在自报分错处才对" = 互补信号/分歧检测(disagreement-based detection)**的一个实例;把它定位成 **reward-hacking / 验证过拟合检测器**(接 full_locked 主线),不是选择器。
- **诚实**:rank≠regret + 在线 veto 不显著,已证"检测**不**自动转成搜索/部署收益"。→ **rescue 的可辩护贡献 = 一个检测器**(诊断 reward-hacking/自报分虚高),别再往"用它选更好"上靠。

### 数据
- **leaf-classification 确在 MLE-bench Lite(22 个低复杂度任务)**里——aira-dojo `arXiv:2507.02554` 明确点名它 + detecting-insults 等小任务。→ 可作便宜的采卡扩任务候选(仍需 Kaggle 接受规则 + 采卡算力,小任务可行)。

## 综合:一句话方向 + 优先级 do-list

**导师把论文往"表征探测科学 + 失效检测"收,文献强烈支持这个重构。** 三条线统一到"**冻结 code-LLM 对解质量编码了什么、线性能解多少、推理能否在难例上多解一点、这信号在自报分失效处最有用**"。

**优先级(便宜高价值在前):**
1. **【最该做,单卡零微调】H1 三件套消融**:探针类别(ridge/stacking/attention/MLP)× 选层扫 × **confound 残差化**。既抬 +0.36、又把 H1 变成 reviewer 打不穿的严格表征探测结论,**同时就是导师要的重构落地**。
2. **【零算力】H1 叙事改写**成表征探测框架 + 显式引用 OPENIA/AutoProbe/2512.07404 划清"连续 grade + 自报分独立"的 novelty 界限。
3. **【中等】H2**:若做,用 **pi-Distill 式 PI-bridging**(不是朴素给真值)+ 防语义泄漏 + 定位成"推理只在难例上超线性";**明确它不改 rank≠regret 结论**。
4. **【中等】rescue**:挂 Goodhart/过优化框架,定位成检测器;`leaf-classification` 等扩任务加强泛化。
