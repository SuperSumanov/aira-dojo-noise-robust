# 立题备忘：AIRA_2 的隐藏验证集会不会被搜索"自适应刷穿"，以及能否检测

日期：2026-07-17

## 一句话

AIRA_2 用一个**固定的隐藏 D_search** 引导搜索，解决了"信 agent 自报分"的评估噪声问题。但**搜索几千步反复查询同一个 D_search，本身就是一串自适应查询——它会不会把 D_search 统计性地"刷穿"（自适应过拟合），尤其在算力/步数放大之后？这种残差 reward-hacking 能不能从解的表征/轨迹里检测、预测、乃至缓解？** AIRA_2 原文明确没测这个、还留了 hedge。

## 为什么这是个真问题（非冗余，引 AIRA_2 原文）

前期一系列便宜实验反复落到负/冗余，因为这个问题空间被"评估质量"支配：
- **选择**：免费自报分已是强 selector（rank≠regret，结构性封顶）；
- **检测"自报分灌水"**：**AIRA_2 的隐藏 val 一劳永逸解决了**（不信自报分、改用外部一致评分引导）。

核实 AIRA_2（arXiv:2603.26499）原文后，发现它给一个**更深的问题留了门**：
1. **HCE 只修了评估噪声**：三层 D_train / D_search（固定、标签隐藏、orchestrator 每步外部评分）/ D_val（仅最终选择）。它把之前的"过拟合"归为**噪声、不是真记忆**。
2. **残差 gap 仍在**：HCE 之后 D_search（看过）vs D_val（没看过）仍有 **~4 个百分位点**，被称"marginal"、且**未机理性解释**。
3. **他们自己 hedge（原话）**：“This is not to say that true overfitting will not be a problem in the future as agents are given more compute.”——**这个"更多算力"的 regime 他们没测。**
4. **最关键**：AIRA_2 **完全没测/量化"固定 D_search 被几千次反复查询是否被自适应过拟合"**。藏标签防的是 *agent 直接作弊*；但**搜索的选择压力本身就是一串自适应查询**——经典 adaptive data analysis（Dwork 等）：反复查一个 holdout，即使看不到标签，也会把它刷穿。**这一块 AIRA_2 没碰。**

→ **靶子正好落在 AIRA_2 明说没测、还 flag 了的空白上，并扎根于真实理论。**

## 核心假设

放大的搜索（更多步 / 更多算力 / 更激进探索）下，搜索会把固定的 D_search 自适应过拟合 → **D_search 分与真 test 的 gap 随规模增长而扩大** → 这是 AIRA_2 方案没解决的残差 reward-hacking，且可从解的表征/搜索轨迹检测、预测、缓解。

## 怎么测（正好要 16–24 卡）

1. **分层数据**：D_train / D_search（引导）/ D_val（选择）/ **D_test（谁都不碰，只用来揭露过拟合）**——比 AIRA_2 多留一层干净 test。
2. **扫规模/步数**：用 16–24 卡跑不同规模、不同步数的搜索（AIRA_2 flag 的 regime），画 **D_search-vs-D_test gap 随规模的增长曲线**（AIRA_2 只在他们的单一规模测、且只有 D_search-vs-D_val）。
3. **检测/预测/缓解**：若 gap 随规模长出来，试从解的表征/轨迹**预测"这一步在刷穿 D_search"**，并试缓解（何时该轮换 D_search、或对可疑步惩罚）。

## 为什么现在能做（放开约束的正当理由）

- **AIRA_2 本身就是异步多 GPU**——放开"单卡"不是投降，是**对齐领域真实 setup**；
- "更多算力 → 过拟合"正是 AIRA_2 flag 但没测的 regime，**16–24 卡正好用来探它**；
- 检测器需要训模型时也允许（放开"绝不微调"后）。

## 诚实的风险（不吹）

- AIRA_2 那个残差 gap 是**小的、还随时间收窄**（24h ~4 点 → 72h <4 点）——**他们的数据其实倾向"没事"**。我们赌它**在更大 scale / 更激进搜索下冒头**，而这正是他们没测的。
- 即便冒不出来：**"在 scale 上证实 AIRA_2 的 hedge、adaptive 过拟合确实 marginal"也是个干净、有用的结果**（在 scale 上验证 SOTA）；冒出来 + 能检测/缓解 → 分量更足。
- 检测/预测/缓解是进一步的赌。

## 差异化（vs 相邻工作）

vs 工具调用作弊（2605.02964）/ 评估完整性 benchmark（2603.11337）/ benchmark 审计（2605.12673）：我们打的是 **ML-agent 搜索对适应度集 D_search 的统计性自适应过拟合**，角度分开，且**直接对话 AIRA_2**。

## 要一起定的

1. **值不值得押**——我判断：这是目前唯一**非冗余、能对话 SOTA、又用得上那 16–24 卡**的正面靶子；
2. **放开约束**（多 GPU + 允许训模型）+ 16–24 卡能否到位；
3. 定了就动手：**搭分层数据管线 + 小 pilot 先测"gap 随步数增不增"**（便宜先证伪，再决定烧大卡）。
