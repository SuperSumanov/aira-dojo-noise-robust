# 汇报：冻结 code-LLM「知道」解的好坏,却「用不上」——穷算力下的表征探测与失效检测

日期：2026-07-16 ｜ 对应论文 `论文_v3_decodable_not_usable.md`（+ 投稿格式 `paper.tex` + 6 图）｜ 承接 07-12 汇报

> 自上次汇报后,按您上次的建议把故事**从"一个杠杆两个非杠杆"的大而全,收拢成一条更锐的主线**:critic 这条线深化成一篇完整的 **"decodable ≠ usable"**——并新增了两块决定性证据(**跨模型家族复现** + **因果 steering 负结果**),现已写成论文 + 投稿格式。

## 一、背景

自动化 LLM「ML 工程 agent」解 Kaggle 式任务 = 生成候选代码 → 跑 → 在结果上搜索。**主导成本是「评估」**（每个候选一次完整训练+打分）。两篇前作定靶:**aira-dojo（2507.02554）** 得负结论——评估固定后搜索策略几乎不重要;**AIRA_2** 把退化诊断为**评估不一致/噪声**。

一个诱人的省钱思路:与其花钱评估每个候选,不如用一个**便宜的 critic**——不执行候选就预测它好不好——来排序、剪预算、或引导生成。最便宜的 critic = 从一个**冻结**（绝不微调,model-agnostic 是卖点）的 code-LLM 隐层里线性读出。**本轮就把这个 critic 想法测到底。**

## 二、动机

核心问题拆成两半,构成全文骨架——**「可解码」与「用得上」是两回事**:
1. **信号在不在?**（decodable）——冻结 code-LLM 的表征里,到底有没有关于"这个解最终能拿多少分"的信息,且是**独立于候选自己那个廉价自报分**的真信息、不是读代码长度的假象?
2. **用不用得上?**（usable）——就算信号在,它能不能**转化成搜索收益**:拿它选候选、拿它当部署 veto、拿它 steer 生成?

**方法纪律不变:贵的在线实验之前,先用便宜的离线探针证伪。**

## 三、方法

- **实验台**：facebookresearch/aira-dojo（负结论同框架）+ DeepSeek 底座（OpenAI 兼容 API,**绝不微调**）+ 非容器解释器 + **外部 pristine 打分**（grader 在 agent 工作区外）。**全程无 LLM-as-judge**,agent 只看分数、看不到标签。
- **公平契约**：每个对照只有被研究的旋钮变;算子集/底座/每任务预算/任务集/划分固定并记录。
- **数据**：289 张 graded「卡」（真实 MCTS 搜索节点:task/code/廉价观测/lineage + 隐藏真分,view/hidden 防泄漏）,3 个 tabular 任务（spaceship 221 / nomad 37 / tps-may 31）。
- **探针 = 冻结 code-LLM 特征 + ridge**（唯一被"训练"的只有 ridge)。关键手段:**mask 掉自报分看谁还活着** + **把代码长度残差化掉看信号还在不在**（命门对照）。
- **本轮新增两把尺**:① **跨家族**——把同一套协议搬到 4 个 code-LLM（Qwen-Coder 7B/14B、DeepSeek-Coder 6.7B、CodeLlama 7B）上;② **因果 steering**——在冻结模型残差流上沿"质量方向"加向量（CAA,±3σ),看模型自己的输出分是否被推动。
- **可用性三协议**（都离线）:best-of-K（rank→regret）、wrong-pair rescue、真实树 vs 随机池 veto（+bootstrap)。

## 四、主要结论

**一句话:冻结 code-LLM 的表征「知道」解的好坏——可解码、独立于自报分和代码长度、低维、且跨 4 个模型家族都成立;但它「用不上」——选不动、veto 不转化、steer 也推不动;唯一能做的是"检测自报分瞎掉的失效"。穷算力下的杠杆还是清洁评估,不是更聪明的 critic。**

**① 信号在(强正面地基,H1)**
- grade 从冻结**中层**表征线性可解码,**换到从没见过的任务(LOTO)仍成立**:自报分设障后 probe 不降反升到 Spearman **0.24**;把代码长度残差化掉后**升到 0.30**——而代码长度单独跨任务 = **−0.07(零预测)**。→ 信号是真的表征质量,**既独立于自报分、也不是读代码长度**。
- **低维**:单个主成分就解码 0.21 = 满维 0.31 的 ~70%,≤16 维追平(呼应 confidence-manifold 3–8 维)。
- **★跨家族复现(本轮新做,决定性)**:同协议在 4 个 code-LLM 上,设障+长度残差化的 LOTO = **0.30 / 0.23 / 0.20 / 0.20**,全在 −0.07 地板之上。→ **不是 Qwen 独有,是冻结 code-LLM 的普遍性质**,焊死 model-agnostic。两点诚实:强度依模型(Qwen-Coder-7B 最好)、**规模不帮忙(14B<7B)**——关键是"是不是 code-LLM",不是大小。

**② 用不上(三连负,§5)**——同一个信号,三种机制都转化不成收益:
- **选不动(rank≠regret)**:固定预算 best-of-K 里,**免费的自报分 proxy 最优**(regret 0),probe ≈ random、跨任务更差。
- **veto 不转化**:随机池上像大赢(Δregret 到 +0.18),但**真实搜索树上收益消失**(hard veto −0.001;soft blend +0.007,bootstrap 95% CI [−0.003,+0.018] **不显著**)。随机池的赢是"候选独立"假象。
- **★steer 推不动(本轮新做,补全三连)**:沿质量方向 steer,对模型输出分的效应**统计上可测但实质为零**(quality−random 斜率 +1e-4 ≈ 分尺度 0.01%);**随机方向自己也"显著"**(扰动通用效应),而**唯一真能 steer 的是代码长度**(效应 ~4.5×)——**只有表面特征能 steer**,正合先例(2603.23629)。

**③ 唯一能用:失效检测(有限正,§6)**
- probe 的价值在**自报分错的地方**:自报分排错的候选对上 probe 仍 **0.59 对**(spaceship,8382 对;构造上自报分 0%)。
- 做成**可部署的 per-candidate 检测器**:在"自报分满意"的候选里抓"偷偷差"的,probe **AUROC 0.63 [95% CI 0.53–0.73]**,而**自报分自己是反信息(0.42<0.5)**——它信任的子集里越自信越可能偷偷差,"自报分管不了自己"的最锐表述。且**不是读代码长度**(残差化后不变)。诚实限制:**温和、量级与代码长度启发式打平、且主要靠 spaceship**。→ 定位成 H1 信号的一个下游**用途**,非独立强检测器。

**④ 另两个非杠杆(§7)**
- **reasoning-first critic 不行**:整体不如 scalar 头(均值 −0.15 vs −0.07)。试了您上次提的"给 teacher 真值让它写连贯 rationale 再蒸馏"——**231 卡下学生欠拟合**(默认塌回基座),加狠训才动、grounding 边际帮 +0.047,但 reasoning 仍**比 scalar 低 ~0.48**。→ 穷算力下**冻结读出赢过训练的生成式 critic**,正因它不需要那种贵且欠拟合的训练。
- **多保真无 headroom**:能搜得起的任务(spaceship)单保真已近 oracle(headroom→0);有 headroom 的离散任务恰恰穷算力搜不起。

**⑤ 收敛与方法论**
- 全部收敛到一句:**表征"知道"质量,但穷算力下"用不上"**——选/veto/steer 三条独立机制都失败,只有检测这一用途成立。这**锐化了 aira-dojo 的负结论**(不止 policy,整个"用廉价 critic 干预搜索"都不划算),并把机制钉在评估噪声上(AIRA_2)。
- **离线证伪先于在线投入**:多个便宜探针在动工前就杀掉了昂贵的错误建设(veto 随机池假象、A3 用贪心读数的假 RED、多保真 headroom)——每个"看着能用"的结果都被几分钟的离线对照溶解。这套**便宜、对抗性、离线的检验**本身也是贡献。
