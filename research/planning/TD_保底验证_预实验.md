# 预实验 0.5：TD 在你的真实搜索树里到底 backup 不 backup 得动？

> 放在 `EXPERIMENT_PROMPTS.md` 的 Prompt 0 之后、Prompt 1 之前。
> 目的：**在花数周实现 TD/Thompson/BAI 之前**，用半天 + 几个 GPU·时，验证 RQ1 的"保底"
> 到底成不成立。成立 → 放心做；不成立 → 趁早换保底，别把周级工程押在一个会落进噪声带的结果上。

## 为什么必须先做这个

`EXPERIMENT_PROMPTS.md` 里 RQ1（T0）被当成"几乎稳成立的保底"。但有个没被验证的前提：
**TD/自举要有东西可 backup，得有足够的树深和分支。** MLE 搜索树常常很浅（draft→少量 improve），
奖励即时（每个节点直接评分），没有长程延迟信用。如果你的真实树普遍只有 2–3 层，
TD 和 MC 的 backup 会几乎一样，"TD 降方差"要么微小、要么落在 seed 噪声带里——保底就没了。

Prompt 1 里的单测"TD 在玩具树上收敛到解析值"只证明**实现对**，
**不证明在你的真实树形上 TD 有用**。这个预实验正好补这个缺口。

## 关键：不需要先实现 RL 控制器

整件事建立在**已有 baseline 的搜索日志**上 + **离线复算**，零新 RL 代码、零额外训练。

## 步骤

### 1. 采集真实树（唯一花 GPU 的一步，~几个 GPU·时）
跑现有 aira-dojo / MLEvolve 的 baseline（MCTS/MCGS，未改），在 **2–3 个最轻的 tabular 任务**、
**3–5 seed**、**小预算（每个 2h）**，全程记录：
- 树结构（每个节点的 parent、children）
- 每个节点的评估分（以及若有的多次评估）
- visit count、时间戳

### 2. 量树形（先看这个，可能直接给出 kill 信号）
统计：**深度分布、分支因子、节点数、有 >1 child 的内部节点占比、价值是否几乎全来自叶子**。
> 若最大深度普遍 ≈ 2–3、内部分支极少 → TD 没什么可 backup，**直接亮红灯**，不用做第 3 步。

### 3. 离线 backup 复算（核心对比，零 GPU/API）
在采集到的同一批树上，纯离线算三种节点价值估计：
- **MC**：Q(n)=后代叶子分的均值
- **TD(λ)**：用子节点价值自举
- **TD+advantage**：TD 再减去同层兄弟均值 baseline
"真值"用该节点的最优后代分（或对部分节点做额外几次高保真重评近似）。

### 4. 注噪 + 测两件事（在真实树形上，不是玩具树）
对叶子分叠加可控高斯噪声（几档 σ），每种 backup 测：
- **价值估计 vs 真值的方差 / 偏差**
- **选错率**：在每个内部节点，按该 backup 选 argmax 子节点，选中真·最优子节点的比例
- 随 σ 增大的退化曲线（带跨 seed error bar）

## Go / No-Go 判据

- 🟢 **绿灯**：在**真实树形**上，TD/advantage 相比 MC 把选错率/价值方差**有意义地**压低，
  且跨 σ 稳定、效应在 seed 噪声带之上 → RQ1 保底成立，进 Prompt 1 实现。
- 🔴 **红灯**：树太浅，或 TD≈MC（差距落在 seed 噪声带内）→ RQ1 不是安全保底。三选一：
  1. 改算子/搜索让树更深（credit assignment 才有意义）——但这改了公平变量，要重设计；
  2. **丢掉 TD，把"保底"换成多保真/方差感知选择**（提案 v2 那条线，不依赖树深，几乎必降方差）；
  3. 重估整个 RL 控制器命题是否值得做。

## 成本

第 1 步 ~6–15 GPU·时（3 任务 × 4 seed × 2h，可并行）；第 2–4 步纯 CPU 离线，几乎免费。
**半天到一天能出结论**，却能挡住数周的错误投入。

## 产物
- 树形统计表 + 三种 backup 的方差/选错率对比图（带 error bar）。
- 一句话结论：TD 在我们真实树形上是否值得做（绿灯/红灯），及理由。
