## 3. SLURM 速查

### 查看
```bash
sinfo                      # 各分区/节点状态
sidle                      # 各节点空闲量（只有部分 linux server 有此命令）
squeue                     # 排队情况；找自己的用户名看是 R(运行) 还是 PD(排队)
squeue -u $USER            # 只看自己的作业
```

### 节点建议（学长经验）
| 节点 | 卡 | 分区 | 用途 |
|---|---|---|---|
| projgpu33 | RTX 3090 | gpu_2h | 快速 debug |
| projgpu8 / 12 / 14 | RTX 3090(24G) | gpu_24h | 跑长实验，目前很空闲，可放心用 |
| projgpu39 | RTX Pro 6000 | gpu_24h | 需要更大显存时用 |
| projgpu13 | — | — | James 的，reserved，暂不可用 |

> 这些节点名义上是别人的，但目前很空闲可以用；若哪天满了/不可用，让学长把你加到 projgpu13。

### 申请交互式 GPU（debug）
```bash
# 快速 debug（任意 3090）
srun -c 6 -p gpu_2h --gres=gpu:1 -C rtx3090 --pty /bin/bash

# 指定节点跑长任务
srun -c 6 -p gpu_24h -w projgpu14 --gres=gpu:1 --pty /bin/bash
```
> 若报 account/qos 相关错误，补上 `--account gpu --qos gpu`。
> `-c` 改 CPU 核数；`--gres=gpu:N` 改 GPU 数；`-C` 指定卡型；`-w` 指定节点。
> 注意：学校的 SLURM 是魔改过的，行为可能和官方文档略有出入。

### 提交后台作业（batch）
```bash
#!/bin/bash
#SBATCH --job-name=myjob
#SBATCH --mail-user=yzyang4@cse.cuhk.edu.hk
#SBATCH --mail-type=ALL

#SBATCH --error=logs/%j.err
#SBATCH --gres=gpu:1

#SBATCH -p gpu_24h

source ~/env_setup.sh

```
提交 `sbatch xxx.sbatch`；看日志 `tail -f logs/<作业号>.out`；取消 `scancel <作业号>`。

## 4. 部署 MLEvolve（仅作 SOTA 对照 / sandbox，非实验台）

> 实验台用 aira-dojo（见 `planning/切回aira-dojo_Prompt.md`）。本节保留作 SOTA 现状对照与快速试跑。

MLEvolve = 自主 ML 工程 Agent，跑 mle-bench（Kaggle 式竞赛），靠 LLM 驱动。
**自身不需要 Docker**（直接 `python run.py` + 本地 grading server），适配 CSE。

### 4.1 克隆 + 装依赖
```bash
cd /research/d7/spc/yzyang4
git clone https://github.com/InternScience/MLEvolve.git
cd MLEvolve
source /research/d7/spc/yzyang4/venvs/exp/bin/activate
uv pip install --no-deps -r requirements_base.txt
uv pip install --no-deps -r requirements_ml.txt
uv pip install --no-deps -r requirements_domain.txt
python -c "import torch; print('CUDA:', torch.cuda.is_available())"   # 确认 torch 没被装坏
```

### 4.2 装 mle-bench + 配 Kaggle + 准备数据
```bash
cd /research/d7/spc/yzyang4
git clone https://github.com/openai/mle-bench.git
cd mle-bench
git lfs fetch --all && git lfs pull       # 需要 git-lfs；若没有：先 conda/apt 装或问管理员
uv pip install -e .

# Kaggle 凭证：把下载的 kaggle.json 放到 ~/.kaggle/
mkdir -p ~/.kaggle && mv ~/kaggle.json ~/.kaggle/ && chmod 600 ~/.kaggle/kaggle.json

# ★ 重要：先去 Kaggle 网站打开该竞赛页面，点 "Join / I Understand and Accept" 接受规则，
#   否则 API 下载会 403。竞赛页：kaggle.com/c/denoising-dirty-documents

# 准备首个小任务（0.06GB，GPU 相关，MLEvolve 官方示例）
mlebench prepare -c denoising-dirty-documents --data-dir /research/d7/spc/yzyang4/mle-bench-data
# 注：--data-dir 名称以 `mlebench prepare --help` 为准；目的是把数据放到 /research 而非家目录
```
准备完，数据应在 `…/mle-bench-data/denoising-dirty-documents/prepared/public/`（含 description.md）。
这个 `…/mle-bench-data` 就是下面 config 的 `dataset_dir`。

### 4.3 配置 config.yaml（DeepSeek + 路径）
编辑 `MLEvolve/config/config.yaml`，改这几处：
```yaml
dataset_dir: "/research/d7/spc/yzyang4/mle-bench-data"

torch_hub_dir: "/research/d7/spc/yzyang4/cache/torch"
pretrain_model_dir: "/research/d7/spc/yzyang4/cache/pretrain_models"

agent:
  code:
    model: deepseek-chat
    base_url: "https://api.deepseek.com"
    api_key: "sk-你的DeepSeekKey"
  feedback:
    model: deepseek-chat
    base_url: "https://api.deepseek.com"
    api_key: "sk-你的DeepSeekKey"

  # 记忆用的嵌入模型（自动从 HF 下载，走代理）；显存紧张可改 cpu
  memory_embedding_device: cuda
  memory_embedding_model_path: "BAAI/bge-base-en-v1.5"
```
> 首跑想更轻量，可把 `coldstart.use_coldstart` 设为 `False`（跳过从 HF 下载一堆预训练模型）。
> DeepSeek 用 `deepseek-chat`（V3，支持 function calling）；`deepseek-reasoner`(R1) 不建议做 agent。

先测 DeepSeek 通不通：
```bash
curl -sS https://api.deepseek.com/v1/models -H "Authorization: Bearer sk-你的Key" --max-time 20
```
返回一段 JSON 模型列表 = 通。

### 4.4 改 run_single_task.sh 填代理
打开 `MLEvolve/run_single_task.sh`，取消注释并填：
```bash
export http_proxy=http://proxy.cse.cuhk.edu.hk:8000/
export https_proxy=http://proxy.cse.cuhk.edu.hk:8000/
```

### 4.5 运行（用 sbatch，12 小时任务上 gpu_24h）
在 `MLEvolve/` 下建 `run_mlevolve.sbatch`：
```bash
#!/bin/bash
#SBATCH --job-name=mlevolve_ddd
#SBATCH --mail-user=yzyang4@cse.cuhk.edu.hk
#SBATCH --mail-type=ALL
#SBATCH --output=logs/%j.out
#SBATCH --error=logs/%j.err
#SBATCH --gres=gpu:1
#SBATCH -w projgpu14
#SBATCH -p gpu_24h
#SBATCH -c 6

source ~/env_setup.sh
source /research/d7/spc/yzyang4/venvs/exp/bin/activate
cd /research/d7/spc/yzyang4/MLEvolve
bash run_single_task.sh denoising-dirty-documents /research/d7/spc/yzyang4/mle-bench-data 1
```
提交：
```bash
mkdir -p logs
sbatch run_mlevolve.sbatch
squeue -u $USER
tail -f logs/<作业号>.out
```
结果写在 `MLEvolve/runs/<时间戳>_denoising-dirty-documents/`（搜索树日志、最优代码、候选提交）。

> 先用交互式跑通一遍更易 debug：
> `srun -c 6 -p gpu_24h -w projgpu14 --gres=gpu:1 --pty /bin/bash`，进去后手动跑 4.5 里的 `bash run_single_task.sh ...`，
> 把 `agent.steps`/`time_limit` 先调小（在 config 里）快速验证全流程，再放大正式跑。

## 6. 常见坑（已踩过）

| 现象 | 原因 / 解法 |
|---|---|
| VSCode 连 proj103 报 glibc | 老机器，改用 linux5（Ubuntu 24.04）|
| 开 VPN 后连网关 timeout | VPN 与网关二选一；linux5 用 VPN 直连 |
| 装 server / pip "Network unreachable" | 必须走代理；env_setup.sh 已设，`~/.wgetrc`/`~/.curlrc` 也配了 |
| `Disk quota exceeded` | 缓存在家目录；已把 XDG_CACHE_HOME/UV_CACHE_DIR 指到 /research |
| `sinfo` 找不到 slurm.conf | 正常，靠 `SLURM_CONF` 指向 gpu-slurm.conf |
| `ulimit -u` Operation not permitted | 无权提升，已静默，无害 |
| Kaggle 下载 403 | 没在网站接受竞赛规则；去竞赛页点 accept |
| DeepSeek/HF 连不上 | 确认 `echo $http_proxy` 有值；代理 `proxy.cse.cuhk.edu.hk:8000` |
