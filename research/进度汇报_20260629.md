# 穷算力下的噪声鲁棒 MLE 搜索 — 进度汇报

> 日期：2026-06-29　|　平台：CUHK CSE 单卡 RTX 3090　|　底座：DeepSeek（不微调权重）
> 一句话：**评估保真度是搜索质量的主杠杆;而在固定廉价预算下改"选择统计量"(多评平均 / 方差惩罚)并不能救 —— 救法在"多保真",不在"怎么选"。**

---

## 0. TL;DR（先看这页）

1. **基建打通**：在 `facebookresearch/aira-dojo`(公平对照框架)上接 DeepSeek、单卡非容器跑通,并自建**外部一致评估(HCE)+ 三臂对照** harness —— 只动"评估/选择协议"一个旋钮,搜索算子与底座完全固定(守公平契约)。
2. **T0 预实验裁决**：
   - **RL 搜索控制器线 → 搁置**:真实树上"父→子价值"无稳健可池化结构(spaceship 稳健 R²≈0.3、被单点虚高到 0.92;nomad 连边都凑不出)。
   - **主线(评估一致性)→ 进 T1**:自报验证分 vs 外部真分 R²=0.14(评估确实噪声),且**噪声任务相关**(nomad R²=0.72)。
3. **T1 主实验首裁(spaceship + nomad,greedy,5 seed)** —— 两条结论:
   - ✅ **清洁评估是大杠杆**:全量评估臂 full 选中解真分 **0.803**,明显高于一切廉价 10% proxy 臂(**~0.785**)。
   - ❌ **改"选择统计量"救不了**:朴素单次、多评平均(λ=0)、方差惩罚(λ=1)三臂真分**几乎一样(0.780–0.787,都在跨 seed 噪声带内)** —— 选择规则不是杠杆(强烈呼应 AIRA「搜索策略不重要」)。
4. **方向修正**：主线卖点从"方差感知选择"**改为"多保真 / 评估预算分配(BAI)"** —— 把廉价评估的**有效保真度**推近 full,而不是改怎么选。
5. **诚实标注**:T1 为首批 5 seed(nomad 偏少);"full ≫ proxy、三廉价臂无差异"方向清楚,但需补 seed / 加任务坐实。
6. **当前判断(今日待定)**:原"会赢的选择方法"卖点已弱;现在是"**诚实地缩小了假设空间**"的状态——证伪了选择规则、定位到评估保真度是杠杆。正在三条路(多保真赌 / 负结果+诊断 / 重构噪声检测)中选主攻方向,见 §6。

## 1. 研究问题与定位

- **背景**：自主 ML 工程 Agent(MLE-bench 式竞赛)靠 LLM 驱动搜索。`AIRA-dojo` 给出**负结论**——脏评估下"搜索策略不重要";`AIRA_2` 把退化诊断为**评估不一致/噪声**。
- **核心问题**：**单卡 + 廉价带噪评分**下,怎样保住「评估一致 → 长程稳定」?
- **定位**：所有改动只在**搜索控制器的评估与选择协议**,**绝不微调底座 LLM**(model-agnostic 是卖点),区别于 TreeRL/TEMPO 等微调路线。

---

## 2. 实验平台与完整性设计(基建,已完成)

| 项 | 选择 | 说明 |
|---|---|---|
| 实验台 | **aira-dojo**(fork) | 干净拆分 search×operator、自带基线、是负结论的同框架 |
| 底座 | **DeepSeek**(OpenAI 兼容) | draft/improve/debug→v4-pro,analyze→v4-flash;经 LiteLLM |
| 硬件 | 单卡 RTX 3090,**非容器** python 解释器 | CSE 封了 user namespace,用不了 Apptainer |
| 任务 | spaceship-titanic(分类/准确率)、nomad2018(回归/RMSLE) | 轻量 tabular |

**完整性 / HCE(防作弊)**：
- 评分一律由**外部 pristine 代码**(mle-bench grader)计算,agent 只看分数、拿不到标签。
- 竞赛 private 答案划成 **D_search**(搜索期外部评分信号,agent 不可见)/ **D_val**(只用于最终选择,对搜索也隐藏)/ **D_test**(全程不碰)。
- 关键工程点:三臂逻辑全在评估层(任务返回的 `VALIDATION_FITNESS`),**搜索算法一行未改** → "只有被研究的评估/选择旋钮在变",公平契约天然成立。

## 3. T0 预实验：两条线的生死裁决(已完成)

> 目的:在投入数周工程前,用便宜的 baseline 搜索日志判定两条线值不值得做。

| 线 | 信号 | spaceship | nomad | 裁决 |
|---|---|---|---|---|
| 扩展线(RL/TD) | 父→子外部真值相关 R² | 0.30 稳健(0.92 被单点虚高)n=20 | 凑不出边(树太碎) | **搁置** |
| **主线(评估一致性)** | 自报验证分 ↔ 外部真分 R² | **0.14**(n=71) | 0.72(n=6) | **进 T1** |

**结论**：① RL 线"保底"(TD 在真实树上降方差)不成立 → 搁置,不浪费算力。② 评估噪声真实且**任务相关**(spaceship 的准确率自报易 overfit/灌水;nomad 的 RMSLE+5 折更诚实,但 n 小 + 难任务存在选择效应)。

## 4. T1 主实验：三臂(+消融)对照首裁

**设计**：固定搜索策略=greedy、20 步、同算子同底座同预算;**只变评估/选择协议**:

| 臂 | 搜索期 fitness | 角色 |
|---|---|---|
| **full 完整** | 全量 D_search 外部真分 | 干净参照(天花板) |
| **naive 朴素** | 1 次廉价 proxy(D_search 随机 10% 子样) | 穷算力 naive 基线 |
| **consistency(λ=1)** | k=3 次廉价 proxy → 均值 − λ·std | 原卖点:方差感知选择 |
| **mean(λ=0)** | k=3 次廉价 proxy → 纯均值 | 消融:只平均、不惩罚方差 |

**指标**:选中解在 **D_val 的真分**(主)、**regret**(选中解 vs 同树内真值最优解之差,↓好)、**gap**(选中解 proxy 分 − 真分,看 proxy 多乐观)。

### spaceship(准确率↑,噪声会咬的任务,5 seed)

| 臂 | 有效 run | 选中解 D_val | regret↓ | gap |
|---|---|---|---|---|
| **full 完整** | 5 | **0.803** | **0.009** | +0.018 |
| consistency(λ=1) | 4 | 0.787 | 0.025 | −0.007 |
| naive 朴素 | 4 | 0.784 | 0.030 | +0.077 |
| mean(λ=0) | 5 | 0.780 | 0.032 | +0.050 |

> **三个廉价 proxy 臂真分 0.780–0.787、均值都 ~0.784–0.786,彼此无显著差异;full 0.803 明显更高、regret 仅 1/3。→ 杠杆是评估保真度(full vs 10% proxy),不是选择统计量。**

### nomad(RMSLE↓,清洁评估对照,5 seed)

| 臂 | 有效 run | 选中解 D_val | regret↓ |
|---|---|---|---|
| full | 5 | 0.0578 | 0.000 |
| naive | 3 | 0.0571 | 0.000 |
| consistency(λ=1) | 2 | 0.0655 | 0.009 |

> nomad buggy 偏重 → 工作节点少 → 树太小 → 各臂选择都 trivial(regret≈0),**检验力弱**,主要作"清洁任务上不变坏 + 评估噪声任务相关"的对照。

---

## 5. 关键发现

1. **清洁评估 = 主杠杆(强结论)。** full 臂全面最好(dval 高 ~0.02、regret 仅 1/3)。→ 这是对 AIRA「搜索策略不重要」负结论的**关键例外:评估保真度是被忽略的杠杆**。
2. **改"选择统计量"不改最终真分(干净的负结论)。** naive(单次)= mean(λ=0,平均)= consistency(λ=1,平均−std)≈ 0.785,全在噪声带内。
   - **机制层面这些旋钮确实在起作用**:gap 从 naive 的 +0.077(单次 proxy 乐观误选 fluke)→ mean +0.050 → penalty −0.007,说明平均/惩罚确实改变了"选什么";
   - **但不转化为更好的解** —— 被乐观误选的节点真实分也没差多少 → **选择规则不是杠杆**(局部印证 AIRA)。
3. **评估噪声任务相关。** nomad(评估本就诚实)上 naive 也选得准、无 fluke 可救 → 方法只在"评估会咬"的任务上有意义。

**→ 主线卖点修正为**：「**穷算力下,把廉价带噪评估通过"多保真 + 固定预算的评估分配(BAI)"做出更高有效保真度**,即可在不增底座成本下逼近全量评估的搜索质量」 —— 杠杆在保真度,不在选择规则。

## 6. 讨论：卖点现状与方案选择(今日待定)

### 6.1 现状的诚实判断
- **原头号卖点"方差感知 / 一致性选择"已被自己的实验证伪**(三廉价臂真分无差异)——"我们做了个会赢的选择方法"这个故事目前立不住。
- **牢但弱**:"评估保真度是杠杆(full≫proxy)"成立,但接近常识 + AIRA_2 已诊断评估是病根 → 作为*新*贡献偏弱。
- 一句话:**假设空间被诚实地缩小了**——不是失败,但要重新选主攻方向。

### 6.2 三条候选路线(按"能否产出强结论"评)

| 路线 | 做什么 | 期望产出 | 风险 |
|---|---|---|---|
| **A. 多保真 / BAI**(唯一的"正向"赌) | 多档保真(10%/30%/全量)+ 固定预算 best-arm 分配(sequential halving / UCB-E),把廉价评估的*有效保真度*推近 full | 赢 → "穷算力下怎么花评估预算"的可用方法 | 可能也只边际增益;偏 incremental(套用已有 multi-fidelity) |
| **B. 负结果 + 诊断**(稳的兜底) | 把"搜索/选择协议不是杠杆、评估保真度才是"做严(+更多任务/seed/MCTS) | 对 AIRA 负结论的更锐利、可控延伸;一篇诚实实证 | 负结果难卖;需更多算力做宽 |
| **C. 重构到"噪声何时咬人"** | 研究"如何预测/检测某任务的廉价评估会坑搜索"(T0 已显示任务相关) | 可能比"改选择"更新的角度 | 换题,要重新设计 |

### 6.3 还没测、可能改变结论的维度
- **只测了 greedy**:MCTS 树更深、选择*可能*更重要(但若因此推翻"保底不依赖树深",本身也是结论)。
- **噪声模型是"廉价 grading 子样"**,非真穷算力的"廉价*训练*(1 epoch/10% 数据)";后者噪声结构不同,选择*可能*在那有用——但要改实验且碰 agent(公平敏感)。

### 6.4 推荐
- **限时(1–2 周)赌路线 A**:赢 → 正向贡献;输 → 自动落到路线 B(负结果+诊断),把 A 的数据并进去。两种结局都比现在能交代。
- **无论 A/B 先补宽**:补到 10 seed + 上 s3e18(+ 可选 MCTS 一档),否则任何结论(正/负)都不够硬。
- **具体动作**:① 补 seed/任务(便宜,集群现空闲);② 实现多保真档 + BAI 分配器;③ 全部出 CSV(一行一 run、含臂/seed/λ/commit),报 median + 跨 seed 方差。
- **汇报口径**:讲"我们诚实地缩小了假设空间——证伪了选择规则、定位到评估保真度是杠杆、下一步赌多保真",体现 rigor,而非硬撑已破的卖点。

## 附录：复现与工程要点

- **公平契约**:对照中只有评估/选择协议变;算子集、底座、每任务预算(20 步)、任务集、HCE 划分固定且逐项记录。
- **复现默认**:pin commit + 全 seed;命令/config/环境随产物存盘;结果 CSV 一行一 run;报 median + 跨 seed 方差。
- **HCE 划分**:private answers 按 0.5/0.25/0.25 → D_search/D_val/D_test,split_seed 固定;proxy = D_search 的随机 10% 分层子样(注入"幸运 split"噪声),k=3 重复。
- **成本实测**:每 run ~$0.5(LLM 主导)、好节点上 20 步约 37–88 分钟;QOS 限每用户同时 ≤4 作业 → 自限流提交器分波跑。
- **已踩并修的坑**:① analyze 算子非 JSON → metric 全判 buggy(改确定性 `FINAL_VALIDATION_SCORE` 解析);② HCE 收尾缺 `score` 键致进程挂墙(已修);③ 某计算节点连不上 API 致任务卡死(已 `--exclude`)。
- **方法学教训**:mean(λ=0)在 n=2 时假象为 0.805,跑满 5 seed 后回落到 0.780 —— 小 n 别下结论(本报告所有数字均为可得的最大 n)。

> 状态:基建 + T0 + T1 首批(含 mean 消融)= 完成;补 seed / s3e18 / BAI = 进行中/规划中。
